# API 与网络工具经验

适用范围：API Mock、访问链路诊断、Cron、连通性收藏和网络输入。

关键词：`API Mock`、`CORS`、`Content-Type`、`access path`、`Cron`

## API Mock：持久配置与运行态分离

持久配置描述用户意图，运行态描述端口、启动结果和当前服务。保存配置不伪装成服务已启动；启动/停止失败显式反馈。Content-Type 选择驱动响应校验与格式化，文本语言复用 `@lazycat/formatters`，二进制或未知类型不强行格式化。

未保存切换、延迟模拟、并发服务和 CORS 都应有行为测试。CORS 处理预检与实际响应头，不能只在前端表单展示开关。

## 访问链路诊断：阶段化且保持只读

输入先归一化，再依次执行本机适配器、DNS、TCP、TLS、HTTP 等阶段；每阶段输出明确状态和终态结论。高级参数可持久化，但运行报告必须脱敏，旧数据迁移保持兼容。诊断默认只读，不为了“修复”自动改 Hosts、证书或系统代理。

长任务使用运行 ID、取消状态与终态事件，前端原位替换当前结果；旧响应和旧事件不得覆盖新一轮诊断。

## Cron 方言显式建模

区分 5 字段、Quartz/Spring 6 字段等方言，输入校验、预览与输出使用同一方言定义。不要通过字段数猜测后静默纠正含义；无法解析时显式报错。

## 轻量收藏使用 settings JSON

连通性测试等小规模、非关系型收藏可复用 `user_settings` JSON；写入前归一化和去重，避免为轻量偏好新增数据库表。
