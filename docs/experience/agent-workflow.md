# Agent 协作经验

适用范围：规范治理、经验沉淀、dirty worktree、计划与验证。

关键词：`AGENTS.md`、`CLAUDE.md`、`process.md`、`dirty worktree`、`verification`

## 根规范是执行入口，不是知识仓库

根规范只保留高频、稳定、会改变执行决策的规则；领域架构和排障细节放入 `docs/experience/`。索引按任务类型组织，避免 agent 每次扫描整份历史。

## 双文件同步用归一化比较

修改 `AGENTS.md` 或 `CLAUDE.md` 时同步另一份。完成后将文件名和互指对象归一化，再用 `Compare-Object` 检查同构，不依赖肉眼。

## dirty worktree 先划定边界

开始前记录 `git status --short` 和相关 diff。现有改动属于用户，任务文件单独暂存；遇到目标文件已有改动时先读 diff，把它纳入迁移或明确避让。

## 验证基于证据

先跑最相关的定向测试，再跑类型、构建和冒烟。不能运行时说明原因，不把静态阅读写成“已验证”。文档迁移使用数量对账、链接检查、规则关键词检查和 diff 边界检查。

## 经验维护

新经验直接写入对应领域文件，初始使用次数为 0；复用后 +1 并记录日期。达到 3 次后只“评估”是否固化，仍需满足高频、稳定、能改变 agent 决策三个条件。

**使用次数**：0
