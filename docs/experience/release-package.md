## 2026-07-26：外部动作在线程启动前关联运行

**场景**：动作中心确认请求复用上线包现有确认链启动打包，并需要在打包结束后收口 dispatch 和上游 Todo。

**问题**：若 worker 启动后才关联 `dispatchId + runId`，快速失败可能先产生终态，留下永久 `running` 或待确认 dispatch；若在多个分支分别回写，部分成功、上传失败和取消容易映射不一致。

**解决**：后端 `start` 严格解析可选 `actionDispatchId`，占用运行槽后、`thread::spawn` 前校验动作、目标和状态并关联 run；关联失败释放运行槽且不启动命令。所有原始终态在统一 `emit_terminal_result` 中、状态事件和通知发出前回写动作中心。

**关键点**：只有 `succeeded` 映射成功并自动完成 Todo；`partially_succeeded`、`package_succeeded_upload_failed` 和 `failed` 都映射失败，`cancelled` 映射取消。普通手动打包没有 external run 关联，保持原通知和重试行为。动作中心只保存项目 ID，不接收 SSH 配置、密码或 Vault 秘密。

**涉及文件**：

- `apps/desktop/src-tauri/src/tools/release_package.rs`
- `apps/desktop/src-tauri/src/tools/release_package_runtime.rs`
- `apps/desktop/src-tauri/src/tools/action_center/dispatches.rs`

## 构建与归档是两阶段提交

构建成功不等于归档成功。先在临时 stage 生成并校验产物，再提交到最终归档目录；整体状态由各目标构建结果和归档提交共同决定。取消或失败不能留下看似可用的半成品。

## 多目标并行但状态独立

前端、后端等目标可并行执行，每个目标维护独立命令、日志 lane、结果与取消状态；overall 状态只聚合，不覆盖目标级错误。项目级日志和实时日志使用稳定运行 ID 关联。

## SSH 上传采用目标级有界并发

每个部署目标使用独立 SSH/SFTP 会话，双目标并发上限为 2；共享 `ssh2::Session` 本身没有吞吐收益。本地源清单校验、全部会话建立、远端冲突检查和目录预建必须在 worker 启动前完成；worker 只写入 temp 并校验。正式目标复核、backup、commit、rollback 和清理保持串行。所有 socket 集中注册，用户取消时关闭全部连接；内部目标失败使用独立 stop 信号，不能伪报为用户取消。进度按 100ms 节流，成功终态的上传总字节必须精确。首轮不做文件级并发、分块上传或可配置并发数，并发收益只通过受控 SSH fixture 评估。

## 归档目录是项目配置

归档根目录按项目持久化，最终路径以运行时返回为准。目录快捷入口只在存在成功 `archive_path` 时显示，不能用配置根目录冒充本次产物。

## 已有归档完整替换

检测到同名归档时先明确展示目标和影响，用户确认后执行完整替换。替换应在可恢复 stage 中完成，不能把新旧文件混合成不确定状态。

## 终态反馈在交付提交之后

`local_archive` 只有归档 commit 成功后才以 `succeeded/partially_succeeded` 表达可用本地产物并显示目录入口。`server_upload` 只有远端 commit 成功后才表达服务器上传完成；任一目标构建失败时不得开始上传，`partially_succeeded` 必须明确说明构建部分失败、未上传服务器。取消或完全失败不显示成功入口。长任务终态通过统一全局通知窗口呈现，通知内容与面板状态使用同一结果对象。

## 上传前必须完成真实预检

上传模式在构建前建立真实 SSH/SFTP 会话，校验认证、目标父目录、写入和重命名能力，并记录同名目标状态；正式上传前再次核对可信指纹和预检绑定。预检令牌必须与项目、目标和远程路径绑定、短期有效且只能消费一次，不能用端口连通性代替预检。

## 主机指纹先于认证

首次连接先展示 SSH 主机密钥类型和 SHA256 指纹，由用户明确确认后再发送密码或私钥认证。已信任指纹发生变化时必须阻止连接，同时展示旧、新指纹并要求显式更新信任，不能提供忽略或静默替换入口。

## 认证秘密只存在于一次性链路

私钥口令只从确认弹窗直接发送到后端预检；服务器密码只由 Rust 从已解锁的 Vault 读取。两类秘密都只保存在一次性、短期内存令牌中，不进入项目配置、数据库、日志、通知或重试描述。弹窗关闭、取消、启动成功和异常后都要清空私钥口令与预检状态。

## 密码库绑定只保存引用

账户密码认证的上线包项目只保存 Vault 服务器条目 ID。地址和账号在运行时从条目的非敏感元数据读取，密码仅在已解锁 Vault、主机指纹受信任后由 Rust 解密并交给一次性预检令牌。前端不得接收或提交服务器密码；Vault 锁定、条目缺失、类型变化或字段不完整必须显式阻止预检，不回退到手填密码。

## 远端目标使用完整替换事务

每个目标先上传到带运行 ID 的 temp 路径并校验完整性，再将正式目标切到 backup，最后提交 temp；失败或取消时按逆序恢复并清理。符号链接只删除链接本身，不跟随到目标。多个远端目标不具备跨路径原子事务，回滚只能尽力完成，失败时必须返回明确的恢复路径。

## 本地归档与服务器上传是互斥类型

项目以 `local_archive` 或 `server_upload` 作为唯一行为真值，不保留“先归档再上传”的组合模式。服务器上传不依赖归档目录，也不创建本地归档或临时副本；前端选择生成物目录时上传目录内部内容，不把源目录本身套入远端目标目录。

上传失败使用 `package_succeeded_upload_failed` 并保留独立重试令牌。重试复用构建产物源清单，执行前必须校验源文件列表和大小没有变化，再结合新的 SSH 预检结果重建远端部署请求；源产物变化时明确拒绝重试。上传取消或失败不能破坏原线上版本，仍遵循远端完整替换事务。
