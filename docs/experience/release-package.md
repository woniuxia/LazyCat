# 上线包经验

适用范围：上线包命令编排、并行目标、构建/归档事务、目录配置、覆盖和终态反馈。

关键词：`release_package`、`archive`、`runtime`、`parallel`、`notification`

## 构建与归档是两阶段提交

构建成功不等于归档成功。先在临时 stage 生成并校验产物，再提交到最终归档目录；整体状态由各目标构建结果和归档提交共同决定。取消或失败不能留下看似可用的半成品。

## 多目标并行但状态独立

前端、后端等目标可并行执行，每个目标维护独立命令、日志 lane、结果与取消状态；overall 状态只聚合，不覆盖目标级错误。项目级日志和实时日志使用稳定运行 ID 关联。

## 归档目录是项目配置

归档根目录按项目持久化，最终路径以运行时返回为准。目录快捷入口只在存在成功 `archive_path` 时显示，不能用配置根目录冒充本次产物。

## 已有归档完整替换

检测到同名归档时先明确展示目标和影响，用户确认后执行完整替换。替换应在可恢复 stage 中完成，不能把新旧文件混合成不确定状态。

## 终态反馈在归档提交之后

只有归档提交成功的 `succeeded/partially_succeeded` 才追加“已完成打包”并发送 overall 终态；取消或完全失败不显示成功入口。长任务终态通过统一全局通知窗口呈现，通知内容与面板状态使用同一结果对象。

**验证**：优先运行 `cargo test ... release_package -- --nocapture`、面板/运行态定向测试、`pnpm typecheck` 与 `build:web`。

**使用次数**：0
