# 请求转发经验

适用范围：HTTP/TCP/UDP 长服务、预检、运行态、日志观测、恢复动作和三栏工作台。

关键词：`request_forward`、`runtime`、`preflight`、`observability`、`logs`

## 运行态与持久化意图分离

`autoStart` 是持久化意图，`running/failed/stopped` 是运行事实。进程级 manager 持有 Tokio runtime、句柄和逐规则锁；启动/停止围绕同一真值串行化。退出时关闭服务但不改写用户自启动意图。

## 预检显式暴露风险

启动前完成输入归一化、地址解析、自转发检测和协议能力判断。wildcard 只覆盖同地址族本机地址，不能用同端口粗暴拒绝所有远端目标；明确不支持的协议应早于 DNS 失败暴露。

## 观测不能拖慢转发

preview 只复制有界字节并继续透传；日志容量和保留期有上限。日志落库失败单独呈现，不能把正常转发伪装成失败。HTTP 头/正文采集是当前请求转发能力，不等同于已删除的 PCAP 抓包工具。

## 异步写回绑定选择意图

自动轮询、筛选防抖、详情切换和写操作并存时，响应校验请求 token、规则 ID 与参数快照。轮询不覆盖 dirty 表单；写操作期间锁定目标上下文，晚响应不得切换当前选择。

## 日志工作台

当前采用规则/编辑、日志列表、详情三栏工作台；支持实时筛选、暂停、导出、连续刷新和时间范围。布局宽度属于用户偏好，数据刷新不重置。结构化错误提供可执行恢复动作，不吞异常或只显示“失败”。

## 停止与终态

runner stop 消费句柄，即使清理报错也不保留幽灵 handle；manager 将错误显式记为 failed。HTTP body 流失败在当前 trace 上幂等结束，避免同时产生匿名失败和成功事件。UDP finalize 等待在途 I/O 记账完成。
