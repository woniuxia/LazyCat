# 接口调试请求栏单行布局设计

## 背景

`ApiWorkbenchPanel.vue` 在 `max-width: 1180px` 断点下同时把 `.api-workbench-meta-row` 和 `.api-workbench-request-bar` 改为单列。请求栏实际仍有足够横向空间，但方法、URL、请求配置、保存和发送被强制拆行，破坏了“填写地址后立即发送”的连续操作路径。

## 目标

- 中等宽度窗口下，请求栏保持稳定单行。
- 强化请求主路径：方法选择、URL 输入、发送。
- 将请求级管理动作放到语义更匹配的元信息行。
- 保持现有行为、事件、快捷键、弹窗和数据模型不变。

## 方案

### 元信息行

元信息行从左到右包含：

1. 接口名称输入框，占据剩余空间并允许收缩。
2. `.api-workbench-primary-actions` 操作组，内部依次包含环境选择器、请求配置按钮和保存按钮。

桌面宽度下，元信息行维持 `minmax(180px, 1fr) auto` 两列，操作组右对齐。`1180px` 以下元信息行切为单列，操作组在第二行左对齐；环境选择器保持现有宽度，请求配置按钮继续触发现有 Popover，保存按钮继续调用现有 `saveRequest`。

配置和保存均属于当前请求的管理动作，与名称和环境放在同一区域后，层级和语义更一致。

### 请求栏

请求栏从左到右只包含：

1. HTTP Method 选择器，固定 `104px`。
2. URL 输入框，占据剩余空间，保留 `min-width: 0`。
3. 发送按钮，保持现有最小宽度和发送行为。

桌面和中等宽度使用 `104px minmax(0, 1fr) auto` 三列结构。`ApiWorkbenchVariablePopover` 虽然在模板中紧随 URL 输入框，但其根节点使用 `Teleport to="body"`，不会生成请求栏内的 Grid Item，因此不占布局列；该结构保持不变。

### 响应式行为

- `1180px` 以下：编辑区和响应区继续沿用现有上下布局；只有元信息行切为单列，请求栏保持三列单行。
- `820px` 以下：沿用面板整体单列逻辑，即侧栏、编辑区、响应区纵向排列；该规则不改变编辑区内部请求栏的三列单行结构。
- 本次以 `375px` 为最小验证窗口宽度。方法列与发送按钮保持固定宽度，URL 输入框承担剩余空间并允许文本裁切；不新增水平滚动或额外换行规则。

## 改动边界

- 只修改 `apps/desktop/src/components/ApiWorkbenchPanel.vue` 的模板顺序和局部样式。
- 不修改请求发送、保存、配置、变量补全、多标签或持久化逻辑。
- 不修改全局设计系统、Element Plus 主题变量或其他面板。

## 可访问性与交互

- 配置和保存按钮保留现有 `title`、`aria-label`、图标和点击区域。
- 发送按钮仍是请求栏唯一主按钮，视觉优先级不变。
- DOM 移动会把键盘 Tab 顺序调整为“接口名称 → 环境 → 请求配置 → 保存 → Method → URL → 发送”，该顺序与新的视觉层级一致，属于预期变化。
- `Ctrl+Enter` 发送和 `Ctrl+S` 保存保持原行为。

## 验证

1. 执行 `pnpm typecheck`。
2. 执行 `pnpm --filter @lazycat/desktop build:web`。
3. 静态检查请求栏旧四列定义和 `1180px` 下的单列覆盖已清理，元信息行仍按预期响应式排列。
4. 检查 `1181px`、`1180px`、`821px`、`820px`、`819px` 和 `375px` 宽度，请求栏均保持单行且无横向滚动。
5. 检查元信息行桌面双列、`1180px` 以下单列布局，以及配置 Popover、保存按钮、发送按钮、变量补全浮层和 Tab 顺序。
6. 冒烟验证 `Ctrl+Enter` 发送与 `Ctrl+S` 保存仍可用。
