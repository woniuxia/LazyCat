# 项目管理思源页面关联弹窗默认列表与本地过滤优化设计

日期：2026-04-02

> 目标：优化项目管理中“项目任务关联页面”弹窗的默认行为。弹窗打开后应直接展示当前项目有效存储位置下的全部文档；项目未配置专属位置时自动回退全局默认位置；输入内容默认仅做本地即时过滤；仅当用户手动点击“扩展到全库”时，才以当前输入发起一次远端搜索。同时保留“扩展到全库”作为手动触发的次级入口，不破坏本地优先体验。

## 1. 背景与目标

### 1.1 当前现状

- 页面关联弹窗位于 `apps/desktop/src/components/PmPanel.vue`。
- 当前交互以“搜索”为中心：
  - 打开弹窗后默认结果为空。
  - 会尝试把工作项标题预填到搜索框。
  - 关键词达到 2 个字符后才会自动发起远端搜索。
  - 顶部同时存在 `搜索` 与 `扩展到全库` 两个按钮。
- 目录树数据已可通过 `tool:pm:siyuan-directory` 读取，并缓存在前端 `siyuanDirectory` 状态中。
- 现有 `apps/desktop/src/utils/pmSiyuan.ts` 已承担 PM 思源相关纯函数逻辑，并已有 `pmSiyuan.test.ts` 测试。

### 1.2 本轮目标

1. 弹窗打开后默认展示“当前位置下的全部文档”，而不是空结果。
2. 有效位置解析规则固定为：`项目专属位置 > 全局默认位置`。
3. 项目未配置专属位置时，自动回退到全局默认位置。
4. 输入框默认行为改为本地即时过滤；仅在用户手动点击“扩展到全库”时，才使用当前输入发起一次远端搜索。
5. 保留“扩展到全库”作为手动备用入口。

### 1.3 非目标

1. 不重做思源目录获取协议。
2. 不改动 Rust 侧已有 `siyuan-search-pages` 搜索接口的协议。
3. 不在本轮新增目录缓存表或单独的页面列表接口。
4. 不把页面关联弹窗改造成复杂的双栏选择器或树形选择器。
5. 不改动页面创建逻辑的核心行为。

## 2. 已确认决策

1. 主路径采用“本地列表优先”，不再把远端搜索作为默认流程。
2. 弹窗默认列表来源于当前有效位置对应的目录子树。
3. 输入框始终表示“当前过滤词”；`location` 模式下用于本地即时过滤，`all` 模式下若继续修改输入则立即退出 `all` 视图。
4. 若无项目专属位置，则自动回退到全局默认位置；若仍无有效位置，不展示当前位置列表，但保留手动“扩展到全库”能力。
5. “扩展到全库”保留为次级入口，但必须手动触发；`all` 模式只表示“本次远端搜索结果视图”，不承载历史缓存复用语义。

## 3. 交互设计

### 3.1 弹窗打开行为

1. 点击“关联主页面”或“添加附加页面”后，先解析当前有效位置：
   - 优先使用项目专属位置
   - 若项目未配置，则回退全局默认位置
2. 若目录缓存为空，先加载目录后再展示列表。
3. 若目录缓存已存在，立即展示缓存结果，并在后台静默刷新目录。
4. 打开弹窗时搜索框默认留空，不再自动填入工作项标题。
5. 若存在有效位置，默认结果集为“当前位置文档列表”，展示该位置节点本身与其全部后代文档。
6. 若不存在有效位置，默认仍进入 `location` 模式，但主体展示“无有效位置”提示，不自动切到 `all` 模式。
7. 每次打开弹窗时都重置到 `location` 模式，并清空本次弹窗内临时产生的 `all` 结果，避免不同工作项之间串状态。

### 3.2 输入过滤行为

1. 搜索框改为“过滤输入框”：
   - 有效位置可用时，placeholder 建议为：`输入标题或路径过滤当前列表`
   - 无有效位置时，placeholder 建议为：`输入关键词后点击扩展到全库`
2. 在 `location` 模式下，用户输入后立即对当前位置完整列表执行本地过滤：
   - 匹配 `docTitle`
   - 匹配 `docHpath`
   - 匹配 `docPath`
3. `location` 模式下清空输入后，列表恢复为当前位置完整列表。
4. `location` 模式下的本地过滤不触发任何远端请求。
5. `all` 模式下，当前输入只用于描述“本次全库搜索所基于的关键词”；若用户继续修改输入，则立即退出 `all` 视图：
   - 若存在有效位置，切回 `location` 模式，并用新输入继续过滤当前位置列表
   - 若不存在有效位置，清空 `all` 结果并回到“无有效位置”提示态

### 3.3 扩展到全库行为

“扩展到全库”保留，但降级为手动备用入口。这里的 `all` 模式严格定义为**一次性手动触发的全库远端搜索结果视图**，不是“全部已打开笔记本下的全部文档列表”，也不是“可持续复用的全库缓存列表”：

1. 仅在用户主动点击按钮时发起远端搜索。
2. 若当前关键字长度小于 2，继续沿用现有提示规则，要求输入至少 2 个字符。
3. 无论当前是否存在有效位置，都允许用户使用当前关键字手动触发全库搜索。
4. 远端搜索成功后，将当前结果源切换为 `all`，并仅展示**本次按钮点击对应关键字**的结果。
5. 当存在有效位置时，全库结果展示期间，顶部提供一个明确的“返回当前位置列表”入口。
6. 返回当前位置列表后，恢复默认本地列表模式；当前输入框内容保留，并继续在当前位置列表上做本地过滤。
7. 全库结果只表示“当前关键字在全部已打开笔记本中的命中结果”，并继续沿用现有后端排序与截断规则；展示时只能显示当前命中条数，不宣称是全库总量。
8. 用户在 `all` 模式下继续修改输入时，不自动再次请求思源，也不继续复用旧的 `all` 结果，而是立即退出 `all` 视图。

说明：

- 默认打开弹窗时不进入全库模式。
- “扩展到全库”只是补充能力，不应抢占主流程。
- 全库模式的后续输入不自动再次请求思源；只有再次点击按钮时才重新远端搜索。
- 弹窗关闭后重新打开时，总是回到 `location` 模式，不保留上一次的 `all` 结果。

### 3.4 文案与状态

顶部提示文案从“当前搜索范围”调整为“当前列表范围”，并根据模式展示不同内容：

- 当前位置模式：
  `当前列表范围：研发笔记 · /项目页（共 18 篇）`
- 全库模式：
  `当前列表范围：本次全库搜索结果（当前显示 12 条）`

数量口径补充说明：

- `location` 模式下，数量表示“当前位置完整列表总数”，不随本地过滤输入变化
- `all` 模式下，数量表示“当前这次全库搜索返回的结果条数”，不表示全库总量
- 若需要展示过滤命中数，应作为次级文案单独显示，不与范围数量混用

空状态分为七类：

1. **未配置位置**
   - 文案：`当前未配置项目专属位置或全局默认位置，无法展示当前位置列表；你仍可输入关键词后手动扩展到全库搜索。`
2. **思源配置缺失**
   - 文案：`当前缺少思源服务地址或 API Token，请先完成思源配置。`
3. **目录加载失败**
   - 文案：`当前位置列表加载失败，请稍后重试。`
4. **位置失效或笔记本已关闭**
   - 文案：`当前默认位置已失效，或所在笔记本已关闭，请重新选择位置。`
5. **当前位置无文档**
   - 文案：`当前位置暂无可关联文档，可以直接新建页面。`
6. **全库搜索无结果**
   - 文案：`全库中没有找到匹配文档，请调整关键词后重试。`
7. **过滤后无结果**
   - 文案：`当前过滤条件下没有匹配文档。`
   - 说明：该空态仅在 `location` 模式下由本地过滤触发

## 4. 数据与状态设计

### 4.1 现有状态调整

`PmPanel.vue` 中的页面关联弹窗状态将从“搜索态”调整为“列表态 + 一次性全库搜索态”。

建议新增或重构以下前端状态：

```ts
const siyuanPageDialogMode = ref<"primary" | "extra">("primary");
const siyuanPageFilterKeyword = ref("");
const siyuanPageResultSource = ref<"location" | "all">("location");
const siyuanPageLocationResults = ref<PmSiyuanPageRef[]>([]);
const siyuanPageAllResults = ref<PmSiyuanPageRef[]>([]);
const siyuanPageSearchingAll = ref(false);
const siyuanPageLocationState = ref<
  "ready" | "missing-location" | "missing-config" | "load-error" | "invalid-location" | "empty"
>("ready");
```

说明：

- `siyuanPageLocationResults`：当前位置完整列表
- `siyuanPageAllResults`：当前仍处于 `all` 视图时，对应的一次性全库搜索结果
- `siyuanPageResultSource`：当前展示的数据源
- `siyuanPageLocationState`：当前位置结果的状态矩阵
- 当前展示列表建议通过 `computed` 派生：
  - `location` 模式：`siyuanPageLocationResults + siyuanPageFilterKeyword`
  - `all` 模式：直接展示 `siyuanPageAllResults`

补充规则：

- 弹窗打开时，`siyuanPageFilterKeyword` 重置为空字符串
- 弹窗打开时，`siyuanPageResultSource` 固定重置为 `location`
- 弹窗打开时，`siyuanPageAllResults` 清空
- 即使当前处于 `all` 模式，后台静默刷新也必须持续更新 `siyuanPageLocationResults + siyuanPageLocationState`
- 用户从 `all` 模式点击“返回当前位置列表”时，始终展示**最近一次成功解析或失败判定后的当前位置状态**
- 用户在 `all` 模式下继续修改输入时，必须立即清空 `siyuanPageAllResults`，并回到最新的 `location` 结果或“无有效位置”提示态

### 4.2 有效位置解析

继续复用现有 `resolvePmSiyuanEffectiveLocation()` 纯函数，确保逻辑唯一：

```ts
projectLocation ?? globalLocation ?? null;
```

本轮不新增第二套位置解析逻辑，避免后续项目设置与弹窗表现不一致。

## 5. 页面列表构建方案

### 5.1 复用目录树缓存

页面关联默认列表不新增后端接口，直接从已有 `siyuanDirectory` 目录树派生。

理由：

1. 当前目录数据结构已足够描述文档层级。
2. 本轮目标是交互优化，不是重建数据通路。
3. 复用 `pmSiyuan.ts` 纯函数更容易测试与维护。
4. 目录静默刷新成功后，若弹窗仍停留在 `location` 模式，应自动重算当前位置列表；若停留在 `all` 模式，仅更新底层缓存，不强制打断用户当前查看的全库结果。

### 5.2 纯函数拆分

建议在 `apps/desktop/src/utils/pmSiyuan.ts` 新增以下能力：

1. `collectPmSiyuanPagesForLocation(notebooks, location)`
   - 输入目录树与有效位置
   - 输出结构化结果，而不是仅返回页面数组
2. `filterPmSiyuanPages(pages, keyword)`
   - 对页面列表做本地过滤
3. 视需要补充内部 helper：
   - 查找目标笔记本
   - 在目录树中定位目标节点
   - 拍平目标子树为 `PmSiyuanPageRef[]`

推荐返回结构：

```ts
type PmSiyuanLocationPagesResult =
  | { state: "ready"; pages: PmSiyuanPageRef[] }
  | { state: "empty"; pages: [] }
  | { state: "invalid-location"; pages: [] };
```

职责边界：

- `collectPmSiyuanPagesForLocation()` 负责在“目录树已成功拿到”的前提下，完成位置定位、子树拍平与位置有效性判断
- `missing-config`、`missing-location`、`load-error` 仍由组件层负责，不下沉到该纯函数

### 5.3 子树提取规则

1. 若位置指向笔记本根目录：
   - 返回该笔记本下全部文档
2. 若位置指向某个父文档：
   - 必须先按 `notebookId + parentDocId` 在目录树中定位目标节点
   - 返回该父文档本身
   - 再追加该父文档下全部子文档
3. 结果按目录遍历顺序输出，保证与用户对目录结构的认知一致
4. 结果按 `docId` 去重，避免目录刷新或结构异常时重复展示
5. 禁止使用 `parentHpath`、标题或显示文案作为主定位条件；这些字段只用于展示与兜底提示
6. 若目标笔记本不存在或已关闭，直接判定为“位置失效或笔记本已关闭”
7. 若目标 `parentDocId` 在当前目录树中不存在，直接判定为“位置失效”
8. 若目标位置有效，但拍平后的结果为空，则返回 `empty`

## 6. 组件改动设计

### 6.1 `PmPanel.vue`

需要调整的点：

1. 打开弹窗时不再自动填充标题并触发搜索
2. 调用 `ensureSiyuanDirectoryLoaded()` 后，构建当前位置完整列表
3. 将结果展示改为读取 `computed` 派生列表
4. 删除默认“搜索”按钮
5. 保留 `扩展到全库` 按钮；当存在有效位置时，增加 `返回当前位置列表` 按钮
6. 提示文案从“搜索范围”改成“列表范围”
7. 空状态根据“未配置位置 / 配置缺失 / 目录加载失败 / 位置失效 / 无文档 / 过滤无结果 / 全库无结果”区分显示
8. 当前位置的“列表数据”和“状态结果”必须独立于当前展示源保存，避免 `all` 模式返回时丢失最近一次位置态
9. 无有效位置时，仍允许用户输入关键词并点击“扩展到全库”；但“立即新建”仍保持禁用
10. 用户在 `all` 模式下继续修改输入时，必须立即退出 `all` 视图，不复用旧的全库结果

### 6.2 `pmSiyuan.ts`

新增页面列表提取与过滤纯函数，并保持实现无副作用、无 Vue 依赖。

### 6.3 Rust 后端

本轮不改动后端数据结构，只复用已有：

- `tool:pm:siyuan-directory`
- `tool:pm:siyuan-search-pages`

其中：

- `siyuan-directory` 用于默认列表
- `siyuan-search-pages` 仅用于手动“扩展到全库”

## 7. 数据流

```text
打开弹窗
  -> 解析有效位置（项目 > 全局）
  -> 确保目录已加载
  -> 若存在有效位置，则从目录树提取当前位置全部文档
  -> 若不存在有效位置，则展示“无有效位置”提示
  -> 渲染默认 location 视图
  -> 用户输入
  -> 在 location 视图内本地过滤当前位置列表

点击“扩展到全库”
  -> 校验关键字长度
  -> 调用 siyuan-search-pages(searchAll=true)
  -> 保存本次全库搜索结果
  -> 切换展示源为 all

点击“返回当前位置列表”
  -> 切换展示源为 location
  -> 继续使用当前输入做本地过滤

all 视图下继续修改输入
  -> 清空当前 all 结果
  -> 若存在有效位置，则回到 location 并继续本地过滤
  -> 若不存在有效位置，则回到“无有效位置”提示态
```

## 8. 错误处理

### 8.1 默认列表阶段

1. 未配置有效位置时，不报错弹 toast，改为在弹窗主体给出明确提示
   - 同时保留“扩展到全库”入口
2. 思源配置缺失时，不进入通用搜索空态，直接展示“配置缺失”主体提示
3. 目录加载失败时：
   - 若已有上一次成功的当前位置结果，则继续保留结果列表，同时显示轻量错误提示
   - 若尚无任何成功结果，则展示“目录加载失败”主体提示
4. 若有效位置所在笔记本已关闭：
   - 提示：`当前默认位置已失效，或所在笔记本已关闭，请重新选择位置`
5. 若有效位置在最新目录中不存在：
   - 提示：`当前默认位置已失效，请重新选择位置`

### 8.2 全库搜索阶段

1. 继续复用现有后端校验：
   - 关键词长度需在 2 到 50 个字符之间
2. 全库搜索成功后，结果只表示“本次按钮点击对应关键字”的命中结果，不作为后续输入的缓存数据源
3. 全库搜索失败时：
   - 保持当前位置列表不丢失
   - 不强制切换到空的全库模式
4. 用户在 `all` 模式下继续修改输入时：
   - 立即清空 `all` 结果
   - 若存在有效位置，切回 `location` 模式并继续本地过滤
   - 若不存在有效位置，回到“无有效位置”提示态
5. `all` 模式期间若后台静默刷新发现当前位置已失效、已关闭或为空：
   - 当前界面仍停留在 `all` 模式
   - 但必须同步更新内部的 `locationResults/locationState`
   - 用户点击“返回当前位置列表”后，应直接看到最新的位置结果或最新的位置错误态，而不是打开弹窗时的旧快照

5. 无有效位置时，不展示当前位置列表，但仍允许手动“扩展到全库”
6. 点击“扩展到全库”后可切换到本次远端结果
7. `all` 模式下继续修改输入后，立即退出 `all` 并回到 `location` 或“无有效位置”提示态
8. 点击“返回当前位置列表”后恢复本地列表模式
9. `all` 模式期间目录静默刷新后，返回 `location` 模式时显示的是最新位置结果或最新位置错误态

## 10. 风险与取舍

1. 默认列表依赖目录缓存，首次打开弹窗时可能需要一次目录加载
2. 目录树是层级结构，页面列表是平面结构，提取规则必须保持稳定，否则容易出现“根页漏掉 / 子页重复”问题
3. 若继续保留全库按钮，就必须清晰标识“当前正在看的是哪一次远端结果”，并在用户修改输入时及时退出 `all` 视图，避免误以为输入一直在全库中实时搜索

## 11. 实施摘要

本轮采用“本地列表优先，全库搜索兜底”的轻量方案：

1. 默认打开即展示当前位置全部文档
2. 输入默认仅用于本地即时过滤；只有点击“扩展到全库”时才触发一次远端搜索
3. 项目位置缺失时自动回退全局默认位置；若仍无有效位置，则允许手动扩展到全库
4. `all` 仅表示本次手动触发的远端结果，用户改输入后立即退出 `all`
5. 不新增后端接口，优先复用现有目录树和纯函数能力
