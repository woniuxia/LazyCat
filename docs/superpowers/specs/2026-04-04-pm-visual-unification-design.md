# 项目管理展示与编辑体验统一优化设计

- 日期：2026-04-04
- 范围：`项目管理 > 左侧项目栏 / 看板卡片 / 详情侧栏 / 工作项编辑弹窗`
- 状态：评审通过，待用户复核

## 1. 背景

当前项目管理面板已经具备项目切换、看板卡片、详情侧栏、工作项编辑、思源关联等完整能力，但四个关键界面的“项目身份表达”仍然不统一：

1. 左侧项目栏更像普通列表项，项目权重与当前焦点不够明确。
2. 看板卡片里，项目名只在总览态底部弱露出，项目信息出现得太晚。
3. 详情页仍以 `label / value` 纵向堆叠为主，项目身份只是普通字段之一。
4. 编辑弹窗虽然已做过时间与思源关联优化，但整体仍偏线性表单，项目语义不够强。

用户希望这次不是只修一个局部，而是围绕“项目身份如何统一被看见”做一轮整体规划与视觉收敛。

## 2. 改动目标

本次设计的明确目标如下：

1. 统一项目管理四个关键界面的信息层级与视觉语言。
2. 让“当前工作项属于哪个项目”在总览、详情、编辑态都更容易被快速感知。
3. 保持浅色、干净、工具型的产品气质，不做过重的企业后台视觉。
4. 在不扩展数据库和后端协议的前提下，优先利用现有前端数据完成体验升级。
5. 保持现有交互模型稳定，例如：
   - 左侧项目切换
   - 看板拖拽
   - 右侧详情滑出
   - 编辑弹窗保存流程
   - 思源关联链路

## 3. 非目标

本次设计明确不包含以下内容：

1. 不新增项目管理新模块。
2. 不重做甘特图交互。
3. 不扩展思源关联能力边界。
4. 不新增数据库字段、后端协议或用户设置项。
5. 不引入新的多步骤表单或复杂向导流。
6. 不修改项目编辑弹窗本身的业务字段模型。

## 4. 统一视觉系统

### 4.1 视觉方向

用户已确认左侧栏采用 `A 冷白蓝灰` 方向，本次四个区域统一沿用该体系。

整体基调：

1. 主背景偏冷白：`#F4F7FB`
2. 卡片底色纯白：`#FFFFFF`
3. 主描边蓝灰：`#DBE5F1` / `#E3EBF5`
4. 主强调蓝：`#4D7DF2`
5. 低对比辅助文本：`#6F8098`
6. 主文本色：`#223042`

### 4.2 组件基线

统一基线如下：

1. 主卡片圆角：
   - 侧栏卡片 `12px ~ 16px`
   - 弹窗/详情主信息卡 `14px`
2. 描边：
   - 主卡片 `1px solid #DBE5F1` 或同等级变量
3. 阴影：
   - Hover / 选中状态使用轻阴影，避免厚重浮层感
4. 动效：
   - Hover / 选中 / 按钮反馈控制在 `150ms ~ 200ms`
5. 信息层级：
   - 第一层：项目身份或标题
   - 第二层：时间 / 状态 / 类型 / 优先级
   - 第三层：标签、链接、附属资源

### 4.3 统一设计原则

1. 项目身份前置，但不压过工作项标题。
2. 相同语义尽量在不同区域使用相同结构。
3. 标签与元信息要收敛，避免一张卡片出现过多横向碎片。
4. 高优先级操作不和正文混排，避免打断阅读。
5. 能通过现有数据推导的显示，不新增后端负担。

## 5. 左侧项目栏设计

### 5.1 目标

左侧栏从“项目列表”升级为“轻量项目导航卡”。

### 5.2 结构

左侧栏结构调整为：

1. 顶部保留 `项目空间 + 新建` 头部。
2. `总览` 升级成单独的总览卡，不再是普通列表第一项。
3. 下面是 `全部项目` 的统一卡片列表。
4. 不再区分 `进行中` / `已归档` 分组。

### 5.3 总览卡

总览卡承担全局入口语义，固定显示：

1. 总览名称
2. 右上角全局待办数
3. 项目数摘要
4. 待办总数摘要

总览卡使用更明显但仍轻量的背景和边框高亮，明确与普通项目卡区分。

### 5.4 项目卡

用户已确认项目卡精简到以下信息：

1. 项目名称
2. 右上角数字徽标

约束：

1. 右上角数字语义固定为 `当前待办数`
2. 卡片内部不再显示：
   - `待办 X`
   - 完成度百分比
   - 进度条
3. 项目颜色仍保留为左侧小色块，用于快速识别

### 5.5 排序与归档表达

用户已确认：

1. 所有项目统一混排
2. 按 `项目任务总数` 从大到小排序

补充规则：

1. 卡面右上角数字显示 `待办数`
2. 排序继续使用 `项目任务总数`
3. 若任务总数相同，则按稳定次序兜底：
   - 先原有 `sortOrder`
   - 再项目名或 `id`

这里的“项目任务总数”明确指：

1. 直接复用 `projectItemCounts[projectId].total`
2. 该值表示当前项目下全部工作项数量
3. 不区分工作项状态是否为 `done`
4. 若项目没有计数记录，则按 `0` 处理
5. 项目是否已归档不影响该排序口径

归档项目不再单独成区，但保留一枚极弱的 `已归档` 标签，避免状态语义完全丢失。

归档标签规则补充：

1. 标签只在 `project.status === 'archived'` 时显示。
2. 标签位置固定为：
   - 项目名称后
   - 右上角待办数徽标前
3. 标签视觉为低对比灰色小胶囊，不使用主强调色。
4. 标签不支持点击、不显示 hover 独立反馈、不参与排序。
5. 侧栏宽度不足时：
   - 项目名称优先省略
   - `已归档` 标签与右上角数字徽标保持固定可见
6. 归档项目仍可正常点击选中、右键操作和作为跨项目拖拽目标；归档语义只影响视觉提示，不新增交互限制。

### 5.6 保留交互

以下交互保持不变：

1. 点击切换项目
2. 右键项目菜单
3. 看板卡片拖拽到项目卡完成跨项目移动
4. 当前激活项目高亮

## 6. 看板卡片设计

### 6.1 总目标

看板卡片从“字段堆叠”改为更清楚的三层结构：

1. 顶栏：项目身份或核心元信息
2. 中层：标题
3. 下层：标签与辅助信息

### 6.2 总览态卡片

总览态卡片顶部左侧显示项目名，作为细胶囊标签。

结构如下：

1. 顶栏左侧：
   - 项目色点
   - 项目名胶囊
2. 顶栏右侧：
   - 置顶 / 逾期等图标
   - 日期摘要
3. 标题独立成主层
4. 下方显示：
   - 类型
   - 优先级
   - 标签

### 6.3 单项目态卡片

用户已确认单项目态与总览态保持同一骨架，但不显示项目名。

最终规则：

1. 单项目态顶栏左侧不留空
2. 顶栏左侧改为显示：
   - 类型
   - 优先级
3. 顶栏右侧继续显示：
   - 置顶 / 逾期图标
   - 日期摘要
4. 标题位置与总览态一致
5. 下方仅保留标签区

### 6.4 标签收敛规则

卡片标签区统一遵循：

1. 最多展示 2 个标签
2. 多余标签合并为 `+N`
3. 标签区不再和类型、优先级混排

补充规则：

1. 这里的“标签”仅指 `item.tags`，不包含类型、优先级、项目名或状态。
2. 标签展示顺序保持 `item.tags` 的原始顺序，不额外重排。
3. 当 `item.tags.length <= 2` 时，全部原样展示。
4. 当 `item.tags.length > 2` 时：
   - 固定展示前 2 个标签
   - 末尾追加一个 `+N` 标签
   - `N = item.tags.length - 2`
5. `+N` 仅表示剩余标签数量，不展开 tooltip，也不在卡片内追加更多说明。

### 6.5 删除的信息

用户已确认不需要以下信息：

1. 卡片底部再重复露出项目名
2. “双击编辑”这类操作提示文案

### 6.6 快捷操作位置

快捷推进按钮继续保留，但位置上移，与标题保持协调，不再压着底部信息区。

## 7. 详情侧栏设计

### 7.1 总目标

详情页从普通字段列表升级为“工作项档案”结构。

### 7.2 面板宽度

详情面板建议由当前约 `320px` 提升到 `352px ~ 368px`，避免资源信息过挤。

### 7.3 顶部主信息卡

顶部第一块合并如下信息：

1. 项目身份
   - 色点
   - 项目名
2. 工作项标题
3. 状态标签
4. 类型 / 优先级 / 标签
5. 逾期提示（若存在）

用户已明确要求删除 `进行中项目` 这句提示语，因此主信息卡不再展示该辅助标签。

### 7.4 时间轨迹区

时间信息改成两列小卡片，而不是长列表字段。

推荐字段：

1. 时间安排
2. 创建时间
3. 开始执行
4. 开始测试
5. 完成时间（如存在）

显示规则：

1. 两列网格优先
2. 没值时显示 `-`
3. 与逾期判断相关的日期保持现有语义

### 7.5 描述与资源的顺序

用户已确认如下规则：

1. 如果描述有内容：
   - `描述` 放在 `资源关联` 前面
2. 如果描述没有内容：
   - `描述` 放到最后，并弱化为空态

原因：

1. 有描述时，用户通常先看“要做什么”
2. 无描述时，描述区不应该抢占前排空间

### 7.6 资源关联区

链接与思源页面统一收进 `资源关联` 区块。

结构统一为：

1. 区块标题
2. 每种资源一个行卡片
3. 行内显示：
   - 名称 / 值
   - 元信息
   - 打开动作

### 7.7 底部操作

底部操作区固定在详情面板底部，与正文区分离。

包含：

1. 置顶 / 取消置顶
2. 推进状态
3. 删除

## 8. 工作项编辑弹窗设计

### 8.1 总目标

编辑弹窗从线性表单改成分区表单，但不演化成多步骤流程。

### 8.2 宽度

弹窗建议从当前 `720px` 提升到约 `820px ~ 860px`，以容纳更清楚的分区和思源关联区。

### 8.3 顶部项目身份卡

编辑页顶部新增项目身份卡，显示：

1. 所属项目
2. 项目色点
3. 项目名
4. 右侧待办数徽标
5. `切换项目` 动作

用户已明确要求删除解释性提示文案，因此项目卡里不再显示：

- `支持快速切换项目，但不再只是一个没有语义的下拉框。`

### 8.4 核心信息区

核心信息区承载：

1. 标题
2. 类型
3. 优先级
4. 状态

布局规则：

1. 标题单独成一行
2. 类型 / 优先级 / 状态采用三列并排
3. 不再与项目字段混排

### 8.5 时间安排

用户已确认：

1. `时间安排` 独占一整行
2. 不与描述并列
3. 保持当前范围日期输入模式

### 8.6 链接

用户已确认：

1. `链接` 独占一整行
2. `打开 / 清空` 放到输入框尾部，而不是下方

因此链接控件应沿用当前输入框尾部操作模式，形成以下结构：

1. 输入值区域
2. `打开`
3. `清空`

### 8.7 描述

描述保留为独立大输入区，不和时间、链接做左右分栏。

### 8.8 思源关联

思源关联继续保留独立大卡片，位置放在核心编辑字段之后。

该区继续显示：

1. 当前位置摘要
2. 已关联页面列表
3. `关联页面`
4. 行内更多操作

本次不改变思源关联的业务能力，只优化它和主表单的前后关系。

### 8.9 流转记录

编辑态才会出现的：

1. 开始执行
2. 开始测试
3. 完成时间

统一收进低优先级的 `流转记录` 区域，不再打散在主表单中间。

## 9. 数据与实现边界

### 9.1 不新增后端协议

本次全部改动基于现有数据完成，不新增：

1. 数据库字段
2. Rust action
3. 前后端协议字段

### 9.2 可直接复用的数据

1. `projects`
2. `projectItemCounts`
3. `selectedProject`
4. `selectedItem`
5. `PM_ITEM_TYPE_MAP`
6. `PM_PRIORITY_MAP`
7. `PM_STATUS_COLUMNS`
8. `itemProjectOptions`
9. `itemFormOpenableLink`

### 9.3 需要新增或重构的前端派生层

建议新增纯前端派生逻辑：

1. 左侧统一排序后的 `sidebarProjects`
2. 卡片展示辅助方法
   - 总览态顶栏信息
   - 单项目态顶栏信息
   - 标签截断与 `+N`
3. 详情侧栏的描述顺序判断
4. 编辑弹窗的分区结构辅助计算

建议的组件化边界：

1. 侧栏项目展示
   - 负责项目卡结构、排序结果消费与归档标签显示
   - 不负责项目切换以外的业务副作用
2. 看板卡片展示
   - 负责总览态 / 单项目态顶栏结构与标签截断
   - 不负责状态推进、右键菜单等副作用实现
3. 详情侧栏展示
   - 负责主信息卡、描述顺序与资源区排版
   - 不负责删除、置顶、推进状态的业务逻辑
4. 编辑弹窗展示
   - 负责项目身份卡、表单分区、链接尾部动作布局
   - 不负责保存协议与思源请求本身

若本次实现后 `PmPanel.vue` 继续膨胀，优先把上述四类展示逻辑下沉为局部子组件或 helper，保持 `PmPanel.vue` 继续承担状态汇总与动作分发，而不是同时承载全部展示细节。

## 12. 风险与控制

### 12.1 风险

1. `PmPanel.vue` 已较大，继续堆 UI 逻辑会降低可维护性。
2. 左侧项目排序由“分组 + 原排序”切到“统一排序”后，可能影响用户已有肌肉记忆。
3. 详情和编辑弹窗都增加了顶部项目身份卡，需要避免重复实现导致样式漂移。

### 12.2 控制策略

1. 先抽出局部展示辅助逻辑，再落模板改造。
2. 排序规则保持稳定兜底，避免视觉跳动。
3. 颜色、圆角、边框、标题层级统一收敛成一套局部变量或样式片段。

## 13. 验收标准

满足以下条件即可视为本次设计达标：

1. 用户能在四个关键界面明显感知“当前属于哪个项目”。
2. 左侧项目栏、看板卡片、详情侧栏、编辑弹窗不再像四套独立语言。
3. 视觉风格保持浅色、工具型、轻量，不出现厚重后台感。
4. 不引入后端协议、数据库结构或业务流程扩展。
5. 当前已存在的项目切换、拖拽、右键菜单、详情滑出、编辑保存、思源关联等能力不回归。
