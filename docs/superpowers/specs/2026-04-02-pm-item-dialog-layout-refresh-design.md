# 项目管理工作项弹窗布局优化设计

- 日期：2026-04-02
- 范围：`项目管理 > 新建工作项 / 编辑工作项` 弹窗
- 状态：已确认，待文档评审

## 1. 背景

当前项目管理工作项弹窗存在两个主要体验问题：

1. 时间字段拆成“开始日期”和“截止日期”两个独立表单项，输入心智偏松散，和“这是一个完整计划区间”的认知不一致。
2. 思源关联区域采用大卡片 + 分段展示，纵向占位偏高，容易把主表单焦点从标题、类型、优先级、时间安排等核心信息上拉走。

用户明确希望本次改动只聚焦工作项弹窗，不扩散成整个项目管理页面重构。

## 2. 目标

1. 将时间输入改成单个“时间安排”范围控件，统一开始/截止的录入方式。
2. 将思源关联区域改造成轻量列表结构，明显降低纵向占位。
3. 保持主表单聚焦，优先突出工作项本身信息，而不是把思源关联做成一个“次级后台”。
4. 尽量复用现有 `startAt / endAt`、思源页面关联、甘特图、详情展示等数据链路，避免数据库结构升级。

## 3. 非目标

本次不包含以下内容：

1. 项目管理整页布局重做。
2. 甘特图交互规则调整。
3. 思源关联能力扩展（例如批量操作、新类型页面关系、跨弹窗复杂管理流）。
4. 数据库存储结构迁移。
5. 思源弹窗搜索机制的再次重构。

## 4. 现状问题

### 4.1 时间输入

- 当前弹窗将 `startAt` 和 `endAt` 分成两个独立日期控件。
- 用户需要逐个填写，无法自然感知“这是一个连续时间段”。
- 表单校验需要分别处理两个字段，状态更松散。

### 4.2 思源关联区域

- 当前区域包含标题、位置来源、主页面区块、附加页面区块、多行操作，纵向结构偏厚。
- 视觉上更像“嵌入式文档管理模块”，而不是“工作项的附属关联信息”。
- 当附加页面增多时，弹窗高度膨胀明显。

## 5. 设计原则

1. 主次分明：工作项核心信息优先，思源关联作为次级信息收纳。
2. 输入成组：同一业务概念尽量在同一个控件里完成录入。
3. 轻量可扫读：列表优先、摘要优先、减少大块容器。
4. 兼容已有数据：新交互不强迫后端改模型，不打破甘特图与既有展示。
5. 操作分层：高频动作直接显示，低频或风险动作收进“更多”。

## 6. 弹窗结构设计

### 6.1 整体布局

工作项弹窗采用“`A1 单列轻刷版`”方向，维持单列表单与自上而下的阅读顺序，不引入新的分组卡片层级，也不扩散成整版改造。

整体信息区块重新组织为：

1. 基础信息
   - 标题
   - 类型 + 优先级（同一行）
   - 状态（单独一行）
2. 时间安排
   - 单个日期范围选择器
3. 描述
   - 多行文本输入
4. 思源关联
   - 顶部摘要 + 统一列表

### 6.2 基础信息布局

- 标题保持单独一行。
- 类型和优先级放在同一行，做有限度压缩，但不把整个基础信息区改成多列网格。
- 状态保持单独一行，继续沿用现有下拉能力。
- 视觉目标为紧凑但不拥挤，看起来仍然是原来的工作项弹窗节奏，而不是一次明显的整版改造。

### 6.3 时间安排

时间输入从两个独立字段改成单个日期范围选择器。

设计规则：

1. 分组名称统一为“时间安排”。
2. 控件语义为“日期范围”，不是“日期时间范围”。
3. 精度只到日期，不需要分钟级输入。
4. 选择规则为：
   - 要么整组留空；
   - 要么必须一次性选择完整的开始日期和截止日期。
5. 用户不再通过新界面制造“只填开始”或“只填截止”的新数据。

数据映射：

- 选择后写回：
  - `startAt = YYYY-MM-DD`
  - `endAt = YYYY-MM-DD`
- 清空后写回：
  - `startAt = null`
  - `endAt = null`

保存协议约束：

1. 表单提交到前后端协议层时，`startAt / endAt` 只允许两种值：
   - `null`
   - `YYYY-MM-DD`
2. 不允许提交空字符串、`undefined`、或带时间部分的值。
3. 每次保存请求都必须显式携带 `startAt` 与 `endAt` 两个 key，不允许通过字段省略表达“不更新”。
4. 若用户清空时间安排，则必须显式提交：
   - `startAt = null`
   - `endAt = null`
5. 若历史值包含时间部分或完整 ISO 字符串，进入表单时统一截断并规范化为前 10 位日期字符串。
6. 日期范围控件输出后必须满足 `endAt >= startAt`。若遇到历史脏数据 `startAt > endAt`，弹窗初始化时按升序纠正后展示，并在保存时写回纠正后的值。

### 6.4 描述

- 描述区保持为独立 textarea。
- 不扩展为富文本，也不加入额外辅助工具。

## 7. 思源关联区域设计

### 7.1 顶部栏

思源关联区采用轻量顶栏：

- 左侧：
  - 标题“思源关联”
  - 当前有效位置摘要（来源优先）
- 右侧：
  - 一个主按钮：`关联页面`

不再默认展开大块“主页面卡片 + 附加页面卡片”。

补充说明：

- 顶部栏展示的“当前有效位置摘要”始终表示当前工作项创建新思源页面时会使用的默认存储位置；
- 该摘要只依赖项目级/全局思源位置配置，不依赖当前是否已有主页面；
- 因此即使进入“无主页面 + 多个附加页面”状态，顶部摘要仍保持不变。
- 摘要文案采用“来源优先”格式，例如：
  - `项目专属位置 · 产品设计 / 项目管理`

### 7.2 统一列表

所有关联页面采用一个统一列表展示，不拆成“主页面分组”和“附加页面分组”。

列表规则：

1. 当前主页面所在行带 `主页面` 标记。
2. 当前主页面固定排在列表第一行。
3. 其他页面作为普通附加页面行显示，并排在主页面之后。
4. 若当前没有主页面，则整个列表按附加页面顺序平铺展示。
5. 每一行只展示最必要信息：
   - 页面标题
   - 路径摘要
   - 行尾动作

附加页面顺序规则：

1. 默认采用稳定插入顺序。
2. 通过 `关联页面` 新增附加页面时，新页面追加到附加页面列表末尾。
3. 删除附加页面时，剩余附加页面保持原有相对顺序。
4. 当附加页面被提升为主页面时，旧主页面降级为附加页面，并插入附加页面列表首位。

### 7.3 行尾动作

每一行右侧统一显示：

- `打开`
- `更多`

顶部主按钮 `关联页面` 的交互规则：

1. 若当前还没有主页面：
   - 点击后进入页面选择流程；
   - 首次选中的页面直接成为主页面。
2. 若当前已经有主页面：
   - 点击后进入页面选择流程；
   - 新选中的页面默认作为附加页面加入列表。
3. 页面选择流程保持单选，不引入多选。
4. 用户取消选择后，不写回任何变更。
5. 若选中的页面已经存在于当前列表：
   - 不新增重复项；
   - 保持当前列表顺序不变；
   - 给出轻量提示，告知该页面已存在。

动作收纳规则：

1. 主页面行的“更多”菜单包含：
   - `更换主页面`
   - `移除`
2. 普通附加页面行的“更多”菜单包含：
   - `设为主页面`
   - `移除`

这样可以让高频动作 `打开` 保持显性，同时把次级管理动作收进菜单，减少右侧视觉噪音。

状态迁移规则：

1. 主页面行执行 `移除`：
   - 当前主页面被移除；
   - 不自动提升任何附加页面；
   - 若仍有附加页面，则进入“无主页面 + 多个附加页面”的状态。
2. 主页面行执行 `更换主页面`：
   - 打开单选页面选择流程；
   - 选中新页面后，新页面成为主页面；
   - 原主页面降级为附加页面，并插入附加页面列表首位；
   - 若新页面原本已在附加页面中，则先从附加页面中移除，再提升为主页面，避免重复。
3. 附加页面行执行 `设为主页面`：
   - 该附加页面提升为主页面；
   - 原主页面降级为附加页面，并插入附加页面列表首位；
   - 其余附加页面保持原有相对顺序。
4. 主页面行执行 `更换主页面` 或附加页面行执行 `设为主页面` 时，若目标页面就是当前主页面，则视为无变化并关闭菜单。

### 7.4 空状态

当未关联任何思源页面时：

- 显示一条轻量提示；
- 不再使用大面积空卡片；
- 文案建议为：
  - `尚未关联页面，点击右上角开始关联。`

## 8. 详情展示同步

右侧工作项详情区建议同步调整时间展示方式：

### 8.1 时间展示

原有“开始日期 / 截止日期”两条字段在详情区内调整为一条“时间安排”，以便和表单输入心智保持一致。该项属于本次范围内的同步改动。

展示规则：

1. 同时存在 `startAt` 和 `endAt` 时，显示：
   - `YYYY-MM-DD ~ YYYY-MM-DD`
2. 只有 `startAt` 时，显示：
   - `YYYY-MM-DD`
3. 只有 `endAt` 时，显示：
   - `YYYY-MM-DD`
4. 都为空时，显示：
   - `-`

详情区思源展示范围：

- 详情区现有思源展示结构暂不重构；
- 只要求本次改动后不出现显示回归；
- 不额外追加详情区思源列表的新交互。

### 8.2 思源展示

详情侧栏的思源区域可以暂时保持现有结构，不强制和弹窗表单区完全同构。本次重点优化的是“编辑/新建场景的表单体验”，不是所有展示面统一改版。

## 9. 历史数据兼容策略

虽然新弹窗不再允许只填单边日期，但历史数据中仍可能存在：

1. 只有 `startAt`
2. 只有 `endAt`
3. 带时间部分的字符串
4. 非法或不可解析的日期字符串

编辑弹窗打开时的处理规则：

1. 若只有 `startAt`，则预填为 `startAt ~ startAt`
2. 若只有 `endAt`，则预填为 `endAt ~ endAt`
3. 若 `startAt > endAt`，则按升序预填为 `endAt ~ startAt`
4. 若某一侧是非法或不可解析日期，则视为该侧为空
5. 若只剩一侧为合法日期，则按该日期预填为同日范围
6. 若两侧都非法或为空，则视为未设置时间安排

这样可确保：

- 老数据不会导致新控件无法显示；
- 只要用户在编辑弹窗中执行保存，无论是否改动了时间安排，历史单边日期都会按当前控件值归一为完整区间；
- 不需要数据库迁移。

补充说明：

- 旧数据若未进入编辑流程，则展示层继续按真实值显示，不伪造双边日期；
- 只有在进入编辑弹窗时，才将单边日期映射为同日范围供用户确认；
- 若用户打开编辑弹窗后取消或关闭，不写回任何归一化结果。
- 本次表单层中的“合法日期”仅指可归一为 `YYYY-MM-DD` 的值；如 `''`、空白、`0000-00-00`、`invalid`、斜杠日期等都按非法值处理。

## 10. 前后端兼容结论

### 10.1 前端

当前前端中 `startAt / endAt` 主要以字符串形式流转，甘特图与卡片展示大多按 `slice(0, 10)` 或 `new Date()` 消费日期。

因此：

- 改成日期范围选择器不会破坏现有字段模型；
- 只要最终仍输出 `YYYY-MM-DD` 字符串，现有消费逻辑大部分可复用。

补充约束：

- 本次相关实现统一按“本地日期语义”处理，不引入 UTC 时间换算；
- 逾期判断继续以截止日期当天 `23:59:59.999` 作为边界；
- 甘特图与详情展示若接收到带时间部分的历史值，统一先截断为日期再参与计算与展示。
- `endAt = null` 的工作项永不判定为逾期；
- 只有 `startAt` 而没有 `endAt` 的历史工作项，在未进入编辑归一前，也不判定为逾期。

### 10.2 后端

当前 Rust 侧 `pm` 工具域对 `startAt / endAt` 的存取仍是字符串层处理，不要求额外的时间对象结构。

因此本次不需要：

- 新增字段
- 迁移表结构
- 修改接口协议

## 12. 测试方案

至少覆盖以下场景：

### 12.1 新建

1. 新建工作项时选择完整日期范围并保存成功。
2. 新建工作项时不填写时间范围并保存成功。
3. 新建工作项时思源列表为空，空状态文案正常。
4. 新建工作项时选择重复思源页面，不会生成重复项，并给出轻量提示。

### 12.2 编辑

1. 编辑已有完整日期范围的工作项，修改后保存成功。
2. 编辑时清空时间范围，保存后 `startAt / endAt` 一起清空。
3. 编辑存在旧单边日期的工作项时，弹窗自动映射为同日范围。
4. 编辑存在旧单边日期的工作项时，即使只修改非时间字段，保存后也会归一为完整区间。
5. 编辑存在旧单边日期的工作项时，若取消或关闭弹窗，不应写回归一化结果。
6. 编辑存在 `startAt > endAt` 的历史脏数据时，弹窗能以纠正后的区间展示并在保存后写回升序结果。
7. 编辑存在非法日期字符串的历史数据时，弹窗能按“非法侧视为空”的规则稳定初始化并保存。

### 12.3 思源关联

1. 通过 `关联页面` 入口新增页面。
2. 主页面行可以打开、移除、替换。
3. 附加页面行可以打开、设为主页面、移除。
4. 无主页面时，通过 `关联页面` 新选页面会直接成为主页面。
5. 已有主页面时，通过 `关联页面` 新选页面会作为附加页面加入。
6. 主页面切换后，列表中的 `主页面` 标记即时更新，且主页面行回到列表第一位。
7. 删除主页面后，不自动提升附加页面。
8. 选择已存在页面时不重复添加，并保持原有顺序。

### 12.4 展示联动

1. 看板卡片日期展示正常。
2. 详情区时间展示正常。
3. 甘特图仍能根据 `startAt / endAt` 正常生成任务区间。
4. 逾期判断仍以截止日期当天结束为准。
5. 截止日期当天结束前不算逾期，结束后才算逾期。
6. 没有 `endAt` 的工作项不判定为逾期。

## 13. 风险与控制

### 13.1 风险

1. 旧单边日期数据进入范围控件时可能出现空值映射不一致。
2. 详情区与卡片区若表达未同步，可能出现表单叫“时间安排”、展示仍是“开始/截止”的割裂感。
3. 思源列表区若直接复用现有大卡片样式，可能无法达到压缩高度的目标。

### 13.2 控制策略

1. 先在表单初始化层做单边日期兼容归一。
2. 同步整理详情区文案与时间展示。
3. 思源区域按“统一列表 + 行级动作”重写结构，不在旧卡片样式上继续堆叠补丁。

## 14. 实施边界

本次只做：

1. 工作项弹窗结构优化
2. 时间安排范围输入统一
3. 思源关联区的轻量列表化
4. 与此直接相关的显示同步和回归验证

本次不做：

1. 项目管理页面其他模块改版
2. 思源能力扩展
3. 甘特图产品交互重做
4. 数据库迁移

## 15. 验收标准

满足以下条件即可视为本次改版达标：

1. 用户能在一个日期范围控件中完成开始/截止日期选择。
2. 时间范围只能整组填写或整组清空。
3. 思源关联区域明显比现状更紧凑，不再占用大面积纵向空间。
4. 主页面与附加页面都能在统一列表中清晰识别。
5. 每行 `打开 + 更多` 的操作分层清晰。
6. 历史单边日期数据可正常编辑，不需要数据迁移。
7. 看板、详情、甘特图没有因本次改版出现回归。
