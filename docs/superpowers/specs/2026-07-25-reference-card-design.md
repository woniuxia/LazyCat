# 置顶参考卡设计

日期：2026-07-25
状态：设计已确认

## 1. 背景与决策

临时复制文字或代码用于比对时，当前需要先打开文本编辑器、粘贴内容，再在编辑器和工作窗口之间反复切换。该流程的主要成本不是文本保存，而是创建载体和持续切换窗口。

本功能采用“多张独立置顶参考卡”方案：用户通过全局快捷键或 Spotlight，把当前剪贴板文本直接变成可编辑的置顶窗口。每张卡片可独立拖动和缩放，适合同时展示 2～3 段参考内容，并与任意应用并排使用。

不采用以下方案：

- 单一参考板：资源更集中，但多段内容只能在一个大窗口内排布，不能自由贴近不同工作区域。
- 侧边挂件扩展：复用现有挂件，但查看多一步展开操作，也不适合自由并排。
- 主窗口工具面板：仍需要切换到 LazyCat，不能解决核心痛点。

## 2. 目标与非目标

### 2.1 目标

- 全局快捷键读取当前剪贴板文本并创建置顶参考卡。
- Spotlight 识别剪贴板后提供“创建置顶参考卡”结果。
- 不同来源文本创建新卡；相同来源文本聚焦已有卡。
- 同时支持多张独立卡片，可拖动、缩放和关闭。
- 卡片复用本地 Monaco，支持直接编辑、行号、语法高亮、查找、语言选择和自动换行。
- 内容仅在当前应用会话中存在；关闭卡片或退出 LazyCat 后清空。
- 所有失败显式反馈，不静默忽略或覆盖已有卡片。

### 2.2 非目标

- 不保存或恢复历史卡片。
- 不写 SQLite，不进入 Inbox，不提供卡片管理页。
- 不支持图片、文件、富文本、Markdown 预览或附件。
- 不实现卡片分组、标签、搜索、排序或跨设备同步。
- 不自动跟随剪贴板变化；只有用户主动触发时才创建或聚焦。
- 不把参考卡注册为主窗口工具面板。

## 3. 核心交互

### 3.1 创建与判重

提供两条入口：

1. 全局快捷键，默认 `Ctrl+Alt+Space`，可在设置中修改，并复用现有命名快捷键注册和冲突检查。
2. Spotlight 剪贴板建议中的“创建置顶参考卡”。

创建规则：

- 保留剪贴板原文，包括换行和缩进。
- 仅为判重执行 `CRLF -> LF` 和首尾空白归一化，再计算来源指纹。
- 来源指纹对应的窗口仍存在时，直接显示并聚焦该窗口，不创建重复卡片。
- 来源指纹只表示卡片的创建来源。即使用户已编辑卡片，再次触发相同原始剪贴板内容仍聚焦该卡片。
- 卡片关闭后移除来源指纹映射；之后相同内容可重新创建。

### 3.2 卡片窗口

每张卡片是独立 Tauri WebviewWindow：

- 动态标签为 `reference-card-<id>`。
- 默认尺寸为 `560 × 360`，最小尺寸为 `360 × 220`。
- 无系统装饰，始终置顶，可缩放，不显示在任务栏。
- 创建后获取焦点；失去焦点后继续置顶，但不主动抢回焦点。
- 新卡片在鼠标所在显示器的工作区内居中偏右，并按固定偏移错位排列；坐标必须限制在当前工作区内。

自定义标题栏包含：

- 拖动区域和“置顶参考”标识；
- Monaco 语言选择；
- 自动换行开关；
- “复制全部”；
- 关闭按钮。

卡片直接可编辑，不设置只读态或额外“进入编辑”步骤。关闭按钮立即销毁卡片，不弹确认框。

### 3.3 资源边界

- 最多同时打开 6 张卡片。
- 单段文本上限为 8 MiB，与 Inbox 当前外部文本边界保持一致。
- 达到卡片上限时，聚焦最近使用的卡片并提示“最多同时打开 6 张参考卡，请先关闭一张”，不得覆盖或关闭旧卡。
- 超过文本上限时拒绝创建并明确提示。

## 4. Spotlight 接入

Spotlight 继续复用现有剪贴板读取和 `detectClipboardContent()` 识别链路，不增加第二套内容类型判断。

空查询时：

- 已识别为 JSON、HTML、SQL 等内容时，保留现有智能工具建议及其首位顺序。
- 对任意符合大小限制的非空文本，额外显示“创建置顶参考卡”。
- 无智能工具建议时，“创建置顶参考卡”成为第一条剪贴板建议。

非空查询时，“参考”“置顶”“卡片”“clipboard”和“reference”可筛选出该结果。

剪贴板建议 payload 使用明确的判别字段区分：

```ts
type ClipboardSuggestionAction =
  | { kind: "open-tool"; toolId: string; text: string }
  | { kind: "open-reference-card"; text: string };
```

不能用虚构工具 ID 表示参考卡。选择参考卡结果时直接调用统一的卡片创建命令，成功后关闭 Spotlight，不显示 LazyCat 主窗口；失败继续使用 Spotlight 现有错误条和重试机制。

## 5. 语言识别与 Monaco

参考卡复用以下现有能力：

- `utils/monaco-setup.ts` 的离线 Monaco 和本地 Worker 配置；
- `MonacoPane.vue` 的编辑、行号、查找、语法高亮和自动布局；
- 剪贴板内容检测的 JSON、XML、HTML、SQL、Java 等类型。

新增纯函数把已识别的剪贴板类型映射为 Monaco 语言。无法识别、超过检测长度边界或不属于代码类型的内容使用 `plaintext`。用户可以随时手动切换语言。

`MonacoPane` 只增加参考卡实际需要的显式配置，例如 `wordWrap`；默认值必须保持现有使用方行为不变。Snippet 和参考卡共用语言选项，不复制两份语言列表。

“复制全部”先调用现有剪贴板回采抑制，再写入系统剪贴板，避免内容重新进入 Inbox。

## 6. 总体架构

```text
全局快捷键 ──读取当前文本──┐
                           ├─> Reference Card Manager ─> 创建或聚焦卡片窗口
Spotlight ──传入已读取文本─┘
```

### 6.1 Rust 会话管理器

新增独立 `reference_card` 模块，避免继续扩大 `main.rs`。职责包括：

- Windows Unicode 剪贴板文本读取；
- 文本规范化和来源指纹；
- 动态窗口创建、定位、显示和聚焦；
- 来源指纹、窗口标签和最近使用顺序的内存注册表；
- 6 张窗口上限、8 MiB 文本边界和失效窗口清理；
- 全局快捷键路径的错误通知。

全局快捷键调用“读取后显示”，Spotlight 调用“使用给定文本显示”。两者必须进入同一个内部创建函数，不能分别实现判重和窗口限制。

注册表不保存编辑后的卡片正文。正文只有前端 Monaco 一份运行时真值；Rust 只保存来源指纹和窗口关系。初始化文本只在窗口 ready 握手完成前临时保留。

### 6.2 前端入口

新增独立的 Reference Card 挂载入口和 Vue 组件，通过 `index.html?view=reference-card` 加载。`main.ts` 按现有 QuickCapture、WidgetCanvas 模式分流，不增加新的 Vite HTML 入口。

窗口创建时保持 `visible = false`。前端完成事件监听和 Monaco 挂载准备后发送 ready；Rust 再向对应窗口发送初始化 payload 并显示窗口。初始化超时或发送失败时销毁半成品窗口并清理注册表。

动态窗口标签必须加入 Tauri capability 白名单，使用 `reference-card-*` 模式，并验证窗口事件、隐藏/关闭和拖动权限。

### 6.3 设置与事件

- 新增命名快捷键 `reference-card`。
- SettingsPanel 增加“置顶参考卡”快捷键配置，并纳入现有冲突检测、保存和清空流程。
- 窗口初始化、复制错误和达到上限等跨窗口事件放入集中事件定义，不在组件中散落字符串。

## 7. 数据与生命周期

本功能没有数据库模型。

运行时记录只包含：

```text
source_hash
window_label
last_used_order
pending_initial_text（仅 ready 前）
```

生命周期规则：

- 卡片关闭时删除对应运行时记录。
- 下次触发前检查映射窗口是否仍存在；不存在则删除失效映射并正常创建。
- LazyCat 退出时由进程生命周期自然清空全部内容和映射。
- 不在设置、localStorage、文件或数据库中保存卡片正文、语言或窗口位置。

## 8. 错误处理

### 8.1 全局快捷键入口

- 空剪贴板或非文本：不创建窗口，通过已注册的系统通知能力提示“剪贴板中没有可用文本”。
- Windows 剪贴板被临时占用：做有限次短间隔重试；仍失败则通知实际错误。
- 文本过大、达到窗口上限、窗口构建失败或初始化超时：显式通知，不伪装成功。

### 8.2 Spotlight 入口

- 空剪贴板、非文本或文本过大时不生成参考卡建议。
- 创建命令失败时保持 Spotlight 打开，使用现有错误条显示原因并允许重试。
- 创建或聚焦成功后才关闭 Spotlight。

### 8.3 卡片内部

- 复制失败时在卡片内显示错误，不吞异常。
- 语言切换失败或 Monaco 初始化异常要记录明确上下文；窗口初始化失败按半成品窗口处理。
- 关闭卡片是明确丢弃操作，不提供伪恢复或隐藏持久化。

## 9. 测试策略

### 9.1 TypeScript 定向测试

- 剪贴板类型到 Monaco 语言的映射及 plaintext 回退。
- Spotlight 已识别内容继续保留现有智能工具建议首位。
- Spotlight 对任意有效文本追加参考卡建议。
- 未识别文本只有参考卡建议。
- “参考 / 置顶 / 卡片 / clipboard / reference”关键词可筛选。
- 参考卡建议走直接创建命令，不经过 `spotlight_pick` 和主窗口导航。
- `MonacoPane` 新增配置不改变现有调用方默认行为。

### 9.2 Rust 定向测试

- CRLF、首尾空白归一化和来源指纹稳定性。
- 相同来源聚焦、不同来源创建。
- 编辑后的窗口仍按原始来源指纹判重。
- 窗口关闭和失效窗口清理。
- 6 张上限和最近使用窗口选择。
- 8 MiB 边界。
- 多显示器错位定位和工作区 clamp 纯函数。
- 剪贴板临时占用重试与最终错误。
- ready 初始化成功、超时和失败清理。

### 9.3 最低验证

```text
参考卡、Spotlight、剪贴板检测和 Monaco 相关定向测试
cargo test reference_card
pnpm test
pnpm typecheck
pnpm --filter @lazycat/desktop build:web
cargo check
git diff --check
```

always-on-top、跨应用聚焦、动态 capability、拖动缩放和多显示器摆放必须进行真实 Tauri 冒烟。遵循项目规则，实施过程不会自动启动产品 UI；需要运行时由用户明确允许后启动。

## 10. 验收标准

1. 用户按全局快捷键后，当前剪贴板文本在鼠标所在显示器变成可编辑置顶卡片。
2. 用户也能从 Spotlight 的剪贴板建议创建同一类卡片，且不会唤起主窗口。
3. 现有 Spotlight 智能工具建议及其首位行为不回归。
4. 不同文本可形成多张独立卡片并排显示；相同来源只聚焦已有卡片。
5. 卡片支持拖动、缩放、语言选择、语法高亮、查找、自动换行和复制全部。
6. 同时打开 6 张后不再创建第 7 张，也不覆盖现有内容。
7. 空、非文本、超过 8 MiB、剪贴板读取失败和窗口创建失败都有明确反馈。
8. 卡片关闭后内容消失；退出并重启 LazyCat 后不会恢复任何卡片。
9. 参考卡正文不会写入数据库、localStorage、文件或 Inbox。
10. 浅色主题、窗口焦点、动态 capability、多屏定位和 Inbox 回采抑制通过验证。
