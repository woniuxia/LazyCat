# 密码管理服务器端口设计

## 目标

为密码管理中的“服务器”类型增加端口字段。新建服务器默认端口为 `22`；编辑缺少端口的存量服务器时同样显示 `22`。端口只用于凭据详情，不参与列表摘要或 Spotlight 检索。

## 现状

- `VaultEntryDialog.vue` 已有数据库端口输入和通用 `port` 表单状态，但服务器表单没有展示或提交端口。
- Rust `vault.rs` 的数据库字段构建已保存 `port`，服务器字段构建会丢弃该值。
- Vault 只加密密码，其他字段保存在 `plain_fields`；Spotlight 通过显式 `searchFields` 白名单建立检索字段，当前没有加入 `port`。
- 服务器列表摘要由地址和服务器类型组成，当前不包含端口。

## 设计

### 表单行为

- 服务器凭据在地址旁增加 `el-input-number` 端口输入，范围为 `1–65535`。
- 新建服务器时端口默认填充 `22`。
- 编辑服务器时优先使用已保存端口；存量记录没有端口时回退为 `22`。
- 从其他凭据类型切换到服务器时，将端口设置为 `22`；切换到数据库时继续使用对应数据库类型的默认端口。
- 服务器保存请求携带数值 `port`。

### 持久化与兼容

- Rust 的服务器 `build_fields` 将 `port` 写入完整字段 JSON，默认值为 `22`。
- `split_fields` 继续只加密 `password`；`port` 与地址、账号等字段一起保存在 `plain_fields`，无需数据库迁移。
- 旧记录在读取时保持原始数据不变；用户打开编辑框时由前端补显 `22`，下次保存后写入端口。

### 检索与展示边界

- 服务器摘要继续保持“地址 + 服务器类型”，不拼接端口，因此主面板列表检索不会因端口命中。
- Spotlight 的 `buildItem` 继续只索引标题、账号、标签、地址等既有字段，不将 `plainFields.port` 加入 `searchFields`。
- 不新增端口筛选、端口索引或端口相关快捷操作。

## 错误处理

- 复用 Element Plus 数值输入的上下限约束，端口必须在 `1–65535`。
- 后端只接受 JSON 无符号整数；缺失或类型错误的服务器端口按 `22` 构建，避免产生无端口的新服务器记录。
- 不吞掉保存错误，继续复用现有“保存失败”提示。

## 测试与验证

- Rust 单元测试先证明服务器字段能够保存显式端口，并在缺失端口时使用 `22`；拆分后端口位于明文字段且密码仍独立加密。
- 前端测试覆盖服务器新建/旧数据的默认端口、保存请求携带端口，以及 Spotlight 搜索字段排除端口。
- 运行 Vault 定向 Rust 测试、相关 Vitest、`pnpm typecheck` 和桌面渲染层构建。

## 非目标

- 不修改数据库类型的端口默认规则。
- 不显示或检索服务器列表中的端口。
- 不改变 Vault 加密模型、数据库表结构或 IPC 通道。
