# 密码库双空闲规则自动锁定设计

日期：2026-07-23

## 1. 背景与目标

密码库当前使用一组“严格 / 平衡 / 便捷”预设控制敏感信息隐藏和 Vault 活动超时。默认平衡预设会在 30 分钟没有 Vault 活动后硬锁，但该规则无法表达“整台电脑连续一段时间没有键盘或鼠标输入”。

本次增加两条可以独立启停、独立配置并允许叠加的硬锁规则：

1. Vault 无活动自动锁定。
2. 电脑无操作自动锁定。

两条规则同时启用时，任一规则先达到阈值即硬锁密码库并清除内存中的会话密钥。新增的电脑无操作规则默认开启，默认阈值为 15 分钟。

## 2. 已确认产品规则

- 两条硬锁规则均支持独立开关。
- 两条规则均使用 `5 / 10 / 15 / 30 / 60 分钟`预设，不支持任意数值输入。
- 两条规则同时启用时使用“任一条件满足即锁定”的 OR 语义。
- 两条规则都关闭时，仍保留手动锁定、关闭到托盘时锁定和窗口失焦隐藏敏感信息。
- 电脑无操作规则对现有用户默认开启 15 分钟。
- 设置变更在持久化成功后立即应用；若新阈值已经被当前状态满足，下一次状态校验立即锁定。
- 窗口失焦只隐藏敏感信息，不销毁解锁会话。

## 3. 方案选择

采用 Rust 后端统一判定方案。Vault 解锁期间由后端监测任务每 30 秒检查两条规则；状态查询和所有需要活跃会话的敏感操作前也执行同一判断。前端定时器只负责状态同步，不作为安全边界。

不采用仅前端轮询方案，因为窗口隐藏、组件未挂载或 WebView 定时器被节流时无法保证锁定。也不只依赖请求前校验，因为电脑空闲达到阈值后，用户恢复输入会重置 Windows 系统空闲计时，随后到来的请求将无法证明此前已经发生过超时。

## 4. 设置模型与迁移

使用以下独立设置键：

| 设置键 | 含义 | 默认值 |
| --- | --- | --- |
| `vault_sensitive_hide_minutes` | 已展示敏感信息的自动隐藏分钟数 | 由旧预设迁移，默认 2 |
| `vault_activity_lock_enabled` | 是否启用 Vault 无活动硬锁 | `true` |
| `vault_activity_lock_minutes` | Vault 无活动硬锁分钟数 | 由旧预设迁移，默认 30 |
| `vault_system_idle_lock_enabled` | 是否启用电脑无操作硬锁 | `true` |
| `vault_system_idle_lock_minutes` | 电脑无操作硬锁分钟数 | 15 |

### 4.1 旧预设迁移

当新设置键不存在时，读取旧 `vault_lock_profile` 并按下表生成前端设置值和后端回退策略：

| 旧预设 | 敏感信息隐藏 | Vault 无活动硬锁 |
| --- | ---: | ---: |
| `strict` | 1 分钟 | 10 分钟 |
| `balanced` 或非法值 | 2 分钟 | 30 分钟 |
| `convenient` | 5 分钟 | 60 分钟 |

迁移不删除旧键，避免回退旧版本时丢失原有偏好。新版本只使用独立设置键进行后续读写。电脑无操作规则在没有新键时始终回退为开启 15 分钟。

### 4.2 归一化

- 两条硬锁分钟数只接受 `5 / 10 / 15 / 30 / 60`。
- 敏感信息隐藏只接受 `1 / 2 / 5` 分钟。
- 缺失值按迁移规则或默认值处理；非法值回退到对应默认值。
- TypeScript 与 Rust 使用相同的常量和映射，并以两侧单元测试固定协议。

## 5. 后端设计

### 5.1 锁定配置

在 `apps/desktop/src-tauri/src/tools/vault.rs` 中用明确结构表示两条规则及分钟数。后端从 `user_settings` 读取新设置；新键缺失时按旧预设回退，不依赖前端迁移已经运行。

Vault 会话继续保存密钥和 `last_activity`。不再把单一 `hard_lock_after_secs` 固化为会话建立时的唯一策略，以便设置保存后无需重新解锁即可生效。

### 5.2 系统空闲时间

复用 `apps/desktop/src-tauri/src/tools/widget/guards.rs` 已有的 Windows `GetLastInputInfo` 能力。新增返回 `Option<u32>` 的可失败读取函数，保留现有返回 `u32` 的 `seconds_idle()` 包装供 Widget 使用，避免扩大既有调用方改动。Vault 使用可失败接口区分真实零值与检测失败。

- Windows 返回距最近一次键盘或鼠标输入的秒数。
- API 失败时返回“无法判断”，不触发电脑无操作锁定。
- 非 Windows 构建返回“无法判断”，Vault 无活动规则仍正常工作。

### 5.3 统一锁定判断

抽取纯判断函数，输入为当前配置、Vault 会话活动时长和可选的系统空闲时长。规则如下：

```text
activity_expired = activity_enabled && vault_idle_secs >= activity_threshold_secs
system_expired = system_enabled && system_idle_secs exists && system_idle_secs >= system_threshold_secs
should_lock = activity_expired || system_expired
```

命中任一规则时调用现有硬锁流程，先清零密钥，再移除会话，并返回 `vault_locked_timeout`。所有需要会话密钥的敏感操作和 `status` / `touch` 都必须经过同一判断，避免不同 IPC 出现不同锁定结果。

判断使用 `>=`，使恰好到达阈值时立即过期。系统检测失败不影响 Vault 活动规则。

### 5.4 后端监测任务

应用启动时建立一个轻量监测任务，每 30 秒唤醒一次：

1. Vault 未解锁时直接跳过，不读取设置或系统空闲状态。
2. Vault 已解锁时读取当前配置和系统空闲样本，调用统一锁定判断。
3. 命中任一规则时清零会话密钥、移除会话，并向前端发送 Vault 已锁定事件。
4. 前端未挂载时事件可以无人接收；下次打开 Vault 时仍由 `status` 得到锁定状态。

监测状态保留上一次检查时间和系统空闲样本。若电脑休眠或任务暂停后恢复，当前输入已经重置系统空闲值，则结合上一样本、两次检查间隔和当前空闲值判断恢复输入之前是否可能已经达到阈值。对超过阈值且无法证明期间持续有输入的长监测缺口，按安全优先锁定，避免休眠恢复后漏锁。

正常运行时，30 秒监测周期意味着自动锁定最多比配置阈值晚约 30 秒。敏感操作前的同步判断可能更早锁定，但不会延后这一上界。

## 6. 前端设计

### 6.1 设置页

将“加密与安全”区域中的组合预设改为三个独立设置行：

1. `敏感信息隐藏`：`1 / 2 / 5 分钟`选择器，并保留“窗口失焦立即隐藏”的说明。
2. `Vault 无活动自动锁定`：开关和 `5 / 10 / 15 / 30 / 60 分钟`选择器。
3. `电脑无操作自动锁定`：开关和相同的分钟选择器。

规则关闭时禁用对应时长选择器。两条规则同时开启时显示“任一条件达到后即锁定”；只开启一条时显示该规则摘要；全部关闭时明确显示“仅手动或关闭到托盘时锁定”。

设置使用现有 `setSettingAndWait` 持久化。保存成功后更新摘要并主动查询一次 Vault 状态；保存失败时回滚对应控件并显示错误，不报告伪成功。

### 6.2 Vault 面板

- 将当前单一前端硬锁定时器调整为只负责 Vault 活动规则。
- 电脑无操作规则不在前端重复实现，避免维护第二套系统空闲真值。
- 保留现有 30 秒状态轮询作为事件之外的状态同步兜底。
- 监听后端 Vault 已锁定事件，收到后立即复用现有锁屏和敏感 UI 清理流程。
- 窗口重新聚焦时继续立即查询后端状态。
- 后端返回 `vault_locked_timeout` 时复用现有 `setLockState("locked")` 和敏感 UI 清理流程。

## 7. 数据流

### 7.1 修改设置

1. 用户切换开关或选择时长。
2. 前端归一化值并通过 `setSettingAndWait` 等待 SQLite 持久化。
3. 保存成功后，Vault 后端下一次状态或敏感操作校验读取新配置。
4. 若当前空闲时长已达到新阈值，后端立即清除会话并返回锁定状态。
5. 保存失败时前端恢复旧值并显示错误。

### 7.2 正常使用与锁定

1. Vault 内有效活动继续通过现有 `touch` 更新 `last_activity`。
2. 电脑上的任意键盘或鼠标输入由 Windows 更新系统最后输入时间，不要求事件发生在 LazyCat 内。
3. 后端校验两条已启用规则。
4. 任一规则到期后，后端监测任务清除会话并发送锁定事件；所有后续敏感请求均得到锁定错误。
5. 前端收到事件后立即显示锁屏；事件未送达时由下一次 30 秒状态轮询兜底。

## 8. 错误处理与边界

- Windows 空闲 API 调用失败：不触发系统空闲锁，不吞掉另一条规则的判断。
- 配置缺失或非法：使用确定的迁移值或默认值，不允许产生零分钟或无限时长等隐式语义。
- 两条规则都关闭：不自动硬锁；手动锁定、关闭到托盘锁定和失焦隐藏继续有效。
- 应用休眠或前端定时器节流：安全性不依赖前端定时器；后端监测任务恢复后根据前后样本和监测间隔执行安全优先判断。
- 已过期会话访问：先清零密钥并移除会话，再返回错误，不允许操作继续执行。

## 9. 测试与验证

### 9.1 Rust 单元测试

- Vault 活动规则单独启用时的未到期、边界到期和超时。
- 电脑无操作规则单独启用时的未到期、边界到期和超时。
- 两条规则同时启用时任一先到期即锁定。
- 两条规则全部关闭时不自动锁定。
- 系统空闲检测失败时仅跳过系统规则。
- 命中规则后会话密钥被清零且会话被移除。
- 旧预设映射、新键优先级和非法配置回退。
- 30 秒监测任务在未解锁时跳过，在规则到期时只执行一次锁定和事件通知。
- 系统空闲值在监测间隔内被恢复输入重置，以及长时间休眠后恢复的判断。

- 开关组合对应的策略摘要。

## 10. 非目标

- 不新增任意分钟输入。
- 不改变主密码、加密算法或密钥派生参数。
- 不在前端实现 Windows 输入监听。

- 不改变 Spotlight 单条即时解密不延长全局会话的既有语义。
