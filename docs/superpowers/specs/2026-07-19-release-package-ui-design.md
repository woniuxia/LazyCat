# 上线包打包页面体验优化设计

## 背景

现有上线包打包页面的前后端构建命令使用单行输入框。后端实际上会将字段内容作为一段 PowerShell 脚本，在同一个 `powershell.exe -Command` 会话中执行，因此已支持多行命令和环境变量复用，但前端没有清晰表达这一能力。运行日志目前为深色背景，也与项目默认的干净浅色视觉方向不一致。

## 目标

1. 让前后端构建命令适合输入和编辑多行 PowerShell 脚本。
2. 提供 Java/Maven 环境、构建、文件及目录操作的常用示例，并支持一键复制。
3. 优化页面信息层级和空间利用率，使配置过程更友好、美观。
4. 将运行日志调整为白色背景，同时保持不同日志类型易于辨识。

## 非目标

- 不修改数据库结构、项目配置字段或前后端 IPC 协议。
- 不改变 PowerShell 的启动方式、命令执行语义、取消机制和归档流程。
- 不增加命令模板插入、命令历史或脚本语法高亮。
- 不重构上线包打包运行态或其他工具页面。

## 页面结构

采用“紧凑双栏工作台”布局：

1. 归档根目录继续位于页面顶部，作为全局配置。
2. 左侧项目列表保持现有职责和交互。
3. 右侧顶部集中显示项目名称、说明和保存、开始打包等主要操作。
4. 项目名称作为独立基础字段放在工程卡片之前。
5. 前端工程与后端工程分别放入两个并排卡片，便于对照配置。
6. 卡片容器使用自适应网格；可用宽度不足时自动切换为单列，保证命令编辑框不被挤压。
7. 运行日志作为工作区下方的独立白色卡片展示。

## 构建命令编辑器

前后端构建命令统一使用 Element Plus 多行输入框：

- 使用等宽字体，便于阅读路径、参数和 PowerShell 语法。
- 默认显示 4 行，随内容自动增高，最多显示 9 行，超过后在输入框内滚动。
- 保留换行内容原样保存；现有配置和后端字段无需迁移。
- 输入框下方提示：内容会作为 PowerShell 脚本在同一会话中顺序执行，前面设置的环境变量可供后续命令使用。
- 提示外部构建工具失败后应及时检查 `$LASTEXITCODE`，避免后续成功命令掩盖前序失败。

## 常用命令示例

在每个“构建命令”标签旁提供“常用示例”入口。点击后显示浮层，按用途展示以下可复制片段：

1. Java/Maven 环境：设置 `JAVA_HOME`、`MAVEN_HOME` 并将其 `bin` 目录加入当前 PowerShell 会话的 `Path`。
2. Maven 构建：执行常用生产构建，并在命令后检查 `$LASTEXITCODE`。
3. 复制文件：使用 `Copy-Item -LiteralPath ... -Destination ... -Force`。
4. 复制目录：使用 `Copy-Item` 的 `-Recurse -Force` 参数。
5. 移动文件或目录：使用 `Move-Item -LiteralPath ... -Destination ... -Force`。

每个示例包含名称、简短说明、代码块和复制按钮。复制仅写入系统剪贴板，不修改当前编辑框；成功显示轻提示，失败通过现有错误提示方式显式反馈。

示例数据放在上线包工具的纯前端 helper 中，组件只负责渲染和复制交互，便于用单元测试锁定示例分类和关键命令。

## 运行日志

日志区域改为白色卡片：

- 白色背景和浅灰边框，与工程卡片保持一致。
- 普通输出使用深灰正文。
- phase、stream 等元信息使用次要灰色。
- stderr 保持红色，确保错误仍然醒目。
- 空态使用次要文本色。
- 标题区域展示“运行日志”和当前运行状态，不改变现有日志数据来源及滚动行为。

## 状态与错误处理

- 运行中继续禁用项目配置编辑，行为与现状一致。
- 未保存修改、保存、删除、开始和终止流程保持不变。
- 示例复制失败时不静默吞错，向用户显示实际错误。
- 多行命令仍由现有后端作为单段 PowerShell 脚本执行，不在前端拆分或逐行解释。

## 测试与验证

1. 先为命令示例 helper 添加失败测试，覆盖示例分类以及 Java/Maven、复制、移动和退出码检查等关键内容。
2. 扩充 `ReleasePackagePanel` 的结构测试，覆盖多行输入、常用示例入口、一键复制和白色日志样式。
3. 运行上线包相关前端测试。
4. 运行 `pnpm typecheck`。
5. 运行 `pnpm --filter @lazycat/desktop build:web`。
