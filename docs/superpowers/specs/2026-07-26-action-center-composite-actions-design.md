# 动作中心组合动作设计

## 1. 背景

LazyCat 当前已有轻量动作中心，用于把 Todo 提醒绑定到上线包动作。现有实现包含可信动作定义、目标引用、派发状态机和目标工具适配，但没有独立动作中心入口，也不能让用户维护和手动运行组合动作。

本次扩展动作中心，使用户能够把多个可信原子动作保存为一个可复用组合并一键运行。首个使用场景是“项目开发环境”：切换 Hosts、启动浏览器身份，并按需启动一个或多个请求转发规则。

组合动作是独立能力，与 Todo 没有关系。本次不增加 Todo 绑定，不改变现有 `Todo -> 上线包打包` 的行为，也不迁移已有派发记录。

## 2. 目标

1. 新增独立“动作中心”工具页。
2. 支持创建、编辑、复制、删除和手动运行命名组合动作。
3. 组合由可信原子动作和目标引用组成，不保存目标工具的配置副本。
4. 首批支持切换 Hosts、启动浏览器身份、启动请求转发规则。
5. 支持组合级串行或并行执行，默认串行。
6. 单步失败不阻断其他步骤，结束后明确展示每一步的成功、已满足或失败结果。
7. 保存组合运行快照和最近结果，应用中断后能显式收口遗留运行。
8. 架构允许后续注册新的原子动作，但不引入任意脚本或通用工作流调度器。

## 3. 非目标

- 不新增或修改 Todo 动作绑定。
- 不支持任意命令、Shell 脚本或数据库注入动作定义。
- 不支持嵌套组合、条件分支、循环、步骤依赖或串并行混排。
- 不支持定时、提醒、快捷键等自动触发器。
- 不支持运行中取消。
- 不修改请求转发规则的 `autoStart` 持久化意图。
- 不检测浏览器身份是否已有窗口，也不关闭已有浏览器进程。
- 不建设复杂日志工作台；只保存组合和步骤级结果。

## 4. 方案选择

### 4.1 采用：注册表与持久化步骤

后端注册可信原子动作。用户组合只保存动作类型、目标引用和顺序，执行时通过原子动作适配器重新查询、校验和执行目标。

该方案复用现有动作中心的可信注册表原则，既能扩展新的动作类型，也不会把动作中心变成任意命令执行器。

### 4.2 不采用：固定项目开发环境模型

固定模型直接保存 Hosts、浏览器身份和请求转发字段，首版实现较快，但下一种组合场景需要新增另一套专用表、接口和页面逻辑，无法形成通用动作中心。

### 4.3 不采用：前端编排

由 Vue 页面依次调用各工具 IPC 虽然改动少，但页面关闭、并行执行、全局并发门禁、运行快照、异常恢复和结果一致性都难以保证。组合执行必须由 Rust 后端持有。

## 5. 核心模型

### 5.1 原子动作定义

动作中心维护代码注册的原子动作定义。定义至少包含：

- `actionType`：稳定唯一标识。
- `label`：界面名称。
- `targetKind`：目标类型。
- `targetToolId`：目标缺失时可跳转的工具。
- `supportsCombination`：是否允许作为组合步骤。
- 目标列表、目标校验和执行适配器。

首批可组合动作：

| actionType               | 名称           | 目标引用                              |
| ------------------------ | -------------- | ------------------------------------- |
| `hosts.activate`         | 切换 Hosts     | Hosts 配置稳定 ID                     |
| `browser_profile.launch` | 启动浏览器身份 | 适配器编码的浏览器类型与 profile 目录 |
| `request_forward.start`  | 启动请求转发   | 请求转发规则 ID                       |

`targetId` 对动作中心是不透明字符串，编码、解析和校验均由对应适配器负责。浏览器身份以 `browser + profileDir` 共同确定目标；动作中心不得自行拆解或猜测该引用。

现有 `release_package.run` 继续保留在可信动作注册体系中，但因其需要独立确认和长任务终态关联，首版不标记为可组合动作。

### 5.2 组合配置

新增组合配置和步骤两张表：

```text
action_combinations
  id
  name
  execution_mode       serial | parallel
  created_at
  updated_at

action_combination_steps
  id
  combination_id       REFERENCES action_combinations(id) ON DELETE CASCADE
  action_type
  target_id
  sort_order
  created_at
  updated_at
```

约束：

- 组合名称去除首尾空白后不能为空。
- `execution_mode` 只能为 `serial` 或 `parallel`。
- 一个组合至少包含一个步骤。
- 步骤动作必须来自注册表且支持组合。
- `sort_order` 在同一组合中唯一并连续重排。
- 允许多个步骤使用同一动作类型和不同目标，因此一个开发环境可启动多个请求转发规则。
- 同一组合内拒绝完全相同的 `action_type + target_id`，避免并行模式重复操作同一目标。
- 保存组合与替换步骤必须在同一事务内完成。

组合只保存目标引用，不复制 Hosts 内容、浏览器可执行文件路径、浏览器别名或请求转发参数。

### 5.3 运行与步骤快照

新增组合运行和运行步骤表：

```text
action_combination_runs
  id
  combination_id       REFERENCES action_combinations(id) ON DELETE SET NULL
  combination_name
  execution_mode
  status               pending | running | succeeded | partially_succeeded | failed
  result_code
  error
  created_at
  started_at
  finished_at

action_combination_run_steps
  id
  run_id
  source_step_id        删除或修改组合后可为空
  action_type
  action_label
  target_id
  target_label
  sort_order
  status               pending | running | succeeded | already_satisfied | failed
  result_code
  message
  started_at
  finished_at
```

数据库对 `action_combination_runs` 建立活动运行部分唯一索引：当状态为 `pending` 或 `running` 时，最多只能存在一条记录。该约束与进程内运行槽共同保证全局单运行。

运行创建时复制组合名称、执行模式、步骤顺序和展示标签。随后修改或删除组合、目标或别名，均不改变历史运行记录。

整体状态聚合规则：

- 所有步骤为 `succeeded` 或 `already_satisfied`：`succeeded`。
- 至少一个步骤成功或已满足，且至少一个失败：`partially_succeeded`。
- 所有步骤失败：`failed`。
- 应用中断遗留的活动运行统一收口为 `failed`，`result_code` 为 `interrupted`；仍在 `pending/running` 的步骤也标记为中断失败。

## 6. 原子动作适配器

每个可组合动作提供一致的内部边界：

```text
list_targets() -> target options
validate_target(target_id) -> current target summary
execute_target(target_id) -> step outcome
```

适配器返回明确的 `succeeded`、`already_satisfied` 或 `failed` 结果，不向组合执行器暴露领域配置，也不通过前端 IPC 反向调用自身。

### 6.1 Hosts

- 目标列表读取已有 Hosts 配置，并使用稳定数据库 ID 作为引用，避免重命名或删除后重建同名配置时误命中。
- 执行前读取目标配置和真实系统 Hosts。
- 真实系统 Hosts 与目标内容一致时返回 `already_satisfied`；不能只信任数据库 `enabled` 标记。
- 不一致时复用现有 Hosts 写入、备份、校验和 UAC 提权链路。
- UAC 取消、超时、读写或最终校验失败均返回该步骤失败，不阻断组合中的其他步骤。

### 6.2 浏览器身份

- 目标列表复用浏览器身份扫描、配置别名和可执行文件发现逻辑。
- 目标由浏览器类型和 profile 目录共同标识。
- 每次执行都复用现有浏览器身份启动参数和统计更新逻辑。
- 不检测是否已有该身份窗口；成功创建浏览器进程即返回 `succeeded`。
- 浏览器未安装、可执行文件失效或 profile 不存在时返回失败。

### 6.3 请求转发

- 目标列表读取已有请求转发规则。
- 执行前读取运行管理器中的真实状态。
- 状态为 `running` 时返回 `already_satisfied`，不重复启动。
- 其他状态调用现有单规则启动流程，并保留预检、逐规则锁和结构化错误行为。
- 组合动作只做本次启动，不修改规则的 `autoStart`。

## 7. 执行流程

### 7.1 启动

1. 前端请求运行已保存组合。
2. 后端在事务中重新读取组合和步骤，验证组合非空、动作定义仍可组合，并创建运行及步骤快照。
3. 后端占用全局组合运行槽，将运行切换为 `running`。
4. 后台执行器根据组合模式运行步骤，启动接口立即返回运行摘要，避免 Hosts UAC 阻塞页面。
5. 每个步骤开始和结束时更新数据库，并发出运行更新事件。
6. 全部步骤结束后按统一规则聚合整体状态、写入终态并释放运行槽。

事件只用于及时刷新，数据库记录是运行状态唯一事实源。页面在存在活动运行时进行低频轮询，以覆盖事件丢失、页面晚进入或监听重建。

### 7.2 串行模式

- 严格按 `sort_order` 逐个执行。
- 单步失败后继续执行下一步。
- 展示顺序与实际启动顺序一致。

### 7.3 并行模式

- 所有步骤同时进入独立工作任务。
- 每个任务使用自己的数据库连接和领域适配器，不能跨线程共享 SQLite 连接。
- 单个工作任务异常或 panic 只让对应步骤失败；协调器仍等待其他任务并收口整体运行。
- 最终结果始终按组合配置顺序返回，不按完成先后重排。

### 7.4 并发门禁

应用内同一时间只允许一个组合运行，组合内部仍可选择串行或并行。进程内运行槽提供快速判断，数据库活动运行唯一约束提供最终一致性。

重复点击当前组合或尝试启动其他组合时，不创建第二条运行记录，直接返回当前运行中的组合名称和状态。

## 8. 后端接口

沿用 `invokeToolByChannel -> tool_execute -> action_center` 链路，新增组合动作接口：

```text
tool:action-center:combination-definition-list
tool:action-center:combination-target-list
tool:action-center:combination-list
tool:action-center:combination-get
tool:action-center:combination-save
tool:action-center:combination-delete
tool:action-center:combination-run
tool:action-center:combination-run-get
tool:action-center:combination-run-list
```

接口职责：

- `combination-definition-list` 只返回支持组合的原子动作。
- `combination-target-list` 按 `actionType` 调用目标适配器。
- `combination-save` 同时处理新建和更新，后端完整替换步骤并保持事务性。
- 复制组合由前端读取现有配置、生成明确的新名称后调用 `combination-save`，不增加专用复制协议。
- `combination-run` 只接受已保存组合 ID，不接受前端提交的临时步骤。
- `combination-run-get` 返回运行及步骤快照。
- `combination-run-list` 首版返回指定组合最近 20 条记录，不提供无限历史加载。

新增事件：

```text
action-center://combination-run-updated
```

事件载荷至少包含运行 ID 和整体状态；前端收到后重新读取运行详情，避免事件载荷成为第二份状态真值。

## 9. 页面与交互

新增工具 ID `action-center`，通过现有工具目录、异步组件注册和主应用导航链路接入。

页面使用现有浅色风格和双栏布局：

### 9.1 左侧组合列表

- 显示组合名称、执行模式和最近运行状态。
- 提供新建入口。
- 支持选择组合，不自动执行。
- 空态说明如何创建第一个组合动作。

### 9.2 右侧编辑区

- 顶部编辑组合名称和 `串行 / 并行` 模式。
- 提供保存、复制、删除和“一键运行”。
- 主体显示可拖拽排序的步骤列表。
- 每步包含原子动作选择、目标选择、状态提示和删除入口。
- 允许添加多个请求转发步骤或其他同类型步骤。
- 动作类型变化时清空旧目标，再请求新动作的目标列表。
- 目标请求使用版本号或等价快照校验，晚响应不得覆盖当前步骤选择。

目标列表为空时显示对应工具的跳转入口。已保存目标失效时保留原步骤，显示不可用原因并要求用户重新选择，不静默移除。

存在未保存修改时禁用“一键运行”，明确提示先保存。运行中锁定当前组合编辑、复制和删除；由于全局单运行约束，其他组合的运行入口也禁用。

### 9.3 运行反馈

- 启动后立即展示当前运行进度。
- 每个步骤展示动作、目标及 `等待中 / 执行中 / 成功 / 已满足 / 失败`。
- 完成后展示整体成功、部分成功或失败提示，并列出每个失败步骤的领域错误。
- 页面底部展示当前组合最近 20 次运行，展开后查看步骤快照和错误。

## 10. 错误处理与恢复

- 保存和执行均校验动作定义；未知或不支持组合的动作显式失败。
- 保存时目标已失效则拒绝保存；保存后目标失效不删除配置，运行时仅对应步骤失败。
- 单步错误保存到步骤结果，不吞异常，也不把部分成功包装成完整成功。
- 并行工作任务无法启动、panic 或结果落库失败时，协调器将对应步骤和整体运行显式收口为失败。
- 组合或步骤保存失败时回滚整个事务，不产生半份配置。
- 活动运行创建失败时不得占用内存运行槽；后台任务启动失败时必须终结已创建运行并释放运行槽。
- 应用启动时先恢复遗留运行，再接受新的组合运行。
- 删除组合需要用户确认，活动运行期间禁止删除。删除组合不删除运行快照。
- 首版不提供取消；Hosts 的 UAC 取消或超时作为普通步骤失败处理。

## 11. 与现有能力的边界

- 现有 Todo 动作定义、绑定、派发、上线包关联和终态完成策略保持不变。
- 组合动作复用可信定义与目标适配原则，但使用独立的组合配置和运行记录，不强行迁移现有单动作派发表。
- Hosts、浏览器身份和请求转发仍分别拥有配置、运行状态、领域校验和错误文本。
- 动作中心不复制目标配置、不修改请求转发自启动意图、不绕过 Hosts UAC，也不重新实现浏览器参数构造。
- 后续触发器若需要启动组合，应只保存组合 ID 并调用组合执行入口；该扩展不在本次范围。

## 12. 测试策略

### 12.1 Rust 定向测试

使用可注入的测试原子动作执行器验证组合调度，不在自动测试中真实修改系统 Hosts、触发 UAC、启动浏览器或监听端口：

- 原子动作注册、仅列出可组合动作、目标列表和失效目标校验。
- 组合新增、更新、复制输入、删除、步骤排序、执行模式校验和事务回滚。
- 空组合、未知动作和无效目标拒绝保存。
- 运行快照不受后续配置和目标修改影响。
- 串行模式严格按序，失败后继续。
- 并行模式确实重叠执行，单任务异常不影响其他任务收口。
- 并行结果按配置顺序返回。
- 单步三种终态和整体三种终态聚合。
- 全局单运行门禁和重复启动拒绝。
- 后台任务启动失败、步骤落库失败和应用中断恢复。
- Hosts 真实内容一致返回已满足，否则调用现有写入链路。
- 浏览器身份始终调用现有启动链路。
- 请求转发运行中返回已满足，未运行时启动且不修改 `autoStart`。
- IPC action 白名单和 camelCase 契约。

### 12.2 前端定向测试

- 新建、编辑、复制和删除组合。
- 原子动作切换后清空目标并加载正确列表。
- 添加多个同类型步骤和拖拽排序。
- 串并行模式切换与默认串行。
- dirty 状态和全局运行态正确禁用操作。
- 目标空态、失效目标和工具跳转。
- 异步目标请求的晚响应不覆盖当前选择。
- 运行事件、轮询、逐步状态和终态汇总。
- 部分失败明确展示成功与失败步骤。
- 最近运行记录限制和展开详情。

### 12.3 最低验证

```text
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml action_center -- --nocapture
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml request_forward -- --nocapture
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml contract_tests -- --nocapture
动作中心相关前端定向测试
pnpm typecheck
pnpm --filter @lazycat/desktop build:web
git diff --check
```

不自动启动产品 UI，也不在验证中触发真实 Hosts/UAC、浏览器或请求转发服务。

## 13. 验收标准

1. 用户能从独立动作中心创建一个命名组合动作。
2. 用户能添加一个 Hosts 步骤、一个浏览器身份步骤和零到多个请求转发步骤。
3. 每个步骤只引用目标工具中的已有配置，目标配置不会复制到动作中心。
4. 组合默认串行，用户可切换为组合级并行。
5. 串行执行按排序进行，步骤失败不阻断后续步骤。
6. 并行执行同时启动各步骤，结果仍按配置顺序展示。
7. Hosts 已是目标真实内容时不重复写入；否则复用现有 UAC 和备份链路。
8. 浏览器身份每次执行都启动窗口，不检测已有进程。
9. 请求转发规则已运行时不重复启动，未运行时仅本次启动且不修改 `autoStart`。
10. 结束后明确展示每一步成功、已满足或失败，并正确区分完整成功、部分成功和全部失败。
11. 同一时间只能运行一个组合，重复启动不会产生第二条运行记录。
12. 未保存配置不能运行，运行使用已保存快照。
13. 已失效目标保留在组合中并显式提示，不被静默删除。
14. 应用中断后遗留运行被标记为中断失败，不阻塞后续运行。
15. 现有 Todo 与上线包动作行为保持不变。
