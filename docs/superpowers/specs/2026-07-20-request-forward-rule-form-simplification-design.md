# 请求转发规则表单简化设计

## 背景

请求转发的新建/编辑弹窗当前将字段拆为四个带编号的卡片区块。每个区块同时包含序号、标题、说明、边框和内边距，字段本身虽然不多，但视觉层级重复，导致弹窗显得冗长。

本次优化采用已确认的“A2 紧凑分组”方向：所有配置字段保持展开，通过减少重复说明和容器装饰提升扫读与填写效率。

## 目标

- 所有字段持续可见，不增加折叠、步骤或二级入口。
- 缩短表单纵向高度，减少重复标题、说明和卡片边框。
- 保持监听与目标两组信息的边界，方便快速核对端点。
- 保持现有帮助提示、安全警告、校验、只读和预检行为。
- 延续 LazyCat 现有浅色、克制、工作台式视觉风格。

## 非目标

- 不修改请求转发的数据类型、默认值或校验规则。
- 不修改前后端通道、保存流程、预检流程或运行逻辑。
- 不重组弹窗底部的保存、检测、启动和删除操作。
- 不调整请求转发主工作台、规则列表或日志观测页面。

## 信息结构

表单按以下顺序呈现：

1. 顶部基础信息：规则名称与协议。
2. 中部端点配置：左侧本地监听，右侧转发目标。
3. 底部采集选项：仅 HTTP 协议显示，两个采集选项横向排列并允许换行。

“规则标识”标题不再单独显示，名称和协议直接作为表单首行。端点配置保留“本地监听”和“转发目标”两个轻量分组标题。原“HTTP 采集”改为“采集选项”，不再显示编号和说明段落。

## 视觉与布局

- 移除 `.form-section` 的卡片边框、白色背景和大块内边距。
- 移除 `01-04` 序号及分组说明段落。
- 使用细分隔线和小号分组标题建立层级，不创建嵌套卡片。
- 规则名称与协议沿用现有宽窄比例。
- 在桌面宽度下，本地监听和转发目标组成两列；每组内部继续使用“主字段 + 端口字段”的既有比例。
- HTTP 目标 URL 占满转发目标分组宽度；TCP/UDP 使用目标主机与目标端口双列。
- 表单字段字号保持现有可读基线，不通过缩小文字换取密度。
- 弹窗宽度、滚动区域、只读提示、预检结果与底部按钮区保持现状。

## 响应式行为

- 当表单可用宽度不足时，端点两列切换为单列。
- 端点组内部在更窄宽度下切换为单列，避免输入框被过度压缩。
- 采集选项允许自然换行。
- 所有字段、校验信息与安全警告在窄屏下仍完整显示，不产生横向滚动。

## 交互与状态

- 字段的 `modelValue`、更新事件、禁用条件和协议条件渲染保持不变。
- 协议已持久化后的不可编辑行为保持不变。
- 字段帮助继续由可聚焦的问号 Tooltip 提供。
- 暴露监听地址的安全警告继续紧跟在本地监听字段之后，并保留 `role="alert"`。
- 运行中只读提示、停止并编辑、表单错误、预检结果和建议端口操作保持不变。
- 不引入动画；既有键盘焦点样式继续保留。

## 组件边界

修改 `apps/desktop/src/components/request-forward/RequestForwardRuleForm.vue`：调整模板分组和局部样式，不改变组件 props、emits 或业务计算。

`RequestForwardRuleDialog.vue` 的结构、行为与样式保持不变。测试改动限制在现有请求转发前端测试文件内。
