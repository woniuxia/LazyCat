# 项目管理甘特图状态筛选设计

- 日期：2026-04-04
- 范围：`项目管理 > 甘特图`
- 状态：已被 `2026-04-04-pm-shared-status-filter-design.md` 替代

> 说明：本设计文档对应的是“状态筛选仅作用于甘特图、入口保留在甘特工具栏”的早期方案。
> 用户随后确认改为“看板与甘特图共享同一套状态筛选，并提升到 PM 顶部工具栏”，因此本文件仅保留为历史记录，不再作为当前实现与规划依据。

## 1. 改动目标

在项目管理甘特图里新增状态多选筛选。

已确认边界：

1. 不再新增项目筛选，继续使用左侧项目 / 总览切换。
2. 状态筛选只作用于甘特图，不影响看板。
3. 状态默认全选，允许全部清空。
4. 在当前 PM 面板会话内保留筛选结果。

## 2. UI 改动

甘特图工具栏直接显示以下按钮：

1. `待办`
2. `进行中`
3. `测试中`
4. `已完成`
5. `全选`
6. `清空`

约束：

1. 不额外增加“项目筛选”或其他新筛选入口。
2. 不使用下拉面板，不增加标题文案，按钮直接显示在甘特图工具栏。
3. 工具栏在甘特空态下也必须保留，避免用户清空后没有恢复入口。
4. 窄宽度下允许换行，不要求强行单行。
5. 状态按钮必须能区分选中态和未选中态；`全选 / 清空` 可弱化，但不禁用。

## 3. 状态来源与按钮行为

状态定义统一复用 `apps/desktop/src/types/pm.ts` 中的：

1. `PmItemStatus`
2. `PM_STATUS_COLUMNS`

唯一映射：

1. `todo <-> 待办`
2. `in_progress <-> 进行中`
3. `testing <-> 测试中`
4. `done <-> 已完成`

按钮行为：

1. 点击状态按钮时，切换该状态是否参与甘特图展示。
2. 点击 `全选` 时，4 个状态全部选中。
3. 点击 `清空` 时，4 个状态全部取消。
4. `全选` 和 `清空` 只改状态筛选，不影响搜索、类型、优先级。
5. 未知状态、空状态或不在 4 个正式值内的状态，在甘特状态筛选链路中按 `todo` 兜底处理，避免工作项无提示消失。
6. 上述兜底只用于筛选归类和可见性计算，不修改工作项原始 `status` 值，也不要求改写其他位置的状态展示文案。
7. 未知状态在默认全选时应可见；当用户主动取消 `待办(todo)` 后，未知状态随之被过滤属于预期行为。

## 4. 数据流边界

前端只新增甘特专用状态筛选，不改后端协议，不改数据库。

过滤链路拆成两层：

1. `baseFilteredItems`
   - 继续承接搜索、类型、优先级。
   - 看板继续使用这一层。
2. `ganttFilteredItems`
   - 在 `baseFilteredItems` 之上叠加状态筛选。
   - 甘特图改为使用这一层。

状态保留范围：

1. 从甘特切到看板，再切回甘特，保留当前状态选择。
2. 在 PM 面板内切换项目 / 总览，保留当前状态选择。
3. `PmPanel` 组件实例销毁后重新进入 PM，恢复默认全选。
4. 状态选择为 PM 面板会话级全局状态，不按项目分别记忆。

父子组件边界：

1. `PmPanel.vue`
   - 持有当前选中状态
   - 计算 `ganttFilteredItems`
   - 向 `PmGanttView.vue` 传递状态与数据
2. `PmGanttView.vue`
   - 渲染按钮
   - 抛出状态筛选事件
   - 不持有状态筛选源数据

推荐接口约束：

1. `PmGanttView.vue` props
   - `items: PmItem[]`
   - `selectedStatuses: PmItemStatus[]`
   - `selectedItemId?: number | null`
   - `showProjectMeta?: boolean`
2. `PmGanttView.vue` emits
   - 现有事件保持不变
   - 新增 `toggle-status`，payload 为 `{ status: PmItemStatus }`
   - 新增 `select-all-statuses`
   - 新增 `clear-statuses`
3. `selectedStatuses` 对外保持数组形态：
   - 不允许重复值
   - 顺序固定跟随 `PM_STATUS_COLUMNS`
   - 内部实现可用 `Set`，但对外输出和比较以稳定数组为准

## 5. 甘特统计与空态边界

统计口径基于 `ganttFilteredItems`：

1. `已排期 X 项`
   - `X` 为当前筛选结果中可显示为甘特条的工作项数量
2. `另有 Y 项未设置日期`
   - `Y` 为当前筛选结果中不可显示为甘特条的工作项数量
   - 仅在 `Y > 0` 时显示

“可显示为甘特条”的判定继续复用现有 `hasPmDateSchedule(startAt, endAt)` 语义：

1. `startAt` 或 `endAt` 任意一侧能归一为合法日期，即视为已排期
2. 只有一侧日期时仍可显示，按现有甘特兜底逻辑构建单日条目
3. 两侧都为空或非法值时，视为未排期

空态区分：

1. `ganttFilteredItems` 为空
   - 显示“当前筛选结果没有可显示的工作项”
2. `ganttFilteredItems` 非空，但都不可显示为甘特条
   - 显示“当前筛选结果中有 X 项未设置日期，无法显示甘特图”

其他边界：

1. 若当前详情面板选中的工作项被状态筛掉，不主动关闭详情面板。
2. 甘特拖拽改日期逻辑不变。
3. 当 `selectedStatuses` 为空时，保持空选择，不自动回填全选。

## 6. 明确不改

本次不做以下内容：

1. 不新增项目筛选。
2. 不修改 PM 顶部通用筛选区结构。
3. 不让状态筛选影响看板列数据。
4. 不新增高级筛选器（逾期、置顶、标签组合等）。
5. 不新增后端接口、数据库字段或用户设置持久化。

## 7. 验收标准

1. 甘特图工具栏直接显示 4 个状态按钮以及 `全选 / 清空`。
2. 状态按钮支持多选，并允许全部取消。
3. 状态筛选只影响甘特，不影响看板。
4. 搜索、类型、优先级仍同时作用于看板和甘特。
5. 甘特图空态下工具栏仍保留，可继续恢复筛选。
6. “筛选后为空”和“未排期为空”两类空态能正确区分。
7. 会话内切换看板 / 甘特、项目 / 总览时保留状态选择。
8. 不引入数据库、后端协议或设置项变更。
9. 未知状态条目在甘特筛选链路中按 `todo` 参与归类，不因未知值直接消失。
10. `清空` 后切到看板再切回甘特，仍保持清空，不自动恢复全选。
