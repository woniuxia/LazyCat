# 项目管理甘特图状态筛选设计

- 日期：2026-04-04
- 范围：`项目管理 > 甘特图`
- 状态：评审中

## 1. 背景

当前项目管理面板已经具备以下筛选与切换能力：

1. 左侧项目列表支持在单项目与“总览”之间切换。
2. 顶部通用工具栏支持搜索、类型筛选、优先级筛选。
3. 甘特图视图已独立封装在 `PmGanttView.vue`，消费父层传入的 `items`。

用户最初提出“给甘特图添加项目和状态筛选”。经确认后，本次需求边界调整为：

1. **不新增项目筛选**。左侧项目 / 总览切换已经承担项目维度筛选职责，不再在甘特图内重复提供一套项目筛选 UI。
2. **只新增状态筛选**。且状态筛选仅作用于甘特图，不影响看板。
3. **状态支持多选**。默认全选，允许全部清空，并在当前 PM 面板会话内保留筛选状态。

## 2. 目标

1. 让用户在甘特图中按状态快速收敛展示范围。
2. 保持项目管理现有“左侧项目切换 + 顶部通用筛选 + 甘特专属控制”的职责边界清晰。
3. 以最小改动接入现有数据链路，不引入数据库或后端协议变更。
4. 明确区分“筛选后为空”和“有工作项但未排期”两类空态。

## 3. 非目标

本次不包含以下内容：

1. 不新增甘特图内的项目筛选。
2. 不修改顶部通用筛选区的结构与职责。
3. 不让状态筛选影响看板列展示。
4. 不新增后端接口、数据库字段或用户设置持久化。
5. 不扩展为“高级筛选器”（如逾期、置顶、排期状态、标签组合等）。

## 4. 方案比选与结论

本次讨论过 3 个 UI 方向：

1. **方案 A：放在甘特图工具栏**
   - 优点：语义最清晰，能力只出现在甘特图，不污染通用工具栏。
   - 缺点：工具栏横向空间更紧，需要接受换行布局。
2. **方案 B：放在顶部主工具栏**
   - 优点：入口统一，容易被发现。
   - 缺点：会把“只对甘特生效”的能力混进看板 / 甘特共用区域。
3. **方案 C：独立筛选按钮 + 浮层**
   - 优点：后续扩展性更好。
   - 缺点：对当前只有 4 个状态的场景偏重，操作路径更长。

**结论：采用方案 A。**

但具体控件形态不是“按钮 + 下拉面板”，而是用户确认后的最终版本：

1. 在甘特图工具栏里直接常显 4 个状态按钮。
2. 同时常显 `全选` 与 `清空` 两个动作按钮。
3. 不额外出现“状态筛选”“常驻筛选区”等标题文案。

## 5. 设计原则

1. 职责清晰：项目维度继续交给左侧列表；状态维度只在甘特图内处理。
2. 轻量直达：4 个状态足够少，直接点击按钮比下拉面板更高效。
3. 最小侵入：不改后端，不重做 PM 顶部工具栏，不改看板状态列逻辑。
4. 空态可解释：无结果原因必须可区分，避免把“未排期”和“被筛掉”混成一个提示。
5. 会话内保留：用户在同一个 PM 面板里来回切换视图时，不应反复重置状态选择。

## 6. 交互设计

### 6.1 工具栏位置

状态筛选按钮只出现在 `PmGanttView.vue` 自己的工具栏中，位置放在 `日 / 周 / 月` 视图切换旁边。

工具栏结构调整为：

1. 左侧：
   - `日 / 周 / 月`
   - `待办`
   - `进行中`
   - `测试中`
   - `已完成`
   - `全选`
   - `清空`
2. 右侧：
   - `已排期 X 项`
   - `另有 Y 项未设置日期`

不在按钮前单独增加“状态筛选”标题，避免重复占位。

### 6.2 按钮行为

状态按钮共有 4 个，对应：

1. `待办`
2. `进行中`
3. `测试中`
4. `已完成`

按钮规则：

1. 点击某个状态按钮时，切换该状态是否参与甘特图展示。
2. 状态按钮允许全部取消，不强制“至少保留一个”。
3. 点击 `全选` 时，4 个状态全部恢复为选中。
4. 点击 `清空` 时，4 个状态全部取消。
5. `全选` 与 `清空` 不影响搜索、类型、优先级等其他筛选条件。

### 6.3 视觉状态

按钮需要有明确的选中态与未选中态差异：

1. 选中态：高亮或实心，能一眼看出该状态仍在展示范围内。
2. 未选中态：浅色或描边，表示该状态已被排除。
3. `全选` 在 4 个状态全部选中时弱化显示，但不禁用。
4. `清空` 在 4 个状态全部未选中时弱化显示，但不禁用。

“弱化”而非“禁用”的原因是：

1. 降低视觉噪音。
2. 避免用户误解为按钮不可用。

### 6.4 响应式布局

由于工具栏新增 6 个按钮，工具栏必须支持窄宽度下换行，不要求强行维持单行。

布局要求：

1. 左侧按钮组允许 `flex-wrap`。
2. 右侧统计信息在空间不足时可换到下一行。
3. 不通过极端压缩间距、缩小点击热区或隐藏按钮来换取单行。

## 7. 数据流与状态设计

### 7.1 状态存放位置

状态筛选状态放在 `PmPanel.vue` 的前端会话状态中，不写入数据库，也不写入 `user_settings`。

推荐形态：

1. 使用 `PmItemStatus[]` 或等价的集合结构维护当前选中的状态集合。
2. 初始值为 `["todo", "in_progress", "testing", "done"]`。

### 7.2 保留范围

状态筛选在当前 PM 面板会话内保留：

1. 从甘特切到看板，再切回甘特，保留上次状态选择。
2. 在当前会话内切换项目 / 总览，也继续沿用同一组状态选择。
3. 刷新页面、重新进入 PM 面板后，恢复默认全选。

这里明确采用“面板级会话状态”，而不是“每个项目单独记忆一份”。

### 7.3 过滤链路拆分

当前 `PmPanel.vue` 中已有 `filteredItems`，承接：

1. 搜索
2. 类型筛选
3. 优先级筛选

本次建议拆成两层计算结果：

1. `baseFilteredItems`
   - 仅包含现有通用筛选：搜索、类型、优先级。
   - 看板继续消费这一层。
2. `ganttFilteredItems`
   - 基于 `baseFilteredItems` 再叠加“状态多选”过滤。
   - 甘特图改为消费这一层。

这样可以明确表达：

1. 看板与甘特共用基础筛选。
2. 只有甘特额外叠加状态筛选。

### 7.4 父子组件边界

不建议由 `PmGanttView.vue` 自己维护状态筛选状态。

推荐边界：

1. `PmPanel.vue`
   - 持有当前状态选择
   - 计算 `ganttFilteredItems`
   - 传入当前选择给子组件
   - 响应子组件抛出的交互事件
2. `PmGanttView.vue`
   - 负责渲染按钮
   - 负责抛出 `toggle`、`select-all`、`clear` 等事件
   - 继续专注甘特视图展示，不承担筛选状态源头

这样更利于测试，也更符合现有“父层掌握业务状态、子层负责视图交互”的方向。

## 8. 空态与边界行为

### 8.1 筛选后为空

当 `ganttFilteredItems` 为空时，甘特图进入“筛选后无结果”空态。

该场景包括：

1. 用户手动点击 `清空`。
2. 用户只保留某些状态，而这些状态在当前基础筛选结果中本来就没有匹配项。

文案保持轻量，延续当前语义，例如：

- `当前筛选结果没有可显示的工作项`

### 8.2 有结果但都未排期

如果 `ganttFilteredItems` 非空，但其中没有任何带日期区间的工作项，则继续沿用当前甘特图已有空态语义，例如：

- `当前筛选结果中有 X 项未设置日期，无法显示甘特图`

这类空态与“筛选后为空”必须分开判断，避免误导用户。

### 8.3 已选中工作项被筛掉

如果右侧详情面板当前正展示某个工作项，而用户调整状态筛选后，该工作项从甘特图中消失：

1. 不主动关闭详情面板。
2. 甘特图中不再显示对应条目。
3. 若用户再次在甘特图里选中其他条目，按现有逻辑切换详情目标。

这样可以避免用户在查看详情或编辑前后文时，因为临时调整筛选而被强制打断。

### 8.4 拖拽改日期

甘特图现有的拖拽改日期逻辑保持不变。

由于拖拽入口只存在于当前可见甘特条上，因此状态筛选不会额外引入新的拖拽边界情况。

## 9. 受影响区域

预计主要涉及以下区域：

1. `apps/desktop/src/components/PmPanel.vue`
   - 甘特专用状态筛选状态
   - `baseFilteredItems / ganttFilteredItems` 分层
2. `apps/desktop/src/components/PmGanttView.vue`
   - 工具栏按钮渲染
   - 向父层抛出状态筛选事件
3. 相关测试文件
   - `apps/desktop/src/utils/pmGantt.test.ts`
   - 若仓库中已有 `PmPanel` / 视图层测试，则同步补覆盖

## 10. 测试方案

### 10.1 过滤链路

至少覆盖以下场景：

1. 搜索、类型、优先级仍同时影响看板和甘特。
2. 状态筛选只影响甘特，不影响看板列数据。
3. `全选` 恢复 4 个状态。
4. `清空` 后甘特进入空结果。
5. 单个状态切换后，甘特结果按预期变化。

### 10.2 会话内保留

1. 从甘特切到看板，再切回甘特，状态选择保持不变。
2. 在当前会话内切换项目 / 总览，状态选择保持不变。
3. 重新进入 PM 面板后，状态恢复默认全选。

### 10.3 空态区分

1. 当状态全部被清空时，显示“筛选后无结果”空态。
2. 当状态筛选后仍有工作项，但它们都没有排期时，显示“未设置日期”空态。
3. 两类空态文案与触发条件不能互相覆盖。

### 10.4 布局回归

1. 按钮在普通宽度下排列稳定，不遮挡统计信息。
2. 窄宽度下允许换行，不出现按钮溢出、文字重叠或点击区域过小。

## 11. 风险与控制

### 11.1 风险

1. 若直接在现有 `filteredItems` 上叠加状态过滤，容易误伤看板逻辑。
2. 若空态判断顺序处理不当，可能把“未排期”错误显示成“无结果”。
3. 若工具栏仍强制单行，新增按钮后在总览场景下容易挤爆布局。

### 11.2 控制策略

1. 明确拆出 `baseFilteredItems` 与 `ganttFilteredItems` 两层。
2. 先判断“筛选结果是否为空”，再判断“是否全未排期”，保持语义互斥。
3. 直接接受工具栏换行布局，不追求单行强塞。

## 12. 实施边界

本次实现只应落在以下范围内：

1. 甘特图工具栏新增状态按钮、`全选`、`清空`。
2. 父层新增甘特专用状态过滤链路。
3. 空态文案与判断修正。
4. 补齐对应测试。

本次不应顺手扩展为：

1. 顶部通用工具栏重做。
2. 甘特图内新增项目筛选。
3. 新的高级组合筛选器。
4. 筛选持久化到设置。

## 13. 验收标准

满足以下条件即可视为完成：

1. 甘特图工具栏直接显示 4 个状态按钮以及 `全选`、`清空`。
2. 状态按钮支持多选，并允许全部取消。
3. 状态筛选只影响甘特，不影响看板。
4. 搜索、类型、优先级仍同时作用于看板和甘特。
5. 从甘特切走再切回，状态选择在当前会话内保留。
6. “筛选后为空”和“未排期为空”两类空态能够正确区分。
7. 不引入数据库、后端协议或用户设置变更。
