# 上线包 SSH 目标级并行上传设计

## 背景

上线包的前端和后端构建已经按目标并行，但服务器上传阶段仍只建立一个阻塞式 SSH/SFTP 会话，并依次上传前端目录和后端文件。前端目录上传还会为每个文件重复检查远端父目录，并且每写入 64 KiB 就发送一次 Tauri 状态事件。

Rust `ssh2` 的同一 `Session` 内部使用互斥锁；阻塞调用会阻塞该会话派生出的其他调用。因此，仅将当前文件循环放入多个线程不会形成有效并行。真正的目标级并行必须使用互相独立的 SSH/SFTP 会话。

本设计在不改变远端完整替换事务和前端 IPC 契约的前提下，先消除重复远端操作与高频进度事件，再让前端、后端目标使用最多两个独立会话并行上传。

## 依赖与实施顺序

本设计依赖 [上线包用户流程一致性修复设计](./2026-07-24-release-package-review-fixes-design.md) 对交付提交点、清理警告、目标集合预检和令牌撤销的修复结果。流程一致性修复先实施并验证，本设计随后基于其最新代码落地。

两项工作必须使用独立规格、计划和提交，不把并行上传混入流程一致性修复提交。

## 目标

1. 双目标上传时，前端和后端各使用一个独立 SSH/SFTP 会话并行传输，最大并发数固定为 2。
2. 单目标上传继续只建立一个会话，不增加无效线程或连接。
3. 前端远端目录根据产物清单预计算并只创建、检查一次，不再为每个文件重复遍历父目录。
4. 上传进度按时间节流，保留首帧、最新路径和精确终态，避免大文件产生大量 IPC/UI 更新。
5. temp、校验、backup、commit、rollback 和清理语义保持安全；正式目标只在全部目标上传和校验成功后才开始提交。
6. 用户取消能够关闭本次运行的全部 SSH 连接；内部 worker 失败不能误报成用户取消。
7. 认证秘密不复制到工作线程，不扩大持久化、日志或通知范围。

## 非目标

- 不实现前端文件级 2 到 4 路并发。
- 不对单个大文件做分块、随机写入或远端拼接。
- 不增加用户可配置的并发数、自动调优或服务器能力配置。
- 不引入 Tokio、异步 SSH 客户端、系统 `ssh`、`scp` 或远端 shell 命令。
- 不改变上传来源、产物清单格式、重试令牌语义或远端目标路径。
- 不修改 Vue 页面、状态事件字段或上传进度展示结构。
- 不把 64 KiB 传输缓冲区调整与本轮并发改动捆绑，避免同时改变多个性能变量。

## 方案比较

### 方案 A：只做串行路径优化

仅增加目录去重和进度节流，改动最小，也能改善大量小文件场景，但前后端总上传时间仍近似相加，不能利用两个独立目标之间的并行性。

### 方案 B：串行路径优化加目标级独立会话并行

前端、后端各使用一个会话上传各自临时目标；协调器在上传前后复用其中一个会话执行准备、提交和清理。它能保持现有事务边界，最大连接数明确，且不需要改动 UI 和项目配置。

本设计采用方案 B。

### 方案 C：前端文件池或单会话非阻塞复用

文件池需要处理目录创建竞争、更多连接、进度归并和服务器连接限制；单会话非阻塞复用需要引入复杂状态机。两者都明显扩大首轮优化风险，仅在目标级并行上线并完成真实压测后再重新评估。

## 总体架构

```text
构建产物清单
      │
      ▼
校验来源、目标和 runId
      │
      ▼
建立 1 或 2 个独立 SSH/SFTP 会话
      │
      ▼
检查 temp/backup 不存在并预创建前端目录树
      │
      ├───────────────┐
      ▼               ▼
前端 worker        后端 worker
上传 temp          上传 temp
校验 temp          校验 temp
      └───────┬───────┘
              ▼
      再次校验正式目标状态
              │
              ▼
      串行 backup / commit
              │
              ▼
      串行清理或逆序回滚
```

协调器只并行“上传临时目标和校验临时目标”。正式目标的状态复核、备份、提交、回滚和备份清理继续串行执行。

## 会话和连接生命周期

### 会话数量

- 单目标：建立一个 `SftpRemoteFs`，沿用串行上传和提交路径。
- 双目标：依次建立两个完全独立的 `SftpRemoteFs`，分别绑定前端和后端。
- 两个会话必须在正式上传阶段创建任何 temp 路径之前全部连接成功。

每个连接都重新执行 TCP 连接、SSH 握手、主机指纹比对、认证和 SFTP 初始化。第二个会话失败时显式结束本次上传，不静默降级为串行；此时尚未创建 temp 路径，也不会改变线上目标。

### 认证秘密

协调器依次借用同一个 `AuthSecret` 建立会话。会话建立后只把已经认证的 `SftpRemoteFs` 移入 worker，不克隆密码或私钥口令，也不把秘密放入线程共享状态。

### 连接注册表

活动运行中的单个 `Option<TcpStream>` 改为小型连接注册表。每次建立会话时注册一个 socket clone；正常结束统一清空，用户取消或应用退出时遍历并 `shutdown` 全部连接。

注册表不暴露地址、认证信息或连接详情，只负责关闭和释放本次运行的 socket。

## 部署阶段拆分

现有部署算法拆分为清晰的四个阶段，仍由 `release_package_deploy.rs` 持有不透明部署计划和事务真值；runtime 只负责建立会话、启动协调流程和发送事件。

### 1. 本地计划阶段

本地计划阶段不连接服务器、不写远端：

1. 校验目标不为空、`runId` 安全和远端目标路径互不包含。
2. 重新验证全部本地产物清单。
3. 为每个目标生成 final、temp 和 backup 路径。
4. 从前端清单预计算去重后的远端目录集合。

本地计划失败时直接结束，不建立额外 SSH 会话。

### 2. 会话与远端准备阶段

runtime 根据目标数量依次建立全部会话。全部会话成功后，协调器使用第一个会话：

1. 确认所有 temp、backup 均不存在。
2. 按深度顺序创建前端 temp 根目录和子目录。

远端准备失败时不启动 worker；已创建的本次 temp 目录按现有安全清理规则删除。

### 3. 并行上传与校验阶段

双目标时启动两个标准线程，每个线程独占一个 `SftpRemoteFs` 和一个目标：

- 前端 worker 只写前端 temp 目录中的文件。
- 后端 worker 只写后端 temp 文件。
- worker 完成上传后立即校验自己的 temp 目标。
- worker 返回会话和结构化结果，协调器统一 `join`。

目标路径已经在准备阶段验证为不重复、不互相包含，因此两个 worker 不会写同一路径。

增加独立的内部停止标记。任一 worker 首次失败后设置内部停止标记，另一个 worker 在文件块边界尽快退出。用户取消标记继续只表达用户意图；终态根据用户取消标记和首个业务错误分别判定，不能因为内部停止而伪报 `cancelled`。

线程 panic 视为上传失败。协调器仍等待其他线程结束，并使用可用的返回会话清理本次 temp 路径。

若 worker panic 导致没有任何会话可用于清理，结果必须返回全部可能残留的 temp 路径，不额外复制认证秘密或静默重连。

### 4. 串行提交阶段

仅当所有 worker 上传和校验成功后才进入提交：

1. 再次检查正式目标存在性和类型与预检绑定一致。
2. 按稳定目标顺序将已有正式目标重命名为 backup。
3. 将 temp 重命名为正式目标。
4. 任一提交失败时按逆序恢复已处理目标。
5. 全部提交成功后串行删除 backup。

提交点、清理警告和 `remote_committed` 语义以流程一致性修复后的结构化结果为准，不通过错误字符串推断。

## 远端目录预创建

前端清单只记录文件。准备阶段从每个相对文件路径推导全部父目录，并加入前端 temp 根目录：

1. 统一使用 `/` 分隔。
2. 去重后按路径深度和字典序排序。
3. 父目录先于子目录创建。
4. 已存在路径必须是目录；非目录冲突显式失败。

上传 worker 随后只负责创建远端文件和写入内容，不再为每个文件从根路径重复执行 `metadata`。

空前端目录仍创建并校验 temp 根目录，保持现有空目录部署能力。

## 进度聚合与节流

上传进度保持现有整体字段：`uploadedBytes`、`totalBytes` 和 `currentPath`。

- 两个 worker 使用原子计数累计已上传字节。
- `currentPath` 保存最近一次发生传输的相对路径。
- 开始上传时强制发送 `0 / total`。
- 中间状态最多每 100 毫秒发送一次。
- 文件切换不强制立即发送，避免大量小文件重新造成事件洪泛。
- 成功、失败或取消前强制发送最后一次可用进度；成功终态必须精确等于总字节数。

节流只影响状态事件频率，不改变每个 64 KiB 块的取消检查、字节统计或传输行为。

## 失败、取消和清理

### worker 失败

- 保存首个非取消业务错误作为主错误。
- 设置内部停止标记，让其他 worker 尽快结束。
- 等待全部线程退出后清理所有本次 temp 路径。
- 提交尚未开始，正式目标保持不变。

### 用户取消

- 设置现有用户取消标记。
- 关闭连接注册表中的全部 SSH socket，使阻塞 IO 尽快返回。
- 等待 worker 退出并清理 temp。
- 未提交时返回取消；远端已提交后的迟到取消继续不覆盖成功或成功警告终态。

### 清理失败

清理失败返回明确的 temp、backup 或正式路径供人工恢复。不能吞掉错误，也不能把未完成上传显示为成功。

## 前端和 IPC

本轮不改变状态事件、bridge action、TypeScript 类型或 Vue 组件：

- 上传进度继续显示整体百分比和一个最新活动路径。
- 双 worker 同时工作时，`currentPath` 表示最近发生进度的文件，不承诺展示所有活动文件。
- 上传日志和重试入口保持现状。
- 不新增并发开关或连接数量提示。

## 测试策略

严格按测试先行实施。

### 部署纯逻辑测试

1. 前端目录集合去重，并保证父目录先创建。
2. 多个文件共享父目录时，每个远端目录只检查、创建一次。
3. 空前端目录仍创建 temp 根目录。
4. 双目标上传实际同时进入写入阶段，不能只验证创建了两个线程。
5. 任一 worker 失败时另一个收到内部停止，正式目标不变且 temp 被清理。
6. worker panic 被转换为显式失败并执行可行清理。
7. 全部 temp 校验成功后才允许进入正式目标提交。
8. 既有第二目标提交失败、逆序回滚和恢复路径测试继续通过。

并发测试使用共享的 fake 远端状态和 barrier，避免依赖调度时序或 `sleep` 猜测并发是否发生。

### 运行态测试

1. 双连接均注册后，取消会关闭全部 socket 并清空注册表。
2. 内部 worker 停止不把整体状态变成用户取消。
3. 上传失败继续生成符合现有规则的重试描述符。
4. 提交完成后的迟到取消不覆盖成功或成功警告。

### 进度测试

1. 初始进度和最终进度必发。
2. 模拟时间推进时，中间事件频率不超过 10 次每秒。
3. 并发累计不会丢失字节，成功时精确等于 `totalBytes`。
4. 小文件路径快速切换不会绕过时间节流。

### 真实 SSH 验证

受控 loopback SSH fixture 可用时，在修改前先记录当前单会话双目标上传基线；实现后用相同产物、服务器和网络条件执行单目标、双目标、密码认证、私钥认证、取消和完整替换冒烟，并对比上传阶段耗时。

fixture 不可用时保留 ignored 测试并明确记录未执行真实吞吐对比，不能连接生产服务器补测，也不能用单元测试冒充性能验证。

最低验证：

```text
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml release_package -- --nocapture
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
pnpm typecheck
git diff --check
```

若流程一致性修复已经修改前端面板或 composable，合并验证继续执行其定向 Vitest 和 `pnpm --filter @lazycat/desktop build:web`，确保并发上传没有破坏同一发布链路。

## 验收标准

1. 双目标上传在测试中可证明存在真实重叠，且同时活动的 SSH/SFTP 会话不超过两个。
2. 单目标上传只建立一个会话。
3. 双会话全部建立前不创建正式上传 temp 路径。
4. 前端目录准备不再随文件数量重复检查相同父目录。
5. 上传中间进度事件频率受控，开始和终态数据准确。
6. 上传或校验失败不会触碰正式目标；提交失败仍按现有规则回滚。
7. 用户取消会关闭全部活动连接，内部错误不会伪装成用户取消。
8. 密码和私钥口令不复制进 worker，不进入配置、日志、通知或重试描述。
9. 现有上线包 Rust 回归测试全部通过；真实 SSH fixture 未配置时明确记录跳过。
