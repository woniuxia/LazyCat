# 置顶参考卡首次自适应尺寸设计

## 背景

置顶参考卡当前由 Rust 以固定 `560×360` 逻辑像素创建，最小尺寸为 `360×220`，窗口允许用户手动调整。固定尺寸会让短内容占用过多空间，也无法让较长内容在首次打开时获得合适的阅读区域。

本次改动只优化参考卡首次创建时的窗口尺寸。窗口显示后，编辑正文、切换语言或切换自动换行均不再触发自动调整。

## 目标

- 根据首次传入的参考文本，自适应计算窗口宽度和高度。
- 自适应宽度、高度分别不超过鼠标所在显示器可用工作区的 `30%`。
- 保留当前最小尺寸 `360×220`；当显示器工作区的 30% 小于最小尺寸时，以最小尺寸优先。
- 保持 `resizable(true)`，不设置原生最大尺寸，允许用户在首次打开后继续手动放大或缩小。
- 保持参考内容仅存在于当前卡片渲染进程，不增加设置项、持久化或新的 IPC 契约。

## 非目标

- 不在正文编辑时持续调整窗口。
- 不记忆用户手动调整后的尺寸。
- 不改变参考卡的工具栏、Monaco 编辑行为、置顶行为或多窗口上限。
- 不新增用户可配置的尺寸比例。

## 方案选择

采用 Rust 创建阶段估算文本尺寸的方案。Rust 在隐藏窗口创建完成后，根据初始文本和目标显示器工作区计算逻辑尺寸，设置窗口尺寸与位置，再沿用现有 ready 握手显示窗口。

未采用 Monaco 渲染后测量方案，因为它需要扩展前后端 ready 协议，还会引入窗口宽度与自动换行高度之间的循环测量。未采用前端隐藏 DOM 或 Canvas 测量方案，因为其精度优势有限，却增加了跨层窗口控制和初始化时序复杂度。

## 尺寸计算

尺寸计算实现为 `reference_card` 模块内的纯函数，输入为初始文本和目标显示器工作区的逻辑宽高，输出为窗口逻辑宽高。

### 文本列数

- 普通 ASCII 字符按 1 个显示列估算。
- 制表符按 4 列的下一个制表位展开。
- 中文及其他非 ASCII 字符按 2 个显示列估算。
- 按 `\n` 分行；Windows `\r\n` 中的 `\r` 不计入显示列。
- 空文本仍按 1 个视觉行处理。

### 自然宽度

自然宽度由最长显示行的列数、Monaco 等宽字体的估算列宽，以及窗口边框和编辑区余量组成。最终宽度按以下顺序限制：

1. 不小于 `360`。
2. 不大于显示器可用工作区宽度的 `30%`。
3. 如果 30% 上限小于 `360`，最终宽度保持 `360`。

工具栏在窄窗口下继续使用现有响应式布局，不单独提高最小宽度。

### 自然高度

自然高度由工具栏高度、文本视觉行数、Monaco 行高和编辑区余量组成。视觉行数同时考虑原始换行和宽度达到上限后的自动折行，避免长单行文本只扩大宽度而没有获得相应高度。

最终高度按以下顺序限制：

1. 不小于 `220`。
2. 不大于显示器可用工作区高度的 `30%`。
3. 如果 30% 上限小于 `220`，最终高度保持 `220`。

达到自适应上限后，剩余内容由 Monaco 内部滚动承载。

## 窗口生命周期

1. `show_text` 保留首次传入的文本，并在创建分支将其传给 `build_window`。
2. 窗口继续以 `visible(false)`、`resizable(true)` 创建，并保留 `360×220` 最小尺寸。
3. 创建隐藏窗口后，沿用现有顺序选择鼠标所在显示器、当前显示器或主显示器。
4. 将显示器物理工作区按缩放因子转换为逻辑工作区，计算首次自适应尺寸。
5. 将逻辑尺寸设置到窗口，再根据实际物理尺寸执行现有错位定位算法。
6. 前端完成现有事件订阅并调用 `reference_card_ready`；Rust 发送正文、显示并聚焦窗口。
7. 窗口显示后不再执行任何自动尺寸更新。

尺寸计算和定位使用同一个显示器工作区，避免尺寸按一个显示器计算、位置却落在另一个显示器。

## 错误处理

- 无法取得任何显示器信息时，保留当前 `560×360` 初始尺寸，输出带 `[reference-card]` 上下文的明确错误日志，并继续现有 ready 流程。
- 设置首次尺寸失败时，窗口创建流程返回明确错误，复用现有通知、会话取消和窗口清理链路，不显示尺寸状态异常的窗口。
- 定位失败沿用当前显式日志行为，不阻断参考卡显示。
- 不增加静默兜底、伪成功或新的持久化默认值。

## 代码边界

- `apps/desktop/src-tauri/src/reference_card/mod.rs`：窗口创建、显示器选择、首次尺寸应用和现有生命周期编排。
- `apps/desktop/src-tauri/src/reference_card/size.rs`：文本列数、视觉行数和自适应尺寸纯函数及单元测试。
- `apps/desktop/src/components/ReferenceCard.contract.test.ts`：守卫窗口仍可手动调整，且前端不引入持续自适应逻辑。

前端 Vue 组件、IPC 类型和事件 payload 不需要修改。

## 测试与验证

Rust 单元测试覆盖：

- 短文本使用最小尺寸。
- 长行在上限范围内扩展宽度。
- 多行文本在上限范围内扩展高度。
- 长行达到宽度上限后，折行增加视觉高度。
- 制表符、Windows 换行和非 ASCII 字符按约定计入显示列。
- 自适应宽高不超过工作区的 `30%`。
- 极小工作区下最小尺寸优先。

前端契约测试覆盖：

- Rust 窗口保持 `resizable(true)`。
- Rust 不设置 `max_inner_size`。
- `ReferenceCard.vue` 不监听正文变化或窗口 resize 来持续执行自适应。

验证顺序：

1. `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml reference_card -- --nocapture`
2. `pnpm --filter @lazycat/desktop test -- src/components/ReferenceCard.contract.test.ts`
3. `pnpm typecheck`
4. `pnpm --filter @lazycat/desktop build:web`
5. `git diff --check`

## 验收标准

- 首次打开短内容时，参考卡使用 `360×220`。
- 首次打开较长内容时，窗口宽高随内容增长。
- 首次自适应尺寸不超过鼠标所在显示器可用工作区的 `30%×30%`，最小尺寸冲突时除外。
- 达到上限的内容可在 Monaco 内滚动查看。
- 首次打开后修改内容不会改变窗口尺寸。
- 用户可手动将窗口调整到首次自适应上限之外。
- 多显示器和缩放场景下，尺寸与位置基于同一个目标显示器工作区。
