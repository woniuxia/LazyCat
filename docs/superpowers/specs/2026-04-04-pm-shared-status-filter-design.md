# 项目管理共享状态筛选设计

- 日期：2026-04-04
- 范围：`项目管理 > 看板 / 甘特图 / 顶部工具栏`
- 状态：评审中

## 1. 背景

当前项目管理已经在甘特图中支持状态多选筛选，但这套能力仍停留在甘特视图内部：

1. 看板视图无法按状态收敛任务集合。
2. 看板与甘特在同一 PM 会话内会出现不同的任务可见口径。
3. 甘特图当前使用一组内嵌状态按钮，而用户这次明确希望把状态筛选提升为顶部工具栏中的统一入口。

用户已进一步确认：

1. 看板和甘特图要共用同一套状态筛选。
2. 筛选入口放在顶部工具栏第二行，位于 `思源设置` 前。
3. 入口形态改为多选下拉框，不继续沿用甘特图里的状态按钮组。
4. 下拉框闭合态不回显已选状态文案，只保留固定入口名称。
5. 当某个状态未被选中时，看板中对应状态列直接隐藏。
6. 允许把所有状态都清空；清空后两种视图都展示空结果。

## 2. 改动目标

本次设计的明确目标如下：

1. 将状态筛选从“甘特图局部能力”提升为“PM 面板共享筛选能力”。
2. 让搜索、类型、优先级、状态四类筛选共同组成顶部工具栏的统一过滤区。
3. 保证看板与甘特图在同一 PM 会话内始终共享同一套任务可见口径。
4. 在不引入后端协议、数据库字段和持久化设置项的前提下完成交互升级。
5. 保持当前 PM 面板的核心交互稳定，包括：
   - 左侧项目 / 总览切换
   - 看板拖拽与右键菜单
   - 甘特图日期拖拽与视图模式切换
   - 详情面板打开逻辑

## 3. 非目标

本次设计明确不包含以下内容：

1. 不新增项目筛选。
2. 不新增逾期、置顶、标签组合等高级筛选。
3. 不把状态筛选做成按项目分别记忆。
4. 不新增“自动恢复全选”之类的保护逻辑。
5. 不修改后端工作项状态模型，不改变数据库中的 `status` 取值。
6. 不引入新的设置持久化，也不要求重启应用后保留状态筛选结果。
7. 不扩展思源设置本身的能力边界。

## 4. 已确认的产品决策

### 4.1 共享范围

状态筛选是 `PmPanel` 组件级共享状态：

1. 看板修改后，切到甘特图保持一致。
2. 甘特图修改后，切到看板保持一致。
3. 在 PM 面板内切换项目 / 总览时保持一致。
4. `PmPanel` 组件销毁后重新进入 PM，恢复默认全选。

### 4.2 入口位置

顶部工具栏第二行调整为：

1. 搜索
2. 类型
3. 优先级
4. 状态筛选
5. 思源设置

### 4.3 入口形态

状态筛选使用 `el-select multiple`。

交互约束：

1. 下拉面板中显示 4 个正式状态选项。
2. 允许多选、全不选。
3. 闭合态不显示已选标签，不显示已选状态文本，不显示 `2/4` 之类汇总。
4. 闭合态固定呈现单一入口名称，建议文案为 `状态筛选`。
5. 清空选择后保持真空数组，不自动回填。

## 5. UI 设计

### 5.1 顶部工具栏

顶部工具栏保留当前两行结构，不新增第三行。

第二行筛选区改动如下：

1. 在优先级和思源设置之间插入状态筛选控件。
2. 状态筛选宽度固定，不随选项内容增长。
3. 工具栏整体允许在窄宽度下换行，但不为状态筛选单独增加摘要文本。
4. 思源设置按钮保持原有入口与功能，不因状态筛选加入而改变行为。

### 5.2 看板视图

看板的数据来源改为共享状态筛选后的结果集合。

表现规则：

1. 未选中的状态列不渲染，不保留空壳列。
2. 已选中的状态列继续按现有列结构展示。
3. 列头计数基于当前共享筛选结果计算。
4. 当状态筛选为空，或筛选后无命中任务时，看板显示统一空结果态，不显示四列骨架。
5. 当前选中的详情项若被筛掉，不主动关闭详情面板。
6. 如果用户通过右键菜单、快捷推进或详情编辑把某个工作项改到未选中状态，该工作项应立即从当前看板结果集中消失；若它当前正处于详情打开状态，详情面板保持打开。

### 5.3 甘特图视图

甘特图继续显示时间粒度切换、排期统计和空态，但移除视图内部状态 chip。

表现规则：

1. 甘特图接收父层已经按共享状态筛好的 `items`。
2. 甘特工具栏只保留甘特自身能力：
   - 日 / 周 / 月视图切换
   - 排期数量统计
   - 未排期提示
3. 状态筛选入口不再出现在甘特图内部工具栏。
4. 当状态筛选为空时，甘特图直接进入空结果态。
5. “筛选后为空”和“有任务但都未排期”两类空态继续区分。
6. 如果用户通过右键菜单、快捷推进或详情编辑把某个工作项改到未选中状态，该工作项应立即从当前甘特结果集中消失；若它当前正处于详情打开状态，详情面板保持打开。

## 6. 数据流与组件边界

### 6.1 筛选分层

当前 `PmPanel.vue` 已有：

1. `baseFilteredItems`
2. `ganttFilteredItems`

本次应收敛为更清晰的三层：

1. `baseFilteredItems`
   - 只承接搜索、类型、优先级
2. `statusFilteredItems`
   - 在 `baseFilteredItems` 之上叠加共享状态筛选
   - 同时供看板和甘特消费
3. 视图派生层
   - 看板列数据、甘特任务数据都从 `statusFilteredItems` 继续派生

### 6.2 组件职责与接口收口

`PmPanel.vue` 负责：

1. 持有共享的 `selectedStatuses`
2. 渲染状态筛选控件
3. 计算 `statusFilteredItems`
4. 计算看板可见列集合
5. 向 `PmGanttView.vue` 传递已筛选的数据

`PmGanttView.vue` 负责：

1. 渲染甘特图
2. 处理时间粒度切换
3. 处理日期拖拽、选中、右键等既有交互
4. 不再持有或渲染状态筛选入口

`PmGanttView.vue` 的最终公开接口应收口为：

1. 保留：
   - `items`
   - `selectedItemId`
   - `showProjectMeta`
   - `view-change`
   - 既有选中 / 编辑 / 右键 / 日期改动 / 视口事件
2. 删除：
   - `selectedStatuses`
   - `toggle-status`
   - `select-all-statuses`
   - `clear-statuses`

也就是说，甘特图只消费父层已经筛好的任务集合，不再感知状态筛选源数据。

### 6.3 看板列集合

建议新增 `visibleStatusColumns` 一类计算值，规则如下：

1. 来源统一复用 `PM_STATUS_COLUMNS`
2. 仅保留出现在 `selectedStatuses` 中的列
3. 顺序保持 `PM_STATUS_COLUMNS` 原顺序
4. `columnItemsMap` 的数据源改为 `statusFilteredItems`
5. 对于未知状态工作项，在看板列归类时按 `todo` 列参与分组

这样“未选中的状态列直接隐藏”可以保持为模板层渲染规则，而不是在列内部堆叠额外判断。

### 6.4 共享状态工具函数

当前仓库已有 `pmGanttFilter.ts`。

本次设计要求把其中的“状态选择与状态归一”语义提升为 PM 共享工具层，不再由甘特命名主导。

建议收口为独立共享 util，例如：

1. `pmStatusFilter.ts`
   - 负责默认全选、切换、全选、清空、稳定顺序
   - 负责“未知状态按 `todo` 参与筛选”的归一逻辑
   - 负责看板列可见状态集合与归类状态值
2. 甘特相关日期 / 任务映射逻辑仍留在 `pmGantt.ts`

如果规划阶段最终决定沿用原文件名，也必须满足一个约束：

1. 共享状态筛选 helper 不能再以“仅供甘特使用”的方式设计或描述。

## 7. 状态值与兼容规则

状态定义继续复用：

1. `PmItemStatus`
2. `PM_STATUS_COLUMNS`
3. `pmGanttFilter.ts` 中已有的顺序归一逻辑

兼容约束：

1. 默认值仍为 4 个正式状态全选。
2. 对外暴露的选中结果仍使用稳定顺序数组。
3. 不允许重复值。
4. 未知状态在共享筛选和看板列归类时都按 `todo` 兜底。
5. 也就是说，未知状态工作项在：
   - 状态筛选命中判断中，视为 `todo`
   - 看板列分组中，进入 `todo` 列
6. 上述兜底只用于筛选参与性与列归类，不修改工作项原始状态值。
7. 详情展示、编辑表单、落库值继续保留原始 `status`，不发生静默改写。

## 8. 空态与行为边界

### 8.1 共享空选择

当 `selectedStatuses` 为空时：

1. 看板显示空结果态。
2. 甘特图显示空结果态。
3. 不自动恢复全选。
4. 用户必须通过再次选择状态恢复结果集。

### 8.2 看板空态

看板应统一处理以下两类情况：

1. `statusFilteredItems` 为空
2. `visibleStatusColumns` 为空

两种情况下都不渲染列骨架，直接显示统一空态，避免出现“空列墙”。

### 8.3 甘特空态

甘特图继续沿用现有两类空态：

1. 当前筛选结果没有可显示的工作项
2. 当前筛选结果中存在未排期项，无法显示甘特图

严格判定规则如下：

1. 当共享筛选结果总数为 `0` 时，进入“当前筛选结果没有可显示的工作项”。
2. 当共享筛选结果总数大于 `0`，且可排期任务数为 `0`，且未排期任务数大于 `0` 时，进入“当前筛选结果中有 X 项未设置日期，无法显示甘特图”。
3. 只要存在任一可排期任务，就不能进入“都未排期”空态。

差异仅在于数据源从甘特私有筛选结果改成共享筛选结果。

## 9. 测试与验证要求

至少覆盖以下验证面：

1. `pmGanttFilter.test.ts`
   - 默认全选
   - 单项切换
   - 全选
   - 清空
   - 稳定顺序
   - 未知状态兜底
2. 新增或补充 PM 纯函数测试
   - 共享状态筛选后的可见列集合
   - 空选择时看板无列
   - 只选部分状态时看板列集合正确
   - 未知状态工作项会进入 `todo` 列
3. 既有 PM 回归测试
   - `pmGantt.test.ts`
   - 如涉及日期派生，补跑 `pmDate.test.ts`
4. 集成验证
   - `pnpm typecheck`
   - `pnpm --filter @lazycat/desktop build:web`
5. UI 级验收
   - 顶部第二行控件顺序为：搜索 / 类型 / 优先级 / 状态筛选 / 思源设置
   - 状态筛选闭合态固定显示 `状态筛选`
   - 甘特图内部状态 chip 已移除
6. 甘特空态判定
   - 只有“可排期任务数为 0 且未排期任务数大于 0”时，才进入“都未排期”空态
   - 只要存在任一可排期任务，就必须正常渲染甘特条

## 10. 验收标准

1. PM 顶部工具栏第二行新增 `状态筛选` 多选下拉，位置在 `思源设置` 前。
2. 下拉面板支持多选和清空；闭合态不回显选中状态名称或数量。
3. 看板与甘特图共用同一套状态筛选结果。
4. 看板未选中的状态列直接隐藏，不保留空列壳子。
5. 当状态筛选为空时，看板和甘特都显示空结果，不自动恢复全选。
6. 甘特图内部原状态 chip 工具栏被移除，甘特只保留自身视图切换和统计信息。
7. 搜索、类型、优先级仍与状态筛选共同作用于最终结果集。
8. 未知状态条目在共享状态筛选链路中继续按 `todo` 参与归类，并在看板中进入 `todo` 列，不因未知值直接消失。
9. 在 PM 面板会话内切换看板 / 甘特、项目 / 总览时，当前状态筛选保持不变。
10. 不引入后端协议、数据库字段和用户设置持久化变更。
