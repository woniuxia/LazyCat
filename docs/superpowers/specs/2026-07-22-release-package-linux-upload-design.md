# 上线包 Linux 上传设计

## 目标与范围

在现有“上线包打包”工具中增加可选的 Linux 上传能力。用户可以继续“仅打包”，也可以选择“打包并上传”：构建开始前完成真实 SSH 预检，构建和本地归档成功后，通过 SFTP 上传本次选中的前端目录和后端文件。

首版支持：

- 用户名 + 密码认证。
- 用户名 + 私钥文件 + 可选私钥口令认证。
- 前端产物目录递归上传，不受本地 `copy_directory` / `zip_directory` 归档方式影响。
- 后端产物文件直接上传。
- 远端同名目标经用户确认后完整替换。
- 上传进度、取消、失败回滚和失败后的单独重试上传。

远程命令执行不在首版范围内。SSH 会话层保留执行命令的扩展边界，但不提前实现命令模板、sudo 或发布脚本。

## 已确认边界

- “仅打包”和“打包并上传”是两种独立启动方式；项目可保存默认选择，启动时仍可切换。
- 上传预检必须在构建前完成，避免打包结束后才发现连接、认证或权限问题。
- 本地归档方式与远程上传方式独立。前端本地即使归档为 ZIP，远端仍上传原始产物目录。
- 密码和私钥口令仅用于本次任务，不持久化、不进入日志和通知。
- 远端同名目标在构建前展示具体路径和影响，用户确认后才允许完整替换。
- 只有本次选中的目标全部构建成功才上传。现有“部分成功”本地归档保持不变，但不会自动部署部分产物。
- 上传失败保留已提交的本地归档，终态显示“打包成功、上传失败”，允许单独重试上传。

## 技术方案

采用 Rust `ssh2` crate，通过 SSH 建立 SFTP 会话。项目当前打包运行时使用阻塞后台线程，`ssh2` 与该模型匹配，并同时提供密码认证、私钥认证、主机公钥读取、SFTP 文件操作以及后续远程命令能力。

不采用系统 `ssh` / `scp`：Windows OpenSSH 环境不一致，密码认证难以安全地在非交互任务中传入，进度、取消和错误分类也会退化为命令行文本解析。不采用独立部署服务，因为会引入额外服务、账号和运维体系，超出当前单机工具范围。

依赖建议：

```toml
ssh2 = { version = "0.9", features = ["vendored-openssl"] }
```

最终特性名和与现有 vendored OpenSSL 的链接方式在实现前用 Windows `cargo check` 验证，以实际 crate 版本为准。

## 总体流程

```text
选择仅打包 / 打包并上传
              │
              ├─ 仅打包 ───────────────┐
              │                        │
              └─ 主机探测与信任确认     │
                 认证与远程预检         │
                 同名目标替换确认       │
                          │             │
                          ▼             ▼
                   前端/后端并行构建
                          │
                          ▼
                     本地归档提交
                          │
               ┌──────────┴──────────┐
               │                     │
          仅打包终态          上传远端临时路径
                                     │
                                     ▼
                              校验并提交远端目标
                                     │
                                     ▼
                                上传任务终态
```

上传是本地归档提交后的第三阶段，不混入前端或后端构建 lane，也不改变现有本地归档事务。

## 项目配置

在 `release_package_projects` 增加：

```sql
upload_enabled INTEGER NOT NULL DEFAULT 0,
ssh_host TEXT NOT NULL DEFAULT '',
ssh_port INTEGER NOT NULL DEFAULT 22,
ssh_username TEXT NOT NULL DEFAULT '',
ssh_auth_type TEXT NOT NULL DEFAULT 'password'
  CHECK (ssh_auth_type IN ('password', 'private_key')),
ssh_private_key_path TEXT NOT NULL DEFAULT '',
frontend_remote_dir TEXT NOT NULL DEFAULT '',
backend_remote_path TEXT NOT NULL DEFAULT ''
```

字段使用幂等迁移加入，保证已有项目可直接打开。`upload_enabled` 只控制启动确认框的默认选择，不强制每次上传。

数据库只保存服务器定位、认证类型、私钥路径和远程目标，不保存账户密码、私钥口令、私钥内容、预检令牌或上传临时路径。

## 主机信任

新增独立表，避免多个项目连接同一服务器时形成多份指纹真值：

```sql
CREATE TABLE IF NOT EXISTS release_package_known_hosts (
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  key_type TEXT NOT NULL,
  fingerprint_sha256 TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (host, port)
);
```

首次连接展示服务器主机密钥类型和 SHA-256 指纹，由用户确认后保存。后续指纹变化时直接阻止认证，用户必须对比旧、新指纹并显式“重新信任”。SSH 握手与指纹校验先于密码或私钥认证，避免向未信任主机发送凭据。

## 临时凭据与预检令牌

密码或私钥口令由启动确认框收集，经 IPC 发送到 Rust。Rust 用 `zeroize` 包装敏感字符串并保存在短期预检会话中：

- 令牌只能消费一次，默认五分钟过期。
- 令牌绑定项目 ID、服务器、端口、用户名、认证方式、本次目标和远程路径。
- 配置或目标变化后令牌失效。
- 启动、取消、失败、超时或应用退出时清除敏感值。
- 前端关闭确认框后清空输入，不把秘密放入持久状态。

正式任务只提交预检令牌，不再次携带密码。上传前后端会重新连接并再次核对主机指纹。

## 前端交互

项目编辑区新增折叠的“服务器上传”区域：

- 默认启用“打包并上传”。
- 服务器地址与 SSH 端口，端口默认 `22`。
- 用户名。
- 认证方式：密码 / 私钥。
- 私钥文件路径，仅私钥方式显示。
- 前端远程目录。
- 后端远程文件路径。

启动确认框流程：

1. 选择“仅打包”或“打包并上传”。
2. 选择本次前端、后端目标，显示本地归档路径。
3. 上传模式下显示服务器和远程目标。
4. 未知主机先展示指纹并确认信任。
5. 输入密码或私钥口令并执行真实预检。
6. 展示连接、认证、父目录、写权限和同名目标结果。
7. 同名目标逐项展示，并要求确认“完整替换以上目标”。
8. 预检成功且覆盖确认匹配后才能开始构建。

运行日志增加独立“上传”区域，展示相对文件路径、已传字节、总字节和整体百分比，不逐文件发送全局通知。

上传失败后提供“重试上传”。重试必须重新预检，但不重新构建；上传源固定为失败任务返回的本地归档和产物清单，不能读取可能已变化的工程产物。

## IPC 契约

沿现有 `invokeToolByChannel` 链路增加：

```text
tool:release-package:remote-probe
  -> release_package / remote_probe
tool:release-package:host-trust
  -> release_package / host_trust
tool:release-package:remote-preflight
  -> release_package / remote_preflight
tool:release-package:upload-retry
  -> release_package / upload_retry
```

`remote_probe` 只完成 SSH 握手和主机公钥读取，返回主机密钥类型、SHA-256 指纹、信任状态以及短期 `probeToken`。`host_trust` 只接受有效探测令牌，防止前端提交任意指纹；指纹变化时要求 `replaceExisting: true`。

`remote_preflight` 接收项目 ID、本次目标、认证秘密和受信任探测令牌。后端重新读取项目配置，再次握手和校验指纹，认证并检查远程目标，返回一次性 `preflightToken` 及每个目标的存在、父目录和写权限状态。

现有 `start` 增加：

```ts
interface ReleasePackageDeployStartInput {
  mode: "package_only" | "package_and_upload";
  preflightToken?: string;
  overwriteRemoteTargets?: Array<"frontend" | "backend">;
}
```

上传模式必须消费有效令牌。Rust 精确比较令牌中的远程存在状态与 `overwriteRemoteTargets`，不能只相信前端复选框。`upload_retry` 接收原运行的可重试描述符和新预检令牌，不复用 `start`，避免重新构建。

## 后端模块

### `release_package_remote.rs`

负责 TCP/SSH 连接、握手、主机指纹、密码或私钥认证、SFTP 文件操作、分块传输、进度、取消和稳定的脱敏错误映射。该模块不感知 Vue、项目数据库或整体任务状态。会话抽象保留后续命令执行能力，首版不暴露 `exec` action。

### `release_package_deploy.rs`

负责部署事务：读取本地产物清单、生成远程临时/备份路径、递归上传、校验文件数和大小、提交、回滚及安全清理。

### `release_package_runtime.rs`

负责消费预检令牌，串联并行构建、本地归档和上传，聚合终态并发送事件和通知。上传沿用现有后台任务线程；取消标记扩展到目录遍历和每个写入块。运行资源槽保存可关闭的 SSH/TCP 连接，取消时设置标记并关闭连接，使阻塞 IO 尽快返回。

## 远程预检

预检执行真实操作，而非只做字段校验：

- 校验地址、端口、用户名、认证方式和目标路径格式。
- TCP/SSH 连接、握手、主机指纹和认证。
- 检查目标父目录，验证缺失目录是否可创建。
- 在目标同级目录创建、重命名并删除探测文件，验证真实权限。
- 查询正式目标是否存在且类型正确。
- 检查本次临时路径和备份路径不存在；发现异常残留时阻止启动并明确报告，不自动删除。

远程路径必须是绝对 Linux 路径，拒绝空路径、根目录 `/`、`.`、`..` 路径段和 NUL。前端目标是目录，后端目标必须含最终文件名。首版不展开 `~`、环境变量或 shell 表达式，因为 SFTP 不经过 shell。

构建期间远端状态可能变化，因此上传前再次连接、校验指纹并检查目标。实际状态与用户确认不一致时，以“上传前状态已变化”失败，不自动扩大覆盖范围。

## 上传来源与校验

本地归档阶段生成部署产物清单，记录目标、绝对来源路径、类型、相对文件路径、文件数、每个文件大小和总字节数。远程前端上传来源始终是本次构建验证过的原始目录，不是本地 ZIP。

上传前重新核对清单；文件缺失、类型或大小变化时立即失败，防止构建后产物被外部进程修改。首版不计算内容哈希，以避免大型目录的额外完整 IO；上传完成后校验远程文件大小、总文件数和总字节数。

对于“重试上传”，来源必须位于已提交的本地归档中：`copy_directory` 直接使用归档目录；`zip_directory` 将已提交的 ZIP 安全解压到本次运行专用的本地临时目录，再递归上传。解压必须拒绝绝对路径和 `..` 路径逃逸，重试结束后只清理本次创建的临时目录。这样不额外持久化隐藏副本，也不读取可能已经变化的工程目录。

## 远端完整替换

每个目标在正式目标同级使用临时和备份路径：

```text
<target>.__lazycat_tmp_<runId>
<target>.__lazycat_backup_<runId>
```

流程：

1. 所有选中目标完整上传到各自临时路径。
2. 校验临时目标的文件数和大小。
3. 再次确认正式目标状态与用户确认一致。
4. 已有正式目标重命名为备份。
5. 临时目标重命名为正式目标。
6. 所有目标提交成功后删除备份。

前端目录和后端文件可能位于不同目录或挂载点，无法提供跨目标真正原子事务。因此定义为“分别原子提交、统一编排、失败尽力回滚”：

- 任一提交失败后停止后续提交。
- 已提交目标先移走新目标，再恢复旧备份。
- 仅完成备份的目标直接恢复备份。
- 回滚失败时明确报告正式、临时和备份路径，保留可人工恢复的唯一副本，不显示伪成功。
- 只清理本次 `runId` 创建且已确认安全的路径，不使用通配符。

若服务器不支持所需重命名语义，预检提前失败；首版不降级为直接覆盖线上目录。

## 状态与取消

事件阶段增加 `upload`。整体状态增加：

```ts
"prechecking";
"uploading";
"package_succeeded_upload_failed";
```

其他现有状态保持兼容。`package_succeeded_upload_failed` 携带本地 `archivePath`、脱敏上传错误和可重试描述符。

取消语义：

- 本地归档提交前取消：整体 `cancelled`，不产生可用归档。
- 本地归档成功、远端提交前取消：保留本地归档，整体 `cancelled`，说明远端未更新。
- 远端提交完成后的迟到取消：沿用现有终态认领锁，由成功终态胜出。

上传取消后清理安全的临时路径并保留原线上版本。清理或回滚失败必须显式报告残留位置。

## 安全与错误处理

- TCP 连接、SSH 握手、认证和 SFTP 操作均设置有限超时。
- 密码、私钥口令和私钥内容永不进入日志、通知或格式化错误。
- 私钥仅由 Rust 侧读取，必须是常规文件；内容不返回前端。
- 不自动接受未知主机，不提供“忽略指纹”。
- 远程路径不经 shell 拼接，首版文件操作全部走 SFTP。
- 底层错误映射为连接失败、主机不可信、认证失败、权限不足、路径冲突、传输中断、提交失败或回滚失败。
- 上传失败不删除本地归档，也不降级为整体成功。

## 测试与验证

Rust 单元测试覆盖：配置迁移、路径校验、指纹信任、令牌单次消费与过期、敏感值清除、产物清单、分块取消、替换各失败点及回滚。

真实协议测试使用本地受控 SSH 服务或专用测试容器，覆盖密码认证、带/不带口令私钥、未知主机、指纹变化、无权限、递归目录、空目录、大文件、中途断连、重命名和取消。测试不得连接生产服务器；环境不可用时明确报告未执行，不能用 mock 冒充真实协议验证。

前端与契约测试覆盖：表单切换、秘密输入清理、主机信任、预检门禁、冲突确认、上传进度、失败终态、迟到事件以及重试不触发构建。

最低验证：

```text
cargo test release_package -- --nocapture
pnpm test -- <上线包相关测试>
pnpm typecheck
pnpm --filter @lazycat/desktop build:web
git diff --check
```

实现涉及真实 SSH 后，补充本地测试服务器的密码、私钥、取消和替换最小冒烟。
