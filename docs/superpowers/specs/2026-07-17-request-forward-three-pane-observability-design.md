# 请求转发三栏观测工作台设计

## 概述

请求转发当前使用“左侧规则列表 + 右侧配置/运行观测 Tab”。虽然上一轮已经收紧间距并实现日志自动刷新，但日志仍按纵向卡片展示，规则配置仍占据右侧工作台的一种主视图。日常排障时，用户需要在日志摘要和展开详情之间反复滚动，首屏可浏览记录数量有限。

本次将页面重组为日志优先的三栏工作台：左侧规则导航、中间高密度日志表、右侧详情检查器。规则配置退出主页面，统一改为弹窗；左键规则切换观测对象，右键规则进入编辑，新建规则也打开同一配置弹窗。改动限于前端布局、交互编排、用户偏好和相关测试，不修改后端请求转发 IPC、日志模型或数据库结构。

## 目标

1. 提高日志首屏密度，使用户可以连续扫描结果、请求、端点、流量、耗时和时间。
2. 让规则切换、运行控制、日志浏览和单条详情同时可达，减少页面内往返。
3. 新建与编辑复用同一配置弹窗，保持现有校验、只读、保存和启停语义。
4. 右侧详情检查器支持拖拽调整宽度并跨会话记忆。
5. 保持现有日志自动刷新、连续分页、请求意图保护和错误处理行为。
6. 窄窗口下优先保证日志主区可用，详情切换为覆盖式抽屉。

## 非目标

1. 不增加跨规则日志查询、日志导出、列自定义或虚拟滚动。
2. 不改变日志排序、筛选参数、分页协议、保留上限或自动刷新周期。
3. 不改变规则 CRUD、启停、统计重置或日志清理的后端合约。
4. 不增加新的数据库表、迁移或外部 UI 依赖。
5. 不重做应用全局主题或 Element Plus 全局覆盖。

## 页面结构

桌面宽度下使用三栏结构：

    request-forward-panel
    ├── rule-navigation
    │   ├── header（标题、新建）
    │   ├── search
    │   ├── batch-actions（全部启动、全部停止、计数）
    │   └── compact-rule-list
    ├── log-workspace
    │   ├── active-rule-toolbar（名称、状态、启动/停止、更多）
    │   ├── metrics-strip（事件、上传、下载、错误）
    │   ├── log-filter-toolbar（关键词、结果筛选、观测操作）
    │   └── dense-log-table
    ├── inspector-resizer
    └── log-inspector
        ├── summary
        ├── request-details（仅 HTTP）
        ├── response-details（仅 HTTP）
        └── connection-summary（TCP / UDP）

### 左侧规则导航

1. 宽度约 220px，保持固定、紧凑且可滚动。
2. 规则由卡片改为列表行，单行展示名称和运行状态，次行展示协议与端点摘要。
3. 左键规则行只负责选择规则并切换中间日志上下文。
4. 行内保留启动或停止快捷按钮。
5. 右键规则行打开上下文菜单，首版包含“编辑”和“删除”；删除仍使用现有二次确认。
6. “新建规则”打开空白配置弹窗。
7. 批量启动、批量停止、搜索和结果计数保持现有能力。

### 中间日志工作区

1. 移除“规则配置 / 运行观测”Tab，页面默认即为运行观测。
2. 当前规则工具条压成单行，展示名称、运行状态、失败原因和运行控制。
3. 四项统计从独立卡片改为无嵌套的横向指标条。
4. 日志筛选栏固定在表格上方，保留关键词及全部/成功/失败筛选。
5. 日志从卡片改为高密度表格，默认列为结果、请求或协议、客户端、目标、上传、下载、耗时、时间。
6. 行高保持在可读和可点击的紧凑基线，不通过缩小正文到不可读尺寸换取密度。
7. 单击日志行设置当前详情；选中态同时使用背景、边框或指示线，不只依赖颜色。
8. 加载更多继续使用现有 offset 分页；本次不引入无限滚动或虚拟列表。

### 右侧详情检查器

1. 默认宽度 420px，桌面模式允许拖拽调整。
2. 最小宽度 320px；最大宽度为当前三栏内容区可用宽度的 50%。
3. 拖拽过程中只更新本地布局状态，拖拽结束后持久化，避免高频写设置。
4. HTTP 日志展示概要、已脱敏请求头、已脱敏响应头、请求体预览和响应体预览。
5. TCP / UDP 日志只展示连接或数据报摘要，不展示不存在的 payload 详情。
6. 未选中日志时显示轻量空态，不用装饰性卡片占据空间。
7. 后台刷新后按日志 id 保持选中；若当前日志已不在连续分页窗口中，则关闭详情并回到空态。

## 配置弹窗

新建与编辑复用同一弹窗和现有 RequestForwardRuleForm：

1. 新建时使用默认表单值，标题为“新建转发规则”。
2. 右键“编辑”时加载目标规则，标题为“编辑转发规则”。
3. 运行中、启动中或停止中的规则继续保持只读，并保留“停止并编辑”操作。
4. 新建与编辑均保留“仅保存”和“保存并启动”。
5. 编辑状态保留删除入口及现有二次确认；新建状态不显示删除。
6. 保存成功后关闭弹窗、刷新规则与状态，并保持用户当前选择意图；新建成功后选择新规则。
7. 校验错误继续在表单字段旁显式展示，不因弹窗关闭而伪装为成功。
8. 弹窗关闭时，如果表单已修改，使用现有项目模式确认是否放弃修改。

## 详情宽度持久化

使用现有 user_settings，不新增后端通道或数据库迁移。设置键为 request-forward:inspector-width。

1. 初次进入使用 420。
2. 读取设置后先验证为有限数字，再按当前可用宽度限制到合法区间。
3. 窗口尺寸变化时只限制当前渲染宽度，不覆盖用户保存的首选宽度；窗口恢复后仍可回到用户首选值。
4. 拖拽结束时保存新的首选宽度。
5. 宽度限制与恢复逻辑抽到 requestForward.ts 纯函数，并覆盖非法值、最小值、最大值和窗口变窄场景。
6. 分隔条具备明确的 col-resize 光标、悬停和焦点样式，并支持键盘左右方向键微调；键盘调整结束后同样持久化。

## 响应式行为

1. 宽窗口使用三栏结构。
2. 当可用宽度不足以同时容纳规则导航、可读日志区和最小检查器宽度时，检查器切换为覆盖式右侧抽屉。
3. 抽屉模式不读取或覆盖桌面检查器宽度，只共享当前选中日志。
4. 更窄窗口下左侧规则导航沿用现有上下分区策略，日志表按优先级隐藏低价值列，但保留结果、请求、耗时和时间。
5. 任何宽度下都不能产生页面级横向滚动、文本重叠或操作按钮挤出容器。

## 状态与数据流

### 规则选择

1. 左键规则时更新选择意图，清空上一条日志详情，并加载新规则的统计和日志。
2. 右键规则只打开上下文菜单，不改变当前选择；编辑弹窗绑定被右键的目标规则，不能误用当前选择。
3. 编辑、删除、启停和批量操作继续使用既有 mutation intent，晚响应不能覆盖用户后来选择的规则。

### 日志选择与刷新

1. 维护 selectedLogId，详情由当前 logItems 中相同 ID 的记录派生。
2. 手动筛选、切换规则、清空日志时清除 selectedLogId。
3. 后台刷新替换连续日志窗口后，如果仍包含所选 ID，则详情保持；否则关闭详情。
4. 日志行选中不发起新的后端请求，详情使用列表中已返回的完整日志数据。
5. 现有串行轮询、单个待刷新意图、筛选快照和日志请求 token 保持不变。

## 错误与边界状态

1. 首次日志加载失败继续显示可重试错误态。
2. 后台刷新失败保留当前日志和详情，并显示非阻塞警告。
3. 统计加载失败只影响指标条，不隐藏可用日志。
4. 配置弹窗保存失败保持打开并显示错误，不刷新成伪成功状态。
5. 设置读取或写入失败不阻断日志浏览；读取失败显式使用本次会话默认宽度，写入失败保留当前宽度并复用现有错误呈现方式。
6. 无规则、无日志、无选中日志、规则运行失败和观测数据不可用均使用独立空态或警告，不能互相冒充。

## 测试策略

按 TDD 顺序先补失败测试，再实现最小改动：

1. 纯函数测试覆盖检查器默认宽度、非法设置、上下界限制和窗口收窄。
2. 组件结构测试确认旧 Tab 与内嵌配置区移除，三栏、配置弹窗、上下文菜单和检查器存在。
3. 交互测试覆盖左键切换规则并清空日志选择、右键不改变当前规则且编辑目标正确、新建与编辑打开同一配置弹窗、行内启动/停止仍可用、日志刷新按 ID 保持或清除详情、拖拽结束才写入设置且恢复时正确限制。
4. 现有轮询、分页、错误和 mutation intent 测试必须继续通过。

## 视觉与可访问性检查

通过本地预览或应用界面检查至少 768px、1024px、1440px 宽度：

1. 三栏无重叠，日志主区有稳定最小宽度。
2. 默认 420px 检查器可以读取常见请求头和正文预览。
3. 拖拽分隔条的光标、悬停、焦点和键盘调整可辨认。
4. 表格行 hover、选中、成功、失败和焦点状态清晰。
5. 右键菜单关闭后再打开弹窗，不触发递归更新或焦点残留。
6. 配置弹窗覆盖新建、编辑、运行只读、校验错误和保存失败状态。
7. 窄窗口抽屉不会遮挡无法恢复，也不会覆盖桌面宽度偏好。
8. 浅色主题、空态、错误态和弹窗态保持足够对比度。

## 风险与取舍

1. 三栏会压缩日志主区，因此检查器必须有响应式抽屉降级和最大宽度限制。
2. 右键入口对新用户不够显眼，因此规则行保留明确的运行控制，并在右键菜单之外保留可访问的“更多”按钮触发同一菜单。
3. 配置迁入弹窗后不再与日志并排，但配置与观测属于不同任务；弹窗可减少低频表单对常驻工作区的占用。
4. 本次不做跨规则日志，避免为全宽日志台扩大后端查询和状态模型。
