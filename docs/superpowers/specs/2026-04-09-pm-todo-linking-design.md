# 项目管理与任务清单衔接设计

- 日期：2026-04-09
- 范围：`项目管理 > 工作项详情`、`任务清单 > 事项详情/编辑`、`pm/todo` 后端关联接口与数据模型
- 状态：已通过评审，可进入实施

## 1. 背景

当前仓库中，项目管理与任务清单之间只有“项目级”的弱关联：

1. `TodoItem` 已带 `projectId / projectName / projectColor`，说明任务清单事项目前只能归属到项目，不支持归属到项目中的具体工作项：`apps/desktop/src/types/todo.ts`
2. `PmItem` 目前没有关联 Todo 的字段，项目管理工作项仍是独立模型：`apps/desktop/src/types/pm.ts`
3. 数据库里 `todo_items` 有 `project_id`，但没有 `pm_item_id` 或专门的关系表；`pm_items` 也没有对应 Todo 关联字段：`apps/desktop/src-tauri/src/tools/helpers.rs`
4. 删除项目时，后端会检查 `todo_items WHERE project_id = ?1`，进一步说明当前关联粒度只到项目，不到 PM 工作项：`apps/desktop/src-tauri/src/tools/pm.rs`

这导致两个模块虽然都服务于“做事”，但心智分层仍然松散：

- PM 更像目标/规划层
- Todo 更像执行层
- 但系统里缺少“一个 PM 工作项可以拆成多个执行 Todo”的正式模型

## 2. 本轮目标与非目标

### 2.1 本轮目标

1. 明确建立 `1 个 PM 工作项 -> 多个 Todo` 的产品关系。
2. 允许一个 Todo 最多只归属 1 个 PM 工作项，避免执行项语义歧义。
3. 在 PM 工作项详情中，提供内嵌的“执行任务”管理区，作为主入口。
4. 同时支持两种建联方式：
   - 在 PM 内直接新建 Todo
   - 在 PM 内绑定已有 Todo
5. 允许绑定“未归项目”的 Todo，并在绑定时自动补齐为当前 PM 所属项目。
6. 在 Todo 侧展示反向归属信息，并支持在同项目内改挂或清除所属 PM 工作项。
7. 明确 PM 与 Todo 之间的双向跳转机制，做到“切换模块并定位对象”。
8. 保持“弱同步”原则：PM 状态仍手动维护，但可展示 Todo 聚合进度并提供辅助推进。

### 2.2 非目标

1. 不在本轮支持一个 Todo 同时关联多个 PM 工作项。
2. 不在本轮实现复杂的关系类型系统（如主执行项、参考项、阻塞项等）。
3. 不在本轮根据 Todo 状态自动强制推导 PM 状态。
4. 不在本轮根据 PM 时间自动覆盖 Todo 时间。
5. 不在本轮实现 PM 详情内的完整 Todo 编辑表单嵌入，只提供轻量操作。
6. 不在本轮引入 AI 自动拆解、自动生成子任务或复杂依赖图。
7. 不在本轮改变现有项目管理与任务清单的主状态模型。
8. 不在本轮支持重复/周期 Todo 与 PM 工作项建联。
9. 不在本轮支持“跨项目原子改挂”，即不实现“改项目时同时自动换到目标项目的另一条 PM 工作项”。

## 3. 已确认的产品决策

1. 主从关系：`PM 为主，Todo 为执行层`。
2. 状态联动：选择“弱同步”，PM 保留手动状态，只展示 Todo 完成进度并提供辅助动作。
3. 关联基数：一个 Todo 只能属于一个 PM 工作项。
4. 建联入口：同时支持“在 PM 内新建 Todo”和“在 PM 内绑定已有 Todo”。
5. PM 内呈现：在 PM 工作项详情中以内嵌区块管理关联 Todo。
6. “执行任务”区块位置：放在 PM 工作项详情的“描述”下面。
7. 绑定已有 Todo 的候选范围：除当前项目下的 Todo 外，还允许绑定“未指定项目”的 Todo。
8. 当前轮关系实现方案：采用关系表，而不是直接在 `todo_items` 上新增 `pm_item_id` 字段。
9. Todo 侧首版能力边界：支持查看、改挂与清除所属 PM 工作项。
10. 重复/周期 Todo 首版不参与 PM 关联，只允许普通一次性 Todo 建联。

## 4. 数据模型设计

### 4.1 关系表方案

新增关系表：`pm_item_todo_links`

建议字段：

- `id`
- `pm_item_id`
- `todo_item_id`
- `created_at`
- `updated_at`

第一版不增加 `link_type`、`sort_order` 等保留字段，避免把一个简单的一对多执行关系提前做重。

### 4.2 关系约束

第一版虽然采用关系表，但业务规则仍保持简单：

1. 一个 PM 工作项可以关联多个 Todo。
2. 一个 Todo 最多只能关联一个 PM 工作项。
3. Todo 与 PM 工作项必须属于同一个项目。
4. 删除 PM 工作项时，只删除关系记录，不删除 Todo。
5. 删除 Todo 时，自动清理关系记录。
6. 一旦 Todo 已有关联，修改项目归属时必须通过统一校验，不允许产生跨项目脏数据。
7. 只有普通一次性 Todo 才允许出现在关系表中。

数据库层建议保证：

1. `todo_item_id` 唯一，确保“一个 Todo 最多只挂一个 PM 工作项”。
2. `pm_item_id` 建普通索引，便于按 PM 工作项拉取 Todo 列表。
3. `pm_item_id` / `todo_item_id` 均建立外键：
   - 删 PM 工作项 -> 关系记录删除
   - 删 Todo -> 关系记录删除

### 4.3 与现有 `project_id` 的关系

`todo_items.project_id` 继续保留，不删除。

两层语义分别是：

- `project_id`：Todo 属于哪个项目
- `pm_item_todo_links`：Todo 对应项目里的哪个 PM 工作项

这样可以支持：

1. Todo 只归属项目，不挂具体 PM 工作项。
2. Todo 一旦挂到 PM 工作项，就必须保证两边 `project_id` 一致。
3. “未归项目”的 Todo 在绑定时自动补齐项目归属，而不是事先强制要求用户先去 Todo 面板手动改项目。

### 4.4 SQLite 升级与兼容策略

当前仓库使用 `apps/desktop/src-tauri/src/tools/helpers.rs` 中的内联 schema 初始化/增量扩展模式，因此本轮不新增独立 migration 文件，而是在现有 schema 初始化链路中追加新表与索引。

升级策略：

1. 在 `todo_items` 与 `pm_items` 已存在的前提下，新增 `pm_item_todo_links` 的 `CREATE TABLE IF NOT EXISTS` 语句。
2. 紧随其后追加唯一索引与普通索引创建语句，同样使用幂等方式执行。
3. 首次升级旧库时只做增量建表/建索引，不做历史关系回填，因为旧版本不存在正式的 PM-Todo 工作项级关系。
4. 新表初始为空；现有 PM / Todo 数据保持原状，不应因升级被重写。
5. 因为新表为空，所以不存在历史 orphan link 需要清洗；后续新增数据由外键和唯一约束负责约束。

失败边界：

1. 若本次 schema 初始化在新表或索引阶段失败，不视为升级完成。
2. 下一次启动继续重复执行同一批幂等 SQL，直到新表与索引完整可用。
3. 只有 schema 初始化成功后，前端才开放 PM-Todo 关联能力；不允许在缺表状态下进入半可用功能。

## 5. 交互设计

### 5.1 PM 侧主入口

主入口放在 `PmPanel.vue` 的工作项详情面板中，位置在“描述”下面、“资源关联”上面。

新增区块：`执行任务`

结构建议：

1. 区块头
   - 标题：`执行任务`
   - 副标题：`当前工作项拆解出的任务清单事项`
2. 摘要区
   - `已关联 X 项`
   - `已完成 Y / X`
   - 轻量进度条
   - 全部完成时可显示弱提示
3. 操作区
   - `新建执行任务`
   - `绑定已有任务`
   - 可选：`在任务清单查看全部`
4. 列表区
   - 标题
   - 状态
   - 优先级
   - 时间信息
   - 逾期标记
   - 快捷动作：打开 / 完成 / 解绑

其中“摘要区”属于第一版主链路的一部分，不后移到后续阶段。只要 PM 详情已展示执行任务列表，就必须同步展示与该列表同源的聚合统计，避免列表与进度感知脱节。
### 5.2 在 PM 内新建 Todo

在“执行任务”区点击 `新建执行任务` 后：

1. 打开 Todo 创建态。
2. 自动带入当前 PM 工作项的上下文。
3. 新建成功后自动建立 PM-Todo 关联。
4. 创建完成后刷新当前 PM 工作项详情中的执行任务列表与摘要。

默认行为：

- Todo 自动写入当前 PM 所属 `projectId`
- Todo 与当前 PM 工作项建立关系
- Todo 默认创建为普通一次性事项，不允许在这条创建路径上切成重复/周期事项
- Todo 表单中的项目字段保持锁定，只展示当前项目，不允许在 PM 内新建路径中切换到其他项目

若用户确实要创建到其他项目，应取消本次创建，改从目标项目的 PM 工作项内发起，或改在 Todo 面板中单独创建。

后端收口方式：

1. 首版不采用“先创建 Todo，再由前端调用第二个接口建联”的两次请求方案。
2. 新增一个 PM 侧原子接口，例如 `tool:pm:item-todo-create`。
3. 该接口在一次事务内完成：
   - 校验 `pmItemId` 存在且可用
   - 校验当前 PM 所属项目
   - 创建普通一次性 Todo
   - 写入 Todo 的 `projectId`
   - 写入 `pm_item_todo_links`
   - 返回新建后的 Todo 记录
4. 前端的 PM 内“新建执行任务”表单只负责收集 Todo 基础字段，提交时统一走这个 PM 原子接口。

这样可以保证主链路满足“创建 Todo + 建立关系”一次成功或一次失败，不产生半成功状态。
### 5.3 在 PM 内绑定已有 Todo

在“执行任务”区点击 `绑定已有任务` 后，打开轻量选择器。

候选范围：

1. 当前项目下、尚未绑定 PM 工作项的普通一次性 Todo
2. `projectId = null`、尚未绑定 PM 工作项的普通一次性 Todo

禁止进入候选范围：

1. 已绑定其他 PM 工作项的 Todo
2. 已属于其他项目的 Todo
3. 重复/周期 Todo
4. 重复系列派生出来的实例 Todo

候选查询接口：

- 新增 `tool:pm:item-todo-candidates`
- 输入：
  - `pmItemId`
  - `keyword?: string`
  - `statuses?: TodoStatus[]`
  - `limit?: number`
- 输出：
  - `items: CandidateTodoItem[]`
  - `total: number`

`CandidateTodoItem` 最小返回字段：

- `id`
- `title`
- `status`
- `priority`
- `eventAt`
- `projectId`
- `projectName`
- `isUnassignedProject`（布尔值，便于前端标注“未归项目”）

候选列表规则：

1. 默认按“未完成优先、最近时间优先”排序。
2. 首版不做分页翻页交互，仅保留 `limit` 作为结果上限保护；若超出上限，前端提示继续缩小搜索范围。
3. 空结果区分为：
   - 当前筛选下没有可绑定任务
   - 存在任务，但都已被其他 PM 占用或属于其他项目

为支持上述空态区分，接口额外返回：

- `eligibleCount`: 当前项目 + 未归项目中符合基础条件且未被占用的数量
- `blockedCount`: 因已被其他 PM 占用或项目不一致而不可绑定的数量
- `reason`: `empty` | `filtered_empty` | `blocked_only`

交互建议：

- 支持标题搜索
- 支持状态筛选
- 支持多选
- 对“未归项目”的 Todo 显示额外提示标记
- 弹窗中明确说明：`可绑定当前项目或未归项目的任务`

绑定结果：

1. 若 Todo 已属于当前项目：直接建关系。
2. 若 Todo 未归项目：允许绑定，并在同一事务中自动补齐为当前 PM 所属项目。
3. 若 Todo 属于其他项目：绑定失败，并给出明确提示。

批量绑定策略：

1. 多选绑定采用“全有或全无”的单事务策略。
2. 只要选中集里有任意一条在提交时变成非法（被删除、已被其他 PM 绑定、项目不一致、不是普通一次性 Todo），整批绑定全部回滚。
3. 前端收到失败后，提示失败原因并刷新候选列表，不做部分成功、部分失败的静默处理。
### 5.4 Todo 侧反向呈现与改挂

在 Todo 面板中，PM 关联能力统一落在“事项详情右侧详情区”的现有字段区，不放进独立弹窗，也不要求在列表卡片上直接编辑。

展示与编辑顺序：

1. 先显示“所属项目”字段
2. 再显示“所属 PM 工作项”字段
3. 只有在项目上下文已稳定后，才允许编辑 PM 归属

展示规则：

1. 未关联：显示“未关联项目任务”
2. 已关联：显示 PM 工作项标题，并支持点击跳转到 PM

支持能力：

- 选择所属 PM 工作项
- 同项目内改挂到另一条 PM 工作项
- 清除当前 PM 关联
- 跳转查看当前 PM 工作项

候选 PM 范围：

1. 若 Todo 已有 `projectId`：只允许选择同项目下的 PM 工作项。
2. 若 Todo 没有 `projectId`：Todo 侧 PM 选择器禁用，并提示“请先选择项目，或从项目管理工作项内绑定该任务”。
3. 不允许在 Todo 侧直接跨项目选 PM；若要换项目，必须先处理项目归属。

与“所属项目”字段的联动规则：

1. 若当前 Todo 已关联 PM 工作项，则“所属项目”字段进入只读锁定态，不允许直接改项目。
2. 若用户要改项目，必须先清除当前 PM 关联。
3. 清除关联后，“所属项目”字段恢复可编辑；项目改动完成后，才可重新选择目标项目下的 PM 工作项。
4. Todo 侧不提供“改项目并同时自动重挂”的复合动作。

重复/周期限制：

1. 如果当前 Todo 是重复/周期事项，或属于重复系列实例，则不展示可编辑的 PM 选择器。
2. 可展示只读提示：`重复事项暂不支持关联项目工作项`。

改挂语义：

1. 改挂只允许在同项目内进行。
2. 改挂不会改变 Todo 自身 `projectId`。
3. 清除关联只删关系，不自动清空 `projectId`。

Todo 侧仍然是弱入口，主要批量管理动作放在 PM 侧。
### 5.5 双向跳转

为增强真正的”衔接感”，需要支持双向定位：

1. PM -> Todo
   - 在 PM 详情执行任务列表中点击某条 Todo
   - 打开任务清单并定位到对应事项
2. Todo -> PM
   - 在 Todo 详情中点击所属 PM 工作项
   - 打开项目管理并定位到该工作项详情

目标不是只做到”切换模块”，而是做到”切换后能定位到对象”。

定位优先级规则：

1. 以”目标对象可见并被选中”为最高优先级。
2. 若当前面板存在会阻止目标对象出现的过滤条件，跳转时允许临时覆盖这些过滤条件。
3. 覆盖仅限本次导航必要范围，不额外清空无关字段。

具体过滤覆盖规则与技术落地实现详见 7.4。

失败兜底：

1. 若目标对象已不存在，提示”目标事项不存在或已被删除”。
2. 若目标对象存在但无法通过当前数据集定位，先触发一次刷新；刷新后仍失败，再提示错误，不保留半选中状态。
## 6. 联动规则与边界行为

### 6.1 状态联动

本轮选择“弱同步”。

规则如下：

1. PM 工作项状态仍然由用户手动维护。
2. PM 工作项详情中展示关联 Todo 的聚合进度。
3. 当全部关联 Todo 完成时：
   - 显示提示
   - 第一版不提供“一键标记 PM 为已完成”按钮，只保留状态提示
4. 当仍存在未完成 Todo 时：
   - 允许用户手动将 PM 标记为完成
   - 但给出轻量提醒，说明仍有执行任务未完成

第一版明确不做：

- Todo 状态自动强制推导 PM 状态
- PM 状态变更自动批量改 Todo 状态

### 6.2 解绑规则

解绑只移除 PM-Todo 关系，不删除 Todo 本身。

解绑后：

1. Todo 继续保留在任务清单中。
2. `projectId` 默认保留，不自动清空。
3. PM 详情中的关联列表与统计立即刷新。

原因：

- “项目归属”和“具体 PM 工作项归属”是两层关系
- 一个 Todo 从某条 PM 工作项解绑后，通常仍然属于这个项目

### 6.3 删除规则

#### 删除 PM 工作项

1. 删除关系记录
2. Todo 保留
3. Todo 仍保留原项目归属

#### 删除 Todo

1. 自动删除关系记录
2. PM 详情中的统计和列表自动刷新

### 6.4 项目变更规则

为防止出现跨项目脏数据，本轮采用严格阻断策略，不实现“跨项目原子改挂”。

#### Todo 改项目

若该 Todo 已关联 PM 工作项：

1. 不允许直接改成其他项目。
2. 用户必须先清除当前 PM 关联。
3. 清除后，才允许修改 Todo 的 `projectId`。
4. 修改项目后，如仍需关联 PM，必须重新选择目标项目下的 PM 工作项。

#### PM 工作项改项目

若该 PM 工作项已有 Todo 关联：

1. 不允许直接改到其他项目。
2. 用户必须先处理掉该 PM 工作项下的所有 Todo 关联。
3. 处理完成后，才允许移动该 PM 工作项。

### 6.5 重复/周期 Todo 语义

本轮明确：重复/周期 Todo 不参与 PM 关联。

具体规则：

1. 只有普通一次性 Todo 可以建联。
2. PM 内新建执行任务时，默认且只允许创建普通一次性 Todo。
3. PM 内“绑定已有任务”候选列表中过滤掉重复/周期 Todo 与其派生实例。
4. Todo 侧若当前事项属于重复/周期模型，则不提供可编辑的 PM 选择器。
5. 后端接口在写入关系时再次校验，防止前端漏拦截。
6. 若某条已关联的普通一次性 Todo 在后续编辑中尝试切换为重复/周期事项，后端必须阻止此次类型变更，并提示“已关联项目工作项的任务不能改为重复事项，请先解除关联”。

### 6.6 完成态可见性

即便 Todo 已完成，也继续在 PM 详情中的“执行任务”列表中可见。

原因：

1. PM 需要看到执行闭环
2. 如果自动隐藏，进度摘要与列表长度会失去一致性

可选提供轻量筛选：

- 默认显示全部
- 可切换“仅看未完成”

但这属于易用性增强，不作为第一版主链路前提。

### 7.2 建议新增通道

在 `pm` 域新增：

- `tool:pm:item-todo-list`
  - 输入：`pmItemId`
  - 输出：关联 Todo 列表 + `totalCount / completedCount / pendingCount`
- `tool:pm:item-todo-link`
  - 输入：`pmItemId`, `todoItemIds: number[]`
  - 语义：批量绑定，单事务全成功或全失败
- `tool:pm:item-todo-unlink`
  - 输入：`pmItemId`, `todoItemId`
- `tool:pm:item-todo-create`
  - 输入：
    - `pmItemId`
    - `title`
    - `description`
    - `priority`
    - `assigneeIds`
    - `eventAt?`
    - `reminderPresets?`
  - 语义：在一次事务内完成”创建普通一次性 Todo + 写入 projectId + 建立 PM 关系”
  - 字段边界：
    - 只收集首版真正必要的执行信息，不在 PM 内暴露分类、重复规则、链接等扩展字段
    - `status` 固定按 Todo 默认创建态处理，不允许在 PM 新建时手动指定
- `tool:pm:item-todo-candidates`
  - 输入：`pmItemId`, `keyword?: string`, `statuses?: TodoStatus[]`, `limit?: number`
  - 输出：`items: CandidateTodoItem[]`, `total: number`, `eligibleCount`, `blockedCount`, `reason`
  - 语义：返回当前项目下 + 未归项目中可供 PM 绑定的候选 Todo 列表，详见 5.3

在 `todo` 域新增：

- `tool:todo:pm-candidates`
  - 输入：`projectId`
  - 输出：`items: PmCandidateItem[]`
  - 语义：返回当前项目下可供 Todo 选择/改挂的 PM 工作项轻量列表
  - `PmCandidateItem` 最小字段：`id`, `title`, `status`, `priority`, `projectId`, `projectName`
- `tool:todo:item-set-pm-link`
  - 输入：`todoItemId`, `pmItemId | null`
  - 语义：
    - `pmItemId = 某值`：设置或改挂到同项目 PM 工作项
    - `pmItemId = null`：清除 PM 关联
  - 校验：只允许普通一次性 Todo 调用，且若设置目标 PM，则必须与 Todo 同项目

同时在 `todo:item-list` / 详情返回中补充 PM 关联只读字段，避免 Todo 面板为展示关系再发第二次查询。
### 7.3 `TodoItem` 返回字段建议

建议在 `TodoItem` 中补充只读字段：

- `pmItemId?: number | null`
- `pmItemTitle?: string | null`
- `pmItemProjectId?: number | null`

这样 Todo 端可以直接渲染所属 PM 工作项，不必额外发第二次查询。

### 7.4 跨工具跳转机制

当前应用没有 `vue-router`，因此本轮不走路由参数，而是采用“打开目标 tab + 传递一次性导航负载”的模式。

建议做法：

1. 复用现有跨工具草稿传递思路，但把 `useClipboardSuggestion.ts` 中与剪贴板无关的 `pendingInput` 能力抽成独立的轻量 composable，例如 `useToolNavigation.ts`。
2. `useToolNavigation.ts` 负责：
   - 持有模块级单例的待消费导航负载
   - 提供 `openToolWithPayload(toolId, payload)`
   - 提供目标面板侧的 `watchToolPayload(toolId, apply)`
3. 打开目标工具仍继续复用 `useTabs().openTab()`，不新增全局 store、事件总线或路由系统。

推荐负载结构：

- PM -> Todo：
  - `toolId: "todo"`
  - `payload: { mode: "detail", itemId: number }`
- Todo -> PM：
  - `toolId: "pm"`
  - `payload: { mode: "detail", projectId: number, itemId: number }`

目标面板消费规则：

1. `TodoPanel.vue`
   - 收到 `{ itemId }` 后，如列表数据尚未加载则先加载
   - 将 `selectedItemId` 设为目标事项
   - 自动切到详情态
2. `PmPanel.vue`
   - 收到 `{ projectId, itemId }` 后，先切换 `selectedProjectId`
   - 等 `loadItems()` 完成后再设置 `selectedItemId`
   - 自动打开对应工作项详情

临时覆盖状态的生命周期：

1. 跳转过程中若为保证定位成功而改动过滤条件或视图模式，这些改动视为“本次导航接管后的当前界面状态”，不做自动恢复。
2. 原因是自动恢复会再次把目标对象从视图中隐藏，违背“定位成功后保持可见”的首要目标。
3. 因此 payload 不携带“恢复前快照”，`useToolNavigation` 只负责一次性投递目标，不负责导航后回滚 UI 状态。

具体落地规则：

- PM -> Todo：
  1. 若 Todo 面板当前项目筛选与目标事项不一致，则自动把筛选切到目标事项所属项目；若目标事项无项目，则切到“全部项目”。
  2. 若当前关键词筛选会把目标事项过滤掉，则清空关键词筛选，并保持清空后的状态。
  3. 若当前视图在日历模式且无法稳定直接定位详情，则切回列表模式后定位，并保持列表模式。
- Todo -> PM：
  1. 自动切换 `selectedProjectId` 到目标 PM 工作项所属项目，并保持该项目为当前选中项目。
  2. 若当前共享状态筛选会把目标 PM 工作项过滤掉，则把目标状态补进可见集合，并保持补入后的状态。
  3. 若当前视图下无法稳定完成定位，则切到更稳定的默认详情来源视图后再选中目标工作项，并保持切换后的视图。

失败兜底：

1. 若目标对象已不存在，提示“目标事项不存在或已被删除”。
2. 若目标对象存在但无法通过当前数据集定位，先触发一次刷新；刷新后仍失败，再提示错误，不保留半选中状态。

该负载为一次性内存态，不做持久化，不要求跨重启保留。
## 8. 风险点与约束

### 8.1 项目边界风险

最大的风险是绑定“未归项目” Todo 时导致项目边界混乱。

因此必须保证：

1. 只允许绑定当前项目或未归项目的 Todo
2. 未归项目 Todo 绑定时，在同一事务中自动补齐 `projectId`
3. 禁止绑定其他项目 Todo

### 8.2 事务一致性风险

“建立关联”和“补项目归属”不能由前端拆成多次请求拼装，而应在后端统一事务中完成。

否则容易出现：

- 关系建成了，但项目没补齐
- 项目补齐了，但关系建失败

Todo 侧改挂同样应在后端单请求内完成：

- 校验 Todo 是否为普通一次性事项
- 校验 Todo 与目标 PM 是否同项目
- 校验目标 PM 是否存在
- 变更关系记录

### 8.3 删除/解绑心智风险

由于本轮明确“不随 PM 删除 Todo”，界面文案必须足够清楚：

1. 解绑：`仅解除与当前工作项的关联，不删除任务`
2. 删除 PM 工作项：`仅删除工作项，已关联任务会保留在任务清单中`
3. 改项目失败：`已关联执行任务的工作项不能直接切换到其他项目`

### 8.4 跳转定位风险

PM 与 Todo 之间的价值不只在于“可切换面板”，更在于“切换后能定位对象”。

因此跳转方案必须明确包含：

1. 打开目标模块
2. 传递一次性导航负载
3. 在目标面板完成定位并自动打开详情

否则用户仍会觉得只是松散链接。

### 8.5 范围膨胀风险

本轮虽然允许 Todo 侧改挂，但仍应限制在“同项目内切换所属 PM 工作项”。

以下动作明确不纳入本轮：

1. 跨项目原子改挂
2. 批量改挂
3. 重复/周期 Todo 改挂
4. 在 PM 详情中直接完整编辑 Todo 全部字段

### 8.6 关键校验落点

为避免约束只停留在文档层，关键阻断规则必须落到具体写接口中：

1. `tool:pm:item-todo-create`
   - 校验目标 PM 是否存在
   - 校验创建路径只允许普通一次性 Todo
   - 在同事务内写入 Todo 与关系表
2. `tool:pm:item-todo-link`
   - 校验 Todo 是否未被占用、是否同项目、是否为普通一次性 Todo
   - 在同事务内完成批量绑定与未归项目 Todo 的 `projectId` 补齐
3. `tool:todo:item-set-pm-link`
   - 校验同项目改挂与清除逻辑
   - 禁止重复/周期 Todo 建联
4. 现有 Todo 写接口（涉及修改 `projectId` 或把 one_off 改成 recurring 的更新路径）
   - 若当前 Todo 已关联 PM，则阻止直接改项目
   - 若当前 Todo 已关联 PM，则阻止切换为重复/周期事项
5. 现有 PM 写接口（涉及移动项目的更新路径）
   - 若当前 PM 工作项下仍有关联 Todo，则阻止直接改项目

这样“项目变更阻断”不会依赖前端自觉，而是由后端写路径统一兜底。

## 10. 分阶段实施建议

本次进入实现计划时，范围明确锁定为 **Phase 1 + Phase 2**。

- **Phase 1**：必须进入本次实现计划，属于首版主链路
- **Phase 2**：必须进入本次实现计划，属于“模块真正衔接起来”的必要闭环
- **Phase 3**：仅作为后续 backlog，不进入本次实现计划

### Phase 1：打通主链路

1. 建关系表 `pm_item_todo_links`
2. 提供 PM 侧查询 / 绑定 / 解绑接口
3. 提供 PM 侧原子新建执行任务接口
4. 提供 Todo 侧设置 / 清除 PM 关联接口
5. 在 PM 详情“描述下方”新增执行任务区
6. 支持在 PM 内新建 Todo
7. 支持在 PM 内绑定已有 Todo
8. Todo 返回体带出 PM 关联信息
9. Todo 详情展示所属 PM 工作项，并支持同项目内改挂/清除
10. PM 详情同步展示聚合进度摘要

### Phase 2：补足双向感知

1. 抽出通用 `useToolNavigation` 能力
2. PM -> Todo 跳转定位
3. Todo -> PM 跳转定位

### Phase 3：增强易用性

1. 全部完成时提供“一键完成 PM”辅助提示
2. PM 内列表支持“仅看未完成”
3. Todo 面板支持按 PM 工作项筛选
4. 视需要再补计数与更轻量的快捷管理能力

## 11. 结论

本轮推荐方案是：

1. 保持 `PM = 目标/管理层`、`Todo = 执行层`
2. 通过关系表 `pm_item_todo_links` 正式建立“一个 PM 工作项对应多个执行 Todo”的结构
3. 以 PM 工作项详情作为主入口，在描述下方内嵌“执行任务”区
4. 允许绑定当前项目 Todo 与未归项目 Todo，其中未归项目 Todo 在绑定时自动补当前项目
5. Todo 侧允许查看、同项目改挂与清除所属 PM 工作项，但不支持跨项目原子改挂
6. 重复/周期 Todo 首版不参与 PM 关联
7. 保持弱同步，不做强自动状态联动，但通过摘要、提示与双向跳转提升两个模块的协同感

这样既能让项目管理与任务清单形成真正的衔接关系，又不会把第一版复杂度抬得过高。
