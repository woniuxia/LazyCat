# 密码库与上线包上传整合设计

## 状态

- 日期：2026-07-23
- 状态：已确认，待编写实施计划
- 范围：上线包项目绑定密码库服务器凭据，并在账户密码认证上传时由 Rust 安全取密

## 目标

让上线包项目绑定一条密码库中的“服务器”凭据。绑定后，上传时自动使用该条目的服务器地址、账号和密码，密码维护只在密码库完成，不再在上线包确认框中重复输入。

## 非目标

- 不把私钥文件、私钥内容或私钥口令纳入本次密码库整合。
- 不重构现有 SSH/SFTP 上传事务、远程替换、取消、重试和日志协议。
- 不增加远程命令执行、发布脚本或新的凭据服务层。
- 不根据服务器地址或账号自动猜测并绑定既有密码库条目。

## 已确认决策

1. 每个上线包项目绑定一条密码库服务器凭据，绑定关系随项目保存。
2. 账户密码认证模式使用绑定条目的地址、账号和密码；SSH 端口、远程目录和产物配置仍属于上线包项目。
3. 私钥认证模式继续使用上线包项目现有的地址、用户名、私钥文件和可选口令。
4. Vault 锁定、凭据不存在、类型不为服务器、地址/账号/密码不完整时，上传必须阻止并给出修复入口；不回退到手动密码输入。
5. 密码只在 Rust 的一次性预检和上传链路中存在，不返回 Vue，不写入配置、日志、通知或错误消息。
6. 凭据绑定控件放在“Linux 服务器上传”配置区内；启动确认框只展示凭据摘要和预检结果。

## 用户流程

### 配置项目

1. 用户选择“上传服务器”和“账户密码”。
2. “密码库凭据”选择器列出 Vault 中类型为“服务器”的条目，展示标题、环境、地址和账号。
3. 地址或账号缺失的条目不可选并标记信息不完整。
4. 绑定后，地址和 SSH 用户名显示为只读摘要；SSH 端口仍可编辑。
5. “刷新凭据”重新读取服务器条目元数据；“密码管理”打开 Vault 标签页，当前上线包标签页和草稿保留。
6. 项目保存时持久化绑定 ID。账户密码项目没有绑定时，保存和开始上传都必须明确提示完成绑定。

### 启动上传

1. 用户点击开始打包，进入现有确认流程。
2. 账户密码模式不再显示服务器密码输入框，改为显示当前凭据摘要。
3. Rust 校验项目绑定、Vault 会话、条目类型、地址和账号；失败时不创建预检令牌、不启动构建。
4. 继续现有主机探测和主机指纹信任确认流程。
5. 主机信任确认后，Rust 解密并校验绑定密码，再执行现有真实 SSH/SFTP 预检。
6. 预检通过后继续既有构建、归档/上传、替换、取消和重试流程。
7. 私钥模式保持当前口令输入与上传流程不变。

### 凭据维护

密码库条目地址、账号或密码被编辑后，不需要修改上线包项目；下一次预检或上传重试读取最新值。已经通过预检并启动的任务继续使用本次一次性凭据快照，不受运行途中锁库或编辑条目影响。条目被删除或改为其他类型时，项目保留失效绑定 ID，界面显示绑定失效并要求重新选择，不静默使用旧地址或旧密码。

## 数据模型

在 `release_package_projects` 增加：

```sql
vault_entry_id INTEGER NULL
```

该字段只保存 Vault 条目 ID，不保存密码、密码库主密码、解密密钥、密码内容或预检令牌。已有项目迁移为 `NULL`。现有 `ssh_host` 和 `ssh_username` 字段保留，继续服务私钥模式；账户密码模式的运行时真值来自绑定条目。

不根据现有字段自动绑定。删除 Vault 条目后，绑定 ID 可能成为悬挂引用；运行时将其视为失效并要求重新绑定。

## 数据流与边界

### 前端

- 使用现有 `tool:vault:meta-list`，以 `category: "server"` 查询绑定候选项。
- 前端只持有条目 ID 和非敏感元数据：标题、环境、地址、账号。
- 上线包项目 CRUD payload 增加 `vaultEntryId`；账户密码模式禁止提交 `password` 字段。
- 确认框仅展示凭据摘要、Vault 状态、主机指纹和远程目标预检结果。

### Rust Vault 模块

提供供上线包模块调用的窄内部接口，用绑定 ID：

- 校验条目存在且 `category == "server"`。
- 读取明文元数据地址、账号。
- 在已有 `VAULT_SESSION` 解锁会话中解密密码。
- 返回带清零密码容器的内部凭据对象，不跨 IPC 返回密码。

该接口复用现有 Vault 会话和加密字段规则，不新增第二套主密码或会话状态。

### Rust 上线包模块

- 项目解析、保存和加载同步 `vault_entry_id`。
- 账户密码模式的主机探测从绑定元数据取得服务器地址和账号。
- 预检阶段在主机指纹信任确认后解析绑定密码，构造现有 `AuthSecret::Password`。
- 预检令牌继续绑定项目、认证方式、目标和远程路径；同时绑定 Vault 条目 ID，防止令牌被另一项目复用。
- 现有上传运行时只消费预检令牌，不需要知道 Vault 数据库结构。

## 安全约束

- 锁定状态只能读取非敏感元数据，不能读取密码；上传因此必须阻止。
- 密码解密发生在主机信任确认之后，避免向未知主机认证。
- 密码使用 `Zeroizing` 或等价清零容器，生命周期限制在预检和运行时认证链路。
- 禁止在 Vue 响应式状态、项目配置、数据库日志、上传日志、全局通知、错误文本和测试快照中出现密码。
- 服务器密码不再从确认弹窗提交；私钥口令仍按现有一次性链路处理。
- Rust 对绑定 ID、条目类型和项目 ID 做服务端校验，不能只相信前端选择器。

## 错误处理

下列情况均为显式失败，不静默回退：

- `vault_locked`：提示先解锁密码库，并提供打开密码管理入口。
- `vault_entry_not_found`：提示绑定条目已不存在，要求重新选择。
- `vault_entry_invalid_category`：提示条目已不是服务器凭据，要求重新选择。
- `vault_entry_incomplete`：提示补充服务器地址、账号或密码。
- 绑定项目与预检令牌不一致：按现有令牌失效处理，要求重新预检。
- Vault 在预检前被锁定：阻止预检；任务已通过预检并启动后，继续使用本次一次性凭据快照。若远端凭据同时变化并导致认证失败，则按现有上传失败/可重试终态表达。

错误消息不得包含密码、主密码、私钥口令或解密内容。

## 迁移与兼容

- 采用幂等 SQLite schema migration 增加可空列。
- 既有项目继续可读；账户密码项目需要用户手动完成一次绑定。
- 切换到私钥模式时保留旧的 `ssh_host`、`ssh_username` 和私钥路径；切回账户密码模式时重新使用绑定条目元数据。
- 不删除现有 `upload_enabled`、SSH、远程目录和运行态字段。

## 测试与验收

### Rust

- schema migration、项目 create/list/update 对 `vault_entry_id` 的读写。
- 账户密码和私钥模式的项目校验边界。
- Vault 绑定条目的存在性、类型、完整性和锁定状态。
- 绑定条目更新后使用新地址/账号/密码；删除或改类后显式失败。
- 预检 payload 和结果序列化不含密码。
- 密码清零容器和错误脱敏的定向测试。

### 前端

- 凭据选择器只展示服务器条目，并正确处理未绑定、失效和不完整状态。
- 账户密码确认框无密码输入，私钥确认框仍有口令输入。
- 项目 dirty 判断包含绑定 ID；密码库条目内容变化不误报项目未保存。
- 锁定、缺失和重新绑定提示及导航动作。
- 既有 `ReleasePackagePanel`、上传预检和运行态测试保持通过。

### 验收命令

1. 上线包与 Vault Rust 定向测试。
2. 前端上线包面板、预检和纯函数测试。
3. `pnpm typecheck`。
4. `pnpm --filter @lazycat/desktop build:web`。
5. `git diff --check`。

真实 SSH/SFTP 服务器不作为自动化测试依赖；上传事务继续按现有人工冒烟流程验证。

## 不变部分

现有前后端构建并行、归档/上传事务、主机指纹信任、远端完整替换、取消、失败回滚、上传重试、日志 lane 和全局终态通知均保持原行为。本设计只增加凭据引用和安全取密边界。
