# Agent 规范与经验库精简重构设计

## 1. 背景

当前 `AGENTS.md` 与 `CLAUDE.md` 各 501 行，既包含高频执行规则，也包含大量领域架构、专题约束和低频操作细节。`process.md` 已积累 118 条经验、约 3800 行，所有记录倒序堆叠在单文件中，检索和维护成本持续上升。

本次重构将规范入口与经验正文分离：根规范负责告诉 agent “必须遵守什么、遇到问题去哪里查”，经验库负责保存“过去如何解决、为何这样做、如何验证”。同时清理已经失效或被新实现取代的内容，避免把历史事实继续包装成当前规则。

## 2. 目标

1. 大幅缩短 `AGENTS.md` / `CLAUDE.md`，仅保留必要、常用、稳定且影响面大的规则。
2. 将 `process.md` 改为经验总索引与维护说明，不再承载全部经验正文。
3. 在 `docs/experience/` 下按领域聚合经验，提供稳定、可搜索的文件入口。
4. 清除已过期、已失效、重复或相互冲突的内容；冲突时以当前代码、当前命令和最新有效经验为准。
5. 保留有长期价值的排障依据，包括场景、根因、解决方式、关键点、涉及文件、验证和使用次数。
6. 保持 `AGENTS.md` 与 `CLAUDE.md` 除文件名互指外完全同构。

## 3. 非目标

1. 不新增与当前项目无关的工程规则。
2. 不改变现有安全边界、破坏性操作确认要求或用户已确认的打包默认决策。
3. 不修改业务代码、构建脚本或数据库结构。
4. 不为每条经验单独创建文件。
5. 不保留仅有过程叙事、对后续任务没有复用价值的历史流水账。

## 4. 目标结构

### 4.1 根规范

`AGENTS.md` 与 `CLAUDE.md` 采用相同结构，仅保留：

1. 文档职责、优先级和双文件同步约束。
2. 项目最小速览：技术栈、关键目录、终端约束。
3. 高频硬规则：离线资源、默认 UI 方向、编码、dirty worktree、dev server、worktree、破坏性操作和 Windows 文件锁。
4. 开工闸门：任务分类、是否需要查经验、是否存在联动或高风险。
5. 常用命令与 Windows 打包决策。
6. 最低验证与提交规则。
7. 任务类型到 `docs/experience/*.md` 的经验索引。

领域架构细节、专题实现约束、完整发版流程、长检查清单和历史经验正文不继续留在根规范中。

### 4.2 经验总索引

`process.md` 保留以下内容：

1. 经验库用途和使用方式。
2. 使用次数规则与固化规则。
3. 新经验的记录模板。
4. 按任务场景和关键词指向领域经验文件的总索引。
5. 领域文件清单及其覆盖范围。

`process.md` 不重复领域文件中的经验正文。

### 4.3 领域经验文件

在 `docs/experience/` 下建立以下聚合文件：

| 文件 | 主要范围 |
|------|----------|
| `architecture.md` | 结构治理、IPC 契约、Tauri 能力、跨模块通用架构 |
| `ui-and-styling.md` | Element Plus、布局、弹层、交互状态和视觉实现 |
| `data-dictionary.md` | 数据字典存储、索引、检索、排序、关系和异步状态 |
| `todo.md` | Todo 数据模型、日期时间、提醒、排序、详情交互 |
| `pm.md` | PM 视图、筛选、甘特图、思源集成和工作项模型 |
| `spotlight-and-launcher.md` | Spotlight、快捷键、浏览器身份、provider 缓存 |
| `api-and-network-tools.md` | API Mock、访问链路、Cron、连通性和其他网络工具 |
| `request-forward.md` | 请求转发运行态、日志、预检、布局和恢复动作 |
| `release-package.md` | 上线包构建、归档、并行目标和运行态日志 |
| `windows-build-and-release.md` | Windows 打包、便携包、WebView2、版本与 GitHub Release |
| `vault-and-inbox.md` | 密码库、收纳箱及其跨工具数据流 |

每份文件顶部包含适用范围、关键词和文内目录。经验条目继续按日期倒序排列。

## 5. 内容分类规则

### 5.1 根规范保留条件

一条内容只有同时满足以下大部分条件才留在根规范：

1. 多数开发任务都会用到，或遗漏后风险较高。
2. 当前仍有效，且不依赖某个具体功能版本。
3. 能直接改变 agent 的执行决策。
4. 用一到两条简短规则可以说清。

只服务单一领域、需要较长背景才能解释、主要用于排障或容易随实现变化的内容移入经验库。

### 5.2 经验保留条件

经验至少满足一项才保留：

1. 记录了非显而易见的根因或边界。
2. 提供可复用的实现模式或验证方法。
3. 能防止重复踩坑。
4. 对当前仍存在的功能或基础设施有效。

纯交付流水、已经完全被移除的功能细节、仅描述一次性 UI 调整且没有通用价值的记录可以删除。

### 5.3 过期与冲突判定

迁移每条内容时按以下证据优先级判断：

1. 当前仓库代码、脚本、配置和 `package.json` 中的真实行为。
2. 日期更新且已验证的经验记录。
3. 当前 `AGENTS.md` / `CLAUDE.md` 中明确的硬规则。
4. 较旧经验与历史设计文档。

处理方式：

- 当前目标、文件、命令或功能已不存在：删除该经验；若根因仍通用，则只保留抽象后的通用部分。
- 多条经验描述同一演进链路：合并为一条当前有效经验，在正文中简述必要演进，不重复保留旧方案。
- 旧记录与新记录冲突：保留新结论，删除旧结论；需要解释兼容边界时明确标注“旧行为已废弃”。
- 无法从仓库事实确认且会影响规则语义：不擅自决断，列入待确认项。

## 6. 经验条目格式

保留的经验统一使用以下字段；没有实际内容的字段不强行补空壳：

```markdown
## YYYY-MM-DD：标题

**场景**：...

**问题**：...

**解决**：...

**关键点**：...

**涉及文件**：
- `path/to/file`

**验证**：
- `command`

**使用次数**：0
```

迁移时允许精简重复叙述和失效路径，但不得把未运行的验证改写为已通过。

## 7. 索引设计

### 7.1 根规范索引

根规范提供“任务类型 → 经验文件”映射，例如：

- 数据字典：`docs/experience/data-dictionary.md`
- Todo / 提醒 / 日期时间：`docs/experience/todo.md`
- Windows 打包与发布：`docs/experience/windows-build-and-release.md`
- UI、Element Plus、Teleport：`docs/experience/ui-and-styling.md`

索引只说明查什么，不复制经验内容。

### 7.2 `process.md` 索引

`process.md` 提供两层入口：

1. 按领域浏览：列出所有经验文件及覆盖范围。
2. 按高频关键词查找：将 `打包`、`WebView2`、`Teleport`、`sort_key`、`Tauri capabilities` 等关键词映射到具体文件。

领域文件顶部再提供本文件内的条目目录，形成三级检索链路：

`AGENTS.md` → `process.md` / 领域文件 → 具体经验条目。

## 8. 迁移与实施顺序

1. 从 `process.md` 解析全部 118 条经验，建立标题、日期、字段和目标领域清单。
2. 对照当前文件、命令和近期记录审查过期项与冲突项，记录每条经验的处理结果：保留、合并或删除。
3. 创建 `docs/experience/` 领域文件并迁移有效经验。
4. 将 `process.md` 改为总索引、维护规则和新增经验模板。
5. 精简 `AGENTS.md`，再生成同构的 `CLAUDE.md`。
6. 修正仓库内仍指向旧 `process.md` 正文或旧规范章节的有效引用；历史设计文档不做批量改写。
7. 完成数量、链接、规则和双文件一致性验证。

## 9. 验证与迁移对账

### 9.1 经验对账

建立迁移清单，确保原 118 条经验每条都有唯一处理结果：

- `kept`：保留到某个领域文件。
- `merged`：合并到另一条经验，并记录目标条目。
- `removed`：注明失效、重复或无复用价值的原因。

验收时满足：`kept + merged + removed = 118`。迁移清单用于本次审计，放在 `docs/experience/README.md` 的迁移说明中；不在根规范重复维护。

### 9.2 自动检查

1. 检查 `AGENTS.md` 与 `CLAUDE.md` 的标题结构和归一化正文一致。
2. 检查 Markdown 相对链接目标均存在。
3. 检查所有保留经验都有日期、标题和使用次数；有验证字段时保持原始真实性。
4. 检查旧 `process.md` 的 118 个标题均出现在迁移清单中。
5. 搜索旧命令、已移除模块和冲突术语，确认没有继续作为当前指导保留。

### 9.3 人工检查

1. 核心安全规则和打包默认决策无遗漏、无语义漂移。
2. 根规范能在短时间内回答“该做什么、该查哪里、何时停下确认”。
3. 经验文件的领域归属合理，常见关键词能通过 `rg` 快速命中。
4. 删除和合并项均有可解释依据。

## 10. 验收标准

1. `AGENTS.md` / `CLAUDE.md` 明显缩短，并保持同构。
2. `process.md` 成为简洁的经验入口和维护说明。
3. `docs/experience/` 按领域承载所有仍有效、可复用的经验。
4. 原 118 条经验全部完成迁移对账，没有静默遗漏。
5. 过期内容已移除，冲突内容采用当前代码与最新有效记录。
6. 所有索引链接有效，高频任务可从根规范快速定位到相关经验。
7. 不修改业务行为，不引入新的风险边界。
