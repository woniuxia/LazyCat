# 上线包配置布局稳定性优化设计

## 目标

优化上线包打包页的两个状态切换问题：

1. “打包类型”不再因为“归档根目录”显示或隐藏而改变宽度。
2. 服务器上传配置在“账户密码”和“私钥文件”之间切换时，只替换认证详情，远程目标和整体阅读顺序保持稳定。

本次只调整 `ReleasePackagePanel.vue` 的模板结构与局部样式，不修改配置模型、校验逻辑、IPC、Rust 或数据库。

## 现状与根因

### 项目基础区

`.project-basics-grid` 当前使用 `repeat(auto-fit, minmax(..., 1fr))`。本地归档模式有两个直接子项，网格分成两列；服务器上传模式隐藏“归档根目录”后只剩一个子项，`auto-fit` 会让“打包类型”扩展到整行。问题来自自动轨道数量随条件节点变化，不是单个控件宽度设置错误。

### 服务器配置区

`.server-config-grid` 当前把认证方式、密码库凭据、私钥连接字段和两个远程目标全部作为同一四列网格的直接子项。认证方式改变时，多组 `v-if` 节点同时加入或移除，CSS Grid 自动放置会重新排列后续字段；跨列规则又会进一步改变各项宽度和起点，因此用户需要重新寻找远程目标字段。

## 方案选择

采用“固定基础列 + 认证分区”的方案。

- 项目基础区使用显式两列：第一列为稳定的打包类型列，第二列为归档根目录。服务器上传模式继续隐藏归档根目录，但第一列不再扩展。
- 服务器配置拆成“连接认证”和“远程目标”两个独立分区。
- 认证方式选择器始终位于连接认证分区顶部。
- 账户密码和私钥文件只在固定的认证详情容器内切换。
- 前端远程目录和后端远程文件移入独立的两列目标网格，不再参与认证字段的自动补位。

不采用继续修补现有四列网格的方案。为每个条件字段手工指定 `grid-column` 虽然改动较少，但响应式断点和未来字段扩展会继续依赖脆弱的自动放置顺序，不能从结构上消除布局跳动。

## 页面结构

### 项目基础区

保留现有字段和交互，只把网格轨道改为：

- 宽屏：`minmax(240px, 320px) minmax(0, 1fr)`。
- 小屏：单列。

“打包类型”始终占第一列，宽度不因第二列是否存在而变化。“归档根目录”仍只在本地归档模式渲染，不增加无效占位控件或新的配置含义。

### 连接认证分区

连接认证分区包含两个稳定层级：

1. 认证方式选择器。
2. 认证详情容器。

账户密码模式的认证详情继续包含：

- 密码库凭据选择器和操作按钮。
- 凭据说明。
- 失效提示或地址、端口、用户名摘要。

私钥文件模式的认证详情包含：

- 服务器地址。
- SSH 端口。
- SSH 用户名。
- 私钥文件。

宽屏下，地址、端口和用户名使用三列，私钥文件占整行；中等窗口降为两列，小屏降为单列。两种模式都只改变认证详情容器内部，不改变分区标题、认证方式选择器或远程目标结构。

### 远程目标分区

远程目标分区始终位于连接认证分区之后，包含：

- 前端远程目录。
- 后端远程文件。

宽屏和中等窗口保持两列，小屏降为单列。两个字段不再跟随认证字段重新补位。

## 视觉与交互约束

- 延续现有干净浅色卡片风格，不改变整体视觉方向。
- 分区使用轻量标题和边界，不新增折叠层级、标签页或动画。
- 条件切换不使用过渡位移，避免产生额外的视觉抖动。
- 保留现有 Element Plus 控件、禁用态、错误态、Vault 摘要和移动端行为。
- 不通过固定高度裁切内容；凭据失效提示和长文本仍可自然扩展。

## 数据流与错误处理

本次不改变任何数据流。`draft.packageType` 和 `draft.sshAuthType` 仍是现有条件渲染的唯一真值，保存、校验、预检和上传逻辑保持不变。

密码库凭据失效、字段不完整、加载失败等状态继续使用现有提示。布局分区不吞掉错误、不增加默认值，也不改变字段的必填条件。

## 测试与验证

先在 `ReleasePackagePanel.test.ts` 增加失败测试，约束以下结构：

- 项目基础区使用固定的首列宽度，不再使用 `auto-fit`。
- 服务器配置存在独立的连接认证、认证详情和远程目标容器。
- 两个远程目标字段位于独立目标网格内。
- 私钥连接字段位于专用响应式网格内。
- 960px 和 640px 断点按两列、单列规则降级。

实现后运行：

- `pnpm test -- apps/desktop/src/components/ReleasePackagePanel.test.ts`
- `pnpm typecheck`
- `pnpm --filter @lazycat/desktop build:web`
- `git diff --check`
