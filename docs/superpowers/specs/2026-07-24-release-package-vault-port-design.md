# 上线包从密码库读取服务器端口设计

## 目标

上线包的账户密码认证不再要求用户重复填写 SSH 端口。服务器地址、SSH 端口、用户名和密码都由所绑定的密码库服务器凭据提供；私钥认证仍使用上线包项目中手工配置的服务器地址、SSH 端口和用户名。

## 现状

- 密码库服务器凭据已保存 `address`、`port`、`account` 和 `password`，新建及缺少端口的旧凭据在编辑时默认使用 `22`。
- 上线包账户密码认证已从密码库读取地址、用户名和密码，但连接端口仍读取项目字段 `ssh_port`，形成两个配置来源。
- 上线包界面始终显示 `SSH 端口` 输入，因此账户密码认证仍要求重复填写。
- 私钥认证不绑定密码库凭据，必须继续使用项目自身的 `ssh_host`、`ssh_port` 和 `ssh_username`。

## 方案选择

采用后端按认证方式统一决定连接端点的方案：

- 账户密码认证：从密码库读取 `address + port + account`。
- 私钥认证：从上线包项目读取 `ssh_host + ssh_port + ssh_username`。

不采用“前端选择凭据后复制端口到项目”的方案，因为复制会产生陈旧副本，密码库端口修改后项目仍可能连接旧端口。不删除项目表中的 `ssh_port`，因为私钥认证仍需要该字段，而且删除会引入无必要的数据库迁移。

## 后端设计

### 密码库元数据

`VaultServerCredentialMetadata` 增加 `port: u16`。`server_credential_metadata` 从 `plain_fields.port` 读取端口，并与地址、账号一起返回。

- 显式端口必须是 `1..65535` 的整数。
- 历史服务器凭据缺少 `port` 时按既有默认规则使用 `22`，无需迁移或解密密码。
- 端口类型错误、为 `0` 或超出范围时返回 `vault_entry_incomplete`，不静默连接其他端口。
- `resolve_server_credential` 复用相同元数据，保证探测、预检和上传看到同一端口。

### 上线包端点解析

`upload_endpoint_with_conn` 是连接端点的唯一裁决点：

- 账户密码认证使用 `metadata.address`、`metadata.port`、`metadata.account`。
- 私钥认证继续使用 `project.ssh_host`、`project.ssh_port`、`project.ssh_username`。

主机探测、主机指纹信任、远程预检和实际上传都通过该端点执行，因此密码库端口会一致地进入所有 SSH 阶段。`release_package_known_hosts` 仍以最终解析出的 `host + port` 为键，不修改表结构。

### 项目配置兼容

保留 `release_package_projects.ssh_port`、Rust 配置结构和前端草稿字段：

- 私钥认证继续读写并校验该字段。
- 账户密码认证不再使用该字段建立连接，也不因其中的历史值覆盖密码库端口。
- 旧项目无需迁移；切换到私钥认证时仍可编辑和保存项目端口。

账户密码认证的完整性校验改为验证密码库元数据中的地址、端口和账号；密码是否存在仍在解析密钥时验证。私钥认证继续验证项目端口范围。

## 前端设计

### 配置表单

- `SSH 端口` 输入仅在 `sshAuthType === "private_key"` 时显示。
- 账户密码认证只要求选择密码库凭据，不提供端口覆盖入口。
- 私钥认证继续显示服务器地址、SSH 端口、用户名和私钥文件。

### 凭据选择与摘要

密码库元数据列表读取 `plainFields.port`。前端选项模型增加端口，并使用与后端一致的规则处理历史数据：缺失端口显示 `22`，显式无效端口使该凭据不可选。

选中账户密码凭据后，只读摘要展示：

- 服务器地址
- SSH 端口
- SSH 用户名

摘要用于确认最终连接目标，不把端口写回项目草稿。绑定凭据失效或字段不完整时继续显示现有错误状态。

### 校验

`validateReleasePackageUpload` 仅在私钥认证时校验 `draft.sshPort`。账户密码认证由后端校验密码库端口，避免项目中的兼容字段阻塞保存或上传。

## 数据流

1. 用户在密码管理中保存服务器地址、端口、账号和密码。
2. 上线包账户密码模式加载服务器凭据元数据，在选择器和只读摘要中显示地址、端口和账号。
3. 上线包项目只保存 `vaultEntryId` 引用，不复制密码库端口。
4. 发起探测、预检或上传时，Rust 根据 `vaultEntryId` 读取最新密码库元数据。
5. Rust 使用密码库的地址、端口和账号建立 SSH 端点，并在认证阶段解密密码。

密码库中的端口修改后，下一次上线包操作自动使用新端口，不要求重新保存上线包项目。

## 错误处理

- 密码库条目不存在、分类错误或字段不完整时继续使用现有稳定错误码。
- 缺少端口的历史服务器凭据按 `22` 兼容。
- 显式无效端口视为凭据不完整，前端禁止选择，后端仍做最终拒绝。
- 密码库锁定时保持现有解锁提示和跳转行为。
- 不回退到上线包项目的旧端口，以免无效密码库数据被隐藏并连接错误目标。

## 测试与验证

### Rust

- 密码库元数据返回显式服务器端口。
- 缺少端口的历史凭据返回默认端口 `22`。
- `0`、超范围和非整数端口返回 `vault_entry_incomplete`。
- 账户密码认证端点使用密码库端口，即使项目 `ssh_port` 不同。
- 私钥认证端点仍使用项目端口。
- 已有凭据解析、主机信任和预检绑定测试保持通过。

### TypeScript / Vue

- 账户密码模式不显示可编辑端口，私钥模式显示端口输入。
- 密码库选项读取并展示端口，旧数据缺失端口时显示 `22`，无效端口不可选。
- 上传校验只在私钥模式校验项目端口。
- 现有凭据绑定、失效提示和打开密码管理行为保持不变。

### 验证命令

- 上线包与 Vault 定向 Vitest。
- 上线包与 Vault 定向 Rust 测试。
- `pnpm typecheck`。
- `pnpm --filter @lazycat/desktop build:web`。
- `git diff --check`。

## 非目标

- 不允许账户密码模式覆盖密码库端口。
- 不把端口复制到上线包项目形成第二份配置。
- 不修改私钥认证的凭据来源。
- 不迁移或删除 `release_package_projects.ssh_port`。
- 不修改密码库加密模型、IPC 通道或主机指纹存储结构。
