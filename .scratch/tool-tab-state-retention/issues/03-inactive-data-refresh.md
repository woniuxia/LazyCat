Type: grilling
Status: resolved

## Question

一个工具页面被缓存后重新激活，数据加载应保持切换前结果，还是按工具类型/数据新鲜度自动刷新？需要定义外部文件、数据库、网络请求、系统资源、后台事件驱动数据和用户正在编辑内容之间的刷新边界，避免状态保留与数据陈旧互相冲突。

## Answer

### 重新激活与刷新

- 缓存页面重新激活时默认保留切换前的页面结果，不重新执行完整初始化或无条件全量刷新。
- 纯本地输入、转换、预览和编辑器内容不自动刷新；用户正在编辑的内容始终优先于外部数据。
- 文件、数据库、运行状态、日志、Inbox、PM/Todo 等外部数据允许在重新激活时做轻量刷新，但必须保留当前选择、滚动位置和筛选条件。
- 网络探测和系统扫描属于主动操作，不因重新激活自动重跑；页面只恢复其上一次运行结果和状态。

### 脏状态与外部变化

- 自动刷新不得覆盖未保存的用户状态或页面草稿。
- 外部数据在页面失活期间发生变化且本地存在脏草稿时，保留草稿，并向用户提示外部数据已更新，由用户决定如何处理冲突。
- 页面没有脏状态时，重新激活可以展示最新外部数据，但不能因此重置用户的局部浏览上下文。

### 用户已启动的单次异步操作

- 打开文件、保存配置、解析、查询、导出等由用户启动的单次操作，切换标签页后继续执行，不因页面失活取消，也不因重新激活重复启动。
- 操作响应必须绑定发起它的 Tab 身份和操作代次；旧响应不得覆盖同一页面上的更新操作或更新后的状态。
- 原 Tab 被关闭后，已销毁页面不再接收响应回写；需要在关闭后继续可见、可取消或可恢复的操作，应提升为应用级长任务并遵循应用级任务工单的契约。
