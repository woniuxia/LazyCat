## Question

面对当前可无限打开标签页、Monaco/富文本/图表/轮询等高资源工具，应采用无限保留、固定数量上限、按资源类型限制，还是暂不设上限？如果发生淘汰，用户可见状态、未保存编辑、异步任务和重新打开行为分别如何定义。

## Answer

### Tab 缓存边界

- 暂不设置 Tab 数量上限，也不因资源压力静默淘汰仍打开的页面实例；当前一工具一 Tab 规则已经限制了同一工具的重复页面。
- 仍打开的 Tab 保留输入、滚动、选择、编辑器模型和未保存状态。资源治理不以销毁页面缓存为手段，避免用户在切换后丢失工作上下文。
- 页面失活时暂停页面级轮询、定时器、窗口监听和重型可视化；可释放仅用于展示的派生资源，重新激活时从保留的页面状态恢复。
- 失活不自动释放必须依赖实例连续性的编辑器或富文本核心状态；具体工具若要拆分模型与渲染资源，必须保持用户可见状态和脏状态不变。

### 关闭与未来压力治理

- 用户关闭 Tab 或批量关闭 Tab 时，销毁对应页面实例并释放页面级资源；关闭行为不取消应用级长任务或后台服务。
- 需要在 Tab 关闭后继续可见、可取消或可恢复的工作，必须由应用级任务状态持有，不得依赖被销毁的页面缓存。
- 当前不引入隐式内存阈值或自动休眠。若后续实测出现内存压力，应增加可观测、可恢复的资源级休眠方案，并单独定义用户提示、脏状态保护和恢复失败处理。
