# 确定微工具的维护边界与淘汰条件

Type: grilling
Status: resolved

## Question

为避免重复成熟产品或形成长期维护负担，新增微工具必须满足哪些离线价值、依赖稳定性、格式支持范围和维护成本条件？何时应明确不做、停止扩展或退出？

## Answer

“必须离线运行”是新增微工具唯一的硬准入门槛：核心输入到输出路径必须在断网、无远程认证、无 CDN 和在线服务时完成。可选联网增强不进入本轮 MVP，也不能影响核心结果。

其他条件作为软约束和排序因素处理：允许与成熟工具在单一高频问题上窄场景重叠，但不复制完整工作台；首版只承诺明确验证的常用格式，不支持的格式显式反馈；允许使用可完整打包、版本可锁定的本地依赖。候选通过离线门槛后，继续按“使用频率 > 离线差异价值 > 长期维护成本 > 实现成本”排序。

生命周期分为三种动作：实现前发现无法离线完成或无法收敛为单点微工具时“不做”；MVP 仍可用但新增需求突破既定边界时“停止扩展”；核心能力因安全、许可证、系统兼容性或依赖失效而无法继续维护时“退出”。低使用量本身不足以触发退出。
