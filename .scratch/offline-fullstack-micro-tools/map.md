## Destination

形成一份面向全栈开发工程师的高频离线微工具集合路线图和可实施规格，明确首批工具、维护边界、离线约束、统一 MVP 标准和开发顺序。

## Notes

- 领域：个人离线开发中的高频小问题处理。
- 规划原则：单点输入输出、离线可用、维护面窄，不建设需要持续追踪复杂生态的平台型产品。
- 现有工具只用于识别重复能力和可复用基础设施，不限制新工具来源或方向。
- 每个决策票据使用 `grilling` 与 `domain-modeling`；先解决范围和产品决策，再进入实现规划。

## Decisions so far

<!-- Closed decisions are indexed below. -->

- [定义高频问题与优先级口径](issues/01-frequency-and-priority.md) — 首批按使用频率、离线差异价值、维护成本和实现成本排序，优先每周反复发生的短时稳定问题。
- [确定微工具的维护边界与淘汰条件](issues/02-maintenance-boundary.md) — 仅将核心路径可离线完成设为硬门槛，其余条件用于软排序和生命周期控制。
- [选择首批候选微工具集合](issues/03-first-candidate-set.md) — 首批冻结为异常堆栈整理器和文本编码与换行诊断器，集合不设最低数量。

## Not yet specified

- 具体目标工作日场景和可观测的优先级证据。
- 微工具之间的独立性、共享入口、持久化和统一交互边界。
- 离线资源、第三方依赖、格式支持和长期兼容策略。
- 首批工具的纵向切片、开发顺序和最低验收证据。

## Out of scope

- HTTP 请求调试器或完整 API 调试平台。
- 数据库工作平台或通用数据库客户端。
- 低频的本地项目/多服务编排功能。
- 完整 IDE、在线协作、云同步和需要持续跟进大型第三方生态的能力。
