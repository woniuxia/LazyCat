# Sol-Luna Delivery

流程固定为 `Sol 研究与详细设计 -> 冻结设计和任务包 -> spawn_agent 启动 Luna -> Luna 执行 -> Sol 审查验收`。Sol 是设计负责人，Luna 只执行边界明确的任务。Git 工作区是唯一事实源；任务包和 Luna 摘要只用于交接，不能替代真实状态、diff 和验证结果。

## 运行前提

- 主代理使用 `gpt-5.6-sol` 和 `xhigh`。仓库根目录 `.codex/config.toml` 固定该项目默认值。
- `~/.codex/agents/default.toml` 必须定义 `name = "default"`、`model = "gpt-5.6-luna"` 和 `model_reasoning_effort = "xhigh"`。该自定义代理覆盖内置 `default` 子代理。
- 运行环境必须提供 `spawn_agent`、`wait_agent`、`followup_task` 和 `send_message` 等协作工具。配置缺失、配置不匹配或工具不可用时显式阻塞，不回退到 Terra、Sol 或其他默认模型。
- 修改个人 agent 配置后，从新 Codex 会话开始使用；不要用当前会话中无法证实的模型身份宣称配置已生效。

## 固定角色

- Sol 负责调研、歧义处理、方案、可直接执行的详细设计、任务包、复杂实现、风险判断、最终审查、验收裁决和提交。
- Luna 固定使用 `gpt-5.6-luna` 和 `xhigh`，只承担简单、边界冻结、低风险且可确定性验收的执行。不要通过 `spawn_agent` 参数覆盖模型或 reasoning effort；个人 `default.toml` 是这两个值的唯一配置源。
- Luna 不处理复杂根因、跨模块不变量、并发、事务、兼容性、安全、解析器或文件系统语义，也不做产品、架构、数据模型和实现方案决策。设计与仓库事实不一致或出现新决策点时返回 `blocked`。
- Luna 不提交、不回滚用户改动、不启动产品 UI、不打包、不发布、不创建下级代理，除非冻结任务包逐项明确授权。
- 同一工作区同时只能有一个写入型 Luna。独立只读分析可以在并发槽允许时并行，但 Sol 必须统一结论并避免与写入任务重叠。
- 当前提示已经声明自己是 Luna 执行代理并包含冻结任务包时，直接执行任务包，不再次调用本 skill 或创建下级代理。

## 路由任务

先判断任务是否简单且已冻结，再判断委派收益。难以判断时由 Sol 执行；不得用 Luna `xhigh` 承接本应属于 Sol 的复杂任务。

| 任务                                                       | 执行者     |
| ---------------------------------------------------------- | ---------- |
| 需求取舍、架构设计、复杂根因、跨模块不变量                 | Sol xhigh  |
| 复杂实现、并发、事务、兼容性、安全、解析器、文件系统语义   | Sol xhigh  |
| 最终审查、风险判断、验收裁决                               | Sol xhigh  |
| 已冻结、低风险、可确定性验收的多文件或耗时简单实施         | Luna xhigh |
| 已冻结、证据源与分类规则明确的耗时只读分析                 | Luna xhigh |
| 一两个命令即可完成的小任务                                 | Sol xhigh  |

只有以下条件全部满足时才使用 Luna：

- 没有需求或产品歧义；
- Sol 已完成并冻结可直接执行的详细设计；
- 不涉及架构、数据模型、并发、事务、兼容性、安全、解析器、文件系统语义或高风险操作；
- 输入、步骤、输出和验收标准均已确定；
- 错误能被测试或确定性规则发现；
- 失败可以安全停止且没有难恢复的副作用；
- 任务工作量足以抵消交接和复验成本。

每次选择 Luna 时都显式声明：Sol 保留真实状态与 diff 检查、关键验证复跑、最终审查、验收裁决和提交责任。

## Sol 详细设计与冻结任务包

委派前读取 [references/task-template.md](references/task-template.md)。Sol 必须先完成研究和决策，再把可直接执行的详细设计写成自包含但紧凑的任务包；完整意味着 Luna 不需要补需求或选择方案，紧凑意味着引用本地文件，不复制完整对话或大段源码。

任务包必须说明：

- `read-only-analysis` 或 `implementation`；
- 目标、上下文和已确认决策；
- `Executable Design`：实施任务写明精确目标文件及相关符号或区段、必要改动、适用的行为/数据/控制流契约、边界/失败/兼容性约束，以及测试改动或验证顺序；只读任务写明精确证据源、搜索或检查方法、适用的分类/去重规则和完整性检查；
- 非目标、允许范围和禁止范围；
- `Allowed Changed Paths` JSON 数组；实施任务逐项列出允许修改的仓库相对文件，只读任务固定为 `[]`；
- 可直接执行的步骤、验收标准、实际验证、停止条件和输出证据。

不得使用“对应测试”“相关文件”等路径占位文本。路径未知时由 Sol 先查明再委派。任务包不得要求 Luna 自行检查仓库后选择方案。

## 使用 spawn_agent

1. 委派前记录 `git status --short`、当前 `HEAD` 和任务相关 diff，识别用户已有改动。目标文件存在冲突时先处理边界，不把冲突交给 Luna 猜测。
2. 生成唯一、简短且符合工具约束的 `task_name`。将完整冻结任务包直接作为 `message`，不要落盘临时任务文件。
3. 调用 `spawn_agent`，固定使用 `fork_turns = "none"`，不传 `model` 或 `reasoning_effort`。这样不会复制主线程历史，并由自定义 `default` agent 配置选择 Luna xhigh。
4. 保存返回的 agent id。使用 `wait_agent` 等待完成；长任务等待期间按会话规则向用户报告进度。需要补充不改变设计的事实时使用 `send_message`。
5. Luna 返回后读取其完整摘要。只有原设计不变的机械修正才可通过 `followup_task` 交给同一 agent；出现新设计点、范围变化、连续失败或重要前提失效时由 Sol 收回。
6. 不因 `blocked`、`failed`、超时或工具异常自动换模型或重新创建代理。先检查事实，再决定由 Sol 处理还是在设计修正后进行最多一次有界补充执行。

任务包要求 Luna 最终返回以下 Markdown 字段：

```text
Status: success | blocked | failed
Summary: 完成结果或阻塞原因
Scope Inspected: 实际检查范围
Changed Files: 实际修改文件；只读任务为 None
Commands: 验证相关命令、退出码和目的
Validation: passed | failed | not-run 及证据
Findings: 关键发现及文件/行号证据
Uninspected Scope: 未检查范围
Scope Deviations: 越界或 None
Remaining Issues: 剩余问题或 None
```

## 审查结果

Luna 完成后，Sol 必须以仓库事实审查：

1. 读取 Luna 摘要、当前 `git status`、`HEAD` 和完整 diff；不得只信 `Changed Files` 声明。
2. 确认 Luna 没有创建提交，`HEAD` 与委派前一致。若不一致，显式报告且不自动改写历史。
3. 只读任务确认工作区未因 Luna 改变；实施任务逐项对账委派前基线、`Allowed Changed Paths` 和真实改动。发现越界时停止验收，不自动回滚用户改动。
4. 对只读分析抽查关键证据；对实施任务检查范围、失败路径、旧行为、测试和用户可见结果。
5. 复跑风险最高且最相关的验证，不能把 Luna 的运行声明当成 Sol 的验证证据。
6. 有明确且不改变设计的机械问题时可生成增量任务包并使用 `followup_task`；机械修正最多一次。新设计问题或连续失败由 Sol 接管。
7. 最终通过后由 Sol 运行 `git diff --check`，只暂存任务文件并按仓库规则提交。

## Token 纪律

- `fork_turns = "none"`，只传冻结结论、必要路径、验收标准和停止条件，不传完整线程历史。
- 优先精确读取目标范围，限制单次工具输出；不要反复读取完整大文件或广泛扫描依赖仓库。
- 独立只读命令批量执行；验证先定向、后综合，完整构建最多在最终阶段运行一次。
- Luna 输出紧凑摘要，不复述任务包，不粘贴大段 diff 或完整命令日志。
- 只有协作工具实际返回 usage 数据时才记录；没有时不估算 token。
- 委派用于把明确执行从 Sol 额度转移到 Luna 额度，不宣称一定降低总 token。
